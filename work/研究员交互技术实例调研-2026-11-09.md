# 研究员交互技术实例调研

日期与资料截止点：2026-11-09（Asia/Singapore）。任务：[Issue #134](https://github.com/normaltank/DataBase/issues/134)。状态：研究建议，尚未施工或验收。本文是本轮调研证据，不修改长期产品规则。

## 结论与范围

首选建设“材料版本—具体版审阅”联动工作区：桌面用清楚的提交／审阅双责任轨道和固定内容窗，点击任一真实版本或审阅节点，内容窗显示该版原件、提交说明、对应意见和可用动作；手机用同一组选项与内容区顺序呈现。价值来自选择与内容联动、跨版本责任可追溯，以及上下文不丢失，不能仅把旧折叠改为彩色时间线就称完成。

第二候选是在 PR #126 已有年份分布上增加连续年份范围选择；第三候选是附件命中到 PDF 页面的伴读。第三项引入真正的新依赖和文件呈现成本，适合作为独立小批，不能挤占协作主线。

调研覆盖八类官方／维护者实例，其中五类完成独立浏览器实际操作；D3 官方笔记本读取到代码，但未得到可刷选图形，故不冒称实操成功；Monaco 与 ELK 只核对文档／源码。研究未操作真实副本、研究库、付费 AI 或任何既有浏览器会话。

业务边界：研究员发现和阅读资料，并按现有两阶段主题材料交接、期刊成果、版本及共建规则协作。成员在站外编写原件，平台保存交接与审阅；不新增实时多人输入、在线 Word 编辑、审批门槛、假日程或影响力指标。[最新任务 #134](https://github.com/normaltank/DataBase/issues/134)与[#128](https://github.com/normaltank/DataBase/issues/128)已实际读取；自主维护结果正式生效，不恢复旧版 PRODUCT 中的强制逐项人工采用。

## 实例一：vis-timeline 的选择事件、导航与分组

第一手：[导航示例](https://visjs.github.io/vis-timeline/examples/timeline/interaction/navigationMenu.html)、[事件示例](https://visjs.github.io/vis-timeline/examples/timeline/interaction/eventListeners.html)、[事件示例源码](https://raw.githubusercontent.com/visjs/vis-timeline/master/examples/timeline/interaction/eventListeners.html)、[官方 API](https://visjs.github.io/vis-timeline/docs/timeline/)。

具体动作与价值：用户点击一个事件，图中选中态和下方详情同时改变；放大／移动改变可见时间范围。项目可将事件换成“提交 v2”“退回 v2”，每个节点绑定具体版本标识，详情窗显示对应原件和意见。事件位置帮助把谁先交、谁后审读成顺序；双责任轨道可进一步区分成员提交与负责人审阅。官方支持分组，但本次只实操导航与选择，未把责任泳道说成已经验证。

实际操作：独立 Chrome 在导航示例点击 `Zoom in`、`Move right`，`getWindow()` 的起止日期均改变；事件示例实际点击 `item 3`，`getSelection()` 返回 `[3]`，下方日志同步出现 `select` 与真实点击事件。截图经查看，选中节点为黄色，事件详情确实对应 item 3。这验证了“选择—详情”的原理，不证明本项目原件预览已接入。

项目映射：`handoffMaterials`／`handoffVersion` 与 `versions[].reviews` 最合适。每份材料各有自己的版本线；不把不同材料的 v1、v2误连成同一系列。沿革应按真实事件顺序表达，提交与审阅分别标注操作者与时间；没有截止日期就不画计划条。旧流程的 `legacy`、`source_ref` 保持“接续旧材料”的身份。

代价与取舍：官方 API 包括 `new vis.Timeline`、`on('select')`、`getSelection`、`setSelection`、`getWindow`；普通 HTML DOM 易嵌入，但完整时间轴的滚动、缩放和编辑并不是本轮必须能力。项目的十几个离散事件用原生按钮＋CSS Grid＋SVG连线已经足够，推荐借联动与责任分轨原理，首批不引入库。官方事件示例开了编辑，产品沿革应只读，不能复制其删除／拖动改日期能力。

无障碍／手机／离线：提供可聚焦版本按钮、选中说明和完整文字，不能仅靠 hover；窄屏把双轨合并成按事件顺序的可点击列表与下方内容窗。原生实现离线可用；如以后用库，需本地固定版本与 CSS，保留线性列表。许可为 [Apache-2.0 OR MIT](https://raw.githubusercontent.com/visjs/vis-timeline/master/LICENSE.md)；[当前源码清单](https://raw.githubusercontent.com/visjs/vis-timeline/master/package.json)列出 vis-data、vis-util、moment、Hammer 系列、xss 等 peerDependencies，独立构建包含依赖，不能把 standalone 当零依赖。源码版本字段是 `0.0.0-no-version`，不能据此声称最新发行号。

## 实例二：D3 Focus + Context 与 brush

第一手：[Mike Bostock／D3 笔记本](https://observablehq.com/@d3/focus-context)、[d3-brush 官方 API](https://d3js.org/d3-brush)、[d3-zoom 官方 API](https://d3js.org/d3-zoom)、[模块清单](https://raw.githubusercontent.com/d3/d3-brush/main/package.json)。另以 Context7 的 `/websites/d3js` 核对 brush／zoom 文档。

具体动作与价值：用户在概览横轴拖出区间，主图放大该范围；概览保持整体分布，避免反复猜日期。项目可把主图换为既有资料清单，把下方概览换成真实发表／收录年份柱形。跨 2018—2022 选择比连续点选几个年份直观。

实际检查：原页已打开并读取到官方 `brushX`、`brush`／`end`、`selection`、`brush.move` 和主图 `update` 源码。独立 Chrome 读到笔记本代码，但等待 `svg rect.overlay` 超时，未能执行真实拖选；`operations.json` 保留失败。不把截图中的网页图标或可读源码当作绘图运行证据；也不将该笔记本描述成已经支持滚轮 focus zoom。

项目映射：PR #126 的 `materialRender` 已有年份柱条／按钮，`materialApply` 把条件写回现有列表；`/api/material-discovery` 已按完整可见查询聚合。新增范围时复用这条路径，保留三种时间口径与“未知”。若时间条件已收窄，当前分布会跟随缩小；用户想扩大范围时，需明确提供清除时间，或仅在概览请求中移除时间条件并清楚标注其范围。不能一边写“当前结果”一边使用另一总体。

代价与取舍：首次做整数年份范围，可用原生双端范围／起止年输入与 SVG 柱形，先不引入 D3；若需稳定触控刷选，局部引入 `d3-brush` 更合适。当前模块声明 3.0.1，依赖 dispatch、drag、interpolate、selection、transition；其 [ISC 许可](https://raw.githubusercontent.com/d3/d3-brush/main/LICENSE)需随分发保留。该源码版本是截止点快照，不作为发行版本锁定。

无障碍／手机／离线：拖动之外提供起止年字段、应用／清除按钮和可读范围；触控避免劫持整页滚动。手机按字段完成同一动作，不强迫捏合或精细拖柄。只登记年份的资料不假填某月某日；未知单列。库本地化后可离线，图加载失败仍保留现有筛选。

## 实例四：PDF.js 的页码、搜索命中与原页上下文

第一手：[Mozilla 官方 Viewer](https://mozilla.github.io/pdf.js/web/viewer.html)、[示例](https://mozilla.github.io/pdf.js/examples/)、[Viewer 应用源码](https://raw.githubusercontent.com/mozilla/pdf.js/master/web/app.js)、[发行与接入说明](https://mozilla.github.io/pdf.js/getting_started/)、[Apache-2.0 许可](https://raw.githubusercontent.com/mozilla/pdf.js/master/LICENSE)。

具体动作与价值：用户输入页码或搜索词，保留完整版面看到命中周围的图、表、脚注。比只显示提取文字更容易核对引文与页码。项目的附件命中可以打开同一份 PDF 的登记页，同时保留原件下载与现有提取文字。

实际操作：官方14页样例从第1页跳到第3页，点击放大，在查找框输入 `trace`；读回页码3、416个匹配项与当前第57项，页面存在高亮。截图经查看，第三页代码示例、图注与命中位置同时可见。未编辑或保存PDF，也没有把样例正确定位等同于本项目扫描件或中文论文都可搜索。

项目映射：`attachmentMatchSection` → `/api/attachments/{id}/segment?locator=...` 已给位置；`attachment-search.js` 现在只有提取文字及下载。最小接入是一个同源只读PDF伴读区域，按页跳转，仍显示资料／附件身份。主题材料 `handoff-view` 当前走文字预览；如果扩展原页预览，必须沿受权文件路由，不能让同源 viewer 接收任意路径或借公开 demo 向外发送材料。

代价与取舍：推荐真正需要原页呈现时才引入本地 `pdfjs-dist`，保留 worker、字体／CMap及适用资源，固定发行版本；完整 viewer 比 canvas hello-world 维护面大。`web/app.js` 属 viewer 源码，不应把其中对象自动当作永久公开 API。先确认所选发行包的页导航／事件接口再接入，不照搬旧版博客代码。原件需同源授权，跨源链接仍受访问与CORS限制；扫描件无文字层不宣称已有OCR。

无障碍／手机／离线：保留文字层、原生键盘入口、页码输入和下载；手机独立阅读区而非三个挤窄窗格，放大后仍可返回原命中。PDF 加载失败保留文本与下载，不能卡住资料阅读；离线只适用于已经保存且有权限的本地原件和本地 viewer 资产。Apache-2.0分发需保留相关声明，官方也要求嵌入版本适当定制，不原封不动套用 Mozilla 品牌界面。

## 实例五：Monaco Diff Editor 的版本并列

第一手：[官方 Diff playground](https://microsoft.github.io/monaco-editor/playground.html#example-creating-the-diffeditor-hello-diff-world)、[官方样例源码](https://raw.githubusercontent.com/microsoft/monaco-editor/main/website/src/website/data/playground-samples/creating-the-diffeditor/hello-diff-world/sample.js)、[项目 FAQ](https://github.com/microsoft/monaco-editor#faq)、[MIT 许可](https://raw.githubusercontent.com/microsoft/monaco-editor/main/LICENSE.txt)。

具体动作与价值：用户同时查看两个版本，变化区对齐，减少靠记忆来回切换。适合共编档案出现版本冲突时对照“我的输入／最新保存”，或对照实际取得的短文本版本。它表达内容差异，不决定采用哪一边。

实际检查：浏览工具打开 playground 原页与维护者样例；读取 `createModel`、`createDiffEditor` 和 `setModel({original,modified})`。未在独立浏览器运行编辑器或实操 diff，归为源码／文档检查。

项目映射：`static/app.js:historyView` 当前展示版本与恢复按钮；`static/journal-results.js`、`static/topic-handoffs.js` 已保留保存冲突输入。可借“当前输入与最新保存并列”的信息结构；协作材料为 Word/PDF 原件，不从文件名、上传说明或有限提取文字冒充正文 diff。若只需在版本间切换原件与意见，Monaco 对本轮过重。

代价与取舍：当前源码清单标0.57.0；MIT，但 worker、编辑器样式、资源加载与销毁均须维护。官方明确不支持移动浏览器，`file://` worker 也有约束。本轮不引入；用语义化的原生并列字段／逐项差异说明就能改善短字段冲突。手机顺序呈现“我的输入／最新保存”，保留原输入；离线可看已加载草稿，恢复保存仍需服务端重新核对版本。无障碍不能依赖红绿块，需新增／删除文字标签和可读顺序。

## 实例六：View Transitions 的局部视图衔接

第一手：[Chrome 官方说明](https://developer.chrome.com/docs/web-platform/view-transitions/)、[其链接的 Cards SPA demo](https://view-transitions.chrome.dev/cards/spa/)。

具体动作与价值：用户增删／切换对象时，仍能看出原对象去了哪里。项目中从某版节点选择另一版时，身份栏和内容窗可以短暂衔接；它帮助理解“仍是同一材料、选了另一版本”，而不是全页闪白或失去所选位置。

实际操作：独立 Chrome 实际点击 Add，删除按钮从4个到5个；再点一个Delete后回到4个；`document.startViewTransition` 存在，前后截图已查看。本次只证明操作及API存在，没有录屏或逐帧测量动画连续性，也没有验证 demo 的增强弹跳效果。普通前后截图不能充当动画性能证据。

项目映射：选择历史版本时，仅更新预览与意见窗；上传／审阅表单保持原DOM和文件输入，避免切换导致保稿丢失。不得将 snapshot 视效的完成当作异步权限／文件加载已完成。帐号切换、版本重读与迟到结果保护仍沿现有 `account/load/generation` 机制。

代价与取舍：原生 API，不需要库或 React；官方使用 `document.startViewTransition` 包住DOM更新，缺失时直接更新。推荐只作为首选方案的小增强，短时淡入或位置衔接即可；不做整屏缩放。`prefers-reduced-motion` 时直接切换，键盘焦点落在真实DOM目的地；手机避免强制横向推移。离线与API支持无关，仍看数据是否已取得。Chrome 文档代码示例为 Apache-2.0，正文为CC BY4.0；本轮借原理自行实现，不复制demo资产，其独立源码路径未取得（尝试返回404），因此不宣称已完成demo源码许可核验。

## 实例七：Scroll-driven animations 的阅读反馈

第一手：[Chrome 官方文档](https://developer.chrome.com/docs/css-ui/scroll-driven-animations)、[官方作者维护的进度示例](https://scroll-driven-animations.style/demos/progress-bar/css/)。

具体动作与价值：用户滚动长文，顶部进度保持与阅读位置连续对应。与按时间播放的动画不同，滚回去时指示也回退；适合表达位置，不表示已经读懂或完成任务。

实际操作：独立 Chrome 滚动2300px，`#progress` 的 transform 从 `matrix(0,0,0,1,0,0)` 变为约 `matrix(0.696337,0,0,1,0,0)`；`CSS.supports('animation-timeline: scroll()')` 为真，截图已查看。只验证该Chrome与该演示，不推导所有浏览器支持。

项目映射与取舍：`uxBindReadingProgress` 已有 ResizeObserver、passive scroll和 `role=progressbar`。因此不立新功能；只有实际测得滚动性能问题，才考虑以 CSS `animation-timeline` 增强视觉层，同时保留语义进度。协作沿革的“当前选择”也不应由滚到某处自动替用户选择。

代价／手机／离线／许可：原生CSS可离线，不需新依赖，须作用于真实滚动容器而非误绑全页。无支持时保留现有进度，无动画偏好下保留静态定位。无障碍读数不能只靠CSS。示例正文和照片并非本项目可任意复制的素材；源码仓库LICENSE路径尝试404，本轮不复制其代码／图片。Chrome文档自身代码的Apache-2.0许可已在原文核实，可依据该文档自行写最小样式。

## 实例八：ELK Layered 的方向明确与稳定布局

第一手：[Eclipse 官方 Layered 算法](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)、[elkjs维护者用法与API](https://github.com/kieler/elkjs)、[依赖清单](https://raw.githubusercontent.com/kieler/elkjs/master/package.json)、[EPL-2.0正文](https://raw.githubusercontent.com/kieler/elkjs/master/LICENSE.md)。

具体动作与价值：用户展开有方向的关系，节点按层排列，带名称的边减少交叉，能比自由漂浮网络更清楚地读“资料→采用的具体版本→成果”。它是布局引擎，自己不提供可点击的业务界面或读屏语义。

实际检查：读取官方算法支持的有向层、边标签、多重边、compound与routing说明，以及维护者的 `elk.layout(graph, options)` Promise、workerUrl与terminateWorker用法。未打开并操作独立ELK在线布局演示，归为文档／源码检查，未跑本项目图布局或性能测试。

项目映射：未来多份原始资料与成果固定引用的复杂图，或真实多系列版本采用关系，可能需要布局；当前一跳关系与一份材料的少量版本没有这个规模。首选协作方案使用固定“提交／审阅”两轨就能清楚表达；分组按职责，不用算法凭空推断组织隶属或合作。

代价与取舍：维护者支持浏览器bundled或worker方式，但还要自建SVG／DOM渲染、选择、键盘、布局取消和迟到结果防护。当前源码清单0.13.0、`EPL-2.0 OR GPL-3.0-or-later`，LICENSE正文为EPL-2.0；若引入应选定适用许可并保留声明，不能按MIT处理。本轮不引入。手机保留明确关系列表，离线可用本地布局资产；worker失败回到固定列表，布局加载不能阻断阅读。
