# 链接与编号辅助录入验收

日期：2026-10-26。范围：[规格 1.0](../docs/specs/链接与编号辅助录入.md)、[任务 #32](https://github.com/normaltank/DataBase/issues/32)。固定施工基线 `62f0ecb`，原发布规格 `96fc463`；实现 `cec4bfc`，时限修复 `ce454d8`，预览保稿与布局修复 `f3c7785`，Windows 时限测试夹具修正 `d4b495f`。最终 CI、合并及真实本机切换由[PR #33](https://github.com/normaltank/DataBase/pull/33)和 Issue 交付评论记录，以下不提前声称部署完成。

## 本轮交付

从提交外部资料的 DOI／公开文章链接开始，先取得题录，再核对字段、已有身份与来源候选，最后保存。人工输入默认保留，替换字段需明确选择；未确认署名、缺少字段及取得失败可继续人工处理。取得不会自动核对资料、创建人物或下载原文。

本轮改动集中于 [题录取得](../platform_app/intake.py)、[公开网络与时限](../platform_app/public_dns.py)、[资料创建事务](../platform_app/record_revisions.py)、[初始署名](../platform_app/bylines.py)、详情及导出，以及 [预览界面](../static/intake.js)／[样式](../static/intake.css)。使用既有历史及 `raw_json` 保存取得依据，不增加数据库结构版本。接口接入、模板和草稿随同修改；操作与边界见 [README](../README.md#用-doi-或文章链接提交资料) 和 [施工说明](../docs/施工说明.md#链接与编号辅助录入2026-10-2632)。

## 开发与自动验证

- [8 项应用 HTTP 检查](../tests/test_assisted_intake.py)通过：只读预览、字段与日期精度、署名待确认／人工确认、失败回滚、可见重复和候选、签名凭据、原始题录、可读导出及备份恢复。多篇 JSON-LD 不混合拼成一篇；返回不匹配 DOI 的服务响应不采用，DataCite 回退使用合成响应验证。
- [3 项 DNS 兼容检查](../tests/test_intake_dns_compat.py)通过：代理 Fake-IP 经固定公开解析取得真实地址；私网回答、错误问题及直接本机／Fake-IP 输入拒绝。先复现本机普通公开网页被错误拒绝及 HTTPS Host 多余端口造成的跳转，再修复验证。
- [3 项绝对时限检查](../tests/test_intake_deadline.py)通过：慢响应头、TLS、连接已移交的响应体及公开 DNS 读取均受总时限约束。0.1 秒预算下，原慢头耗时约 0.61 秒；修复后及时失败。另修正中断返回 EOF 被误认为成功，连续 5 次超时后容量释放。
- 指挥方在 `cec4bfc` 运行 `python scripts/check.py`：202 项，201 通过、1 项真实外部导入按既有约定跳过，耗时约 281 秒。它不冒充后续修复的全量结果；修复后的 8＋3＋3 定向检查和最终提交的双系统 CI 分别记录。
- [真实浏览器定向回归](../scripts/check_intake_preview_browser.py)红→绿：同一题录重复取得原会丢失人工署名修改；修复后保留署名、确认身份、依据及替换选择。不同结果需明确选择，改变输入或关闭编辑器隔离旧响应，草稿可恢复，390 像素宽不溢出。该脚本使用合成库及模拟服务，不计入上述无浏览器套件。

开发者还实际验证了保存后阅读、失败后保留输入、窄屏操作；变更 JavaScript 的语法及差异空白检查通过。所有自动写入均在临时合成库，未导入 ThinkTank 或改写真实研究库。

`0baca7a` 的 Ubuntu CI 通过，Windows CI 205 项中两项时限用例报错：慢头 reader 尚未建立，测试便因证书环境初始化耗时提前超时。`d4b495f` 将真实 SSL context 在测试计时外准备，并增加实际进入慢头／握手／响应体的断言，没有放宽时限或跳过检查。修正后 3 项定向通过；应用代码及证书校验保持不变，最终提交重新接受双系统完整 CI。

本轮 9 份变更 Markdown 的 273 处本地链接及锚点检查通过。施工说明中既有的一份早期本地浏览器 JSON 已不在公开工作树，检查单独列为基线即存在的不可用历史证据，不把它改写为本轮成功证明。

修复后重启并加载 `f3c7785`：已有资料按 DOI 提示重复；改写署名、选定身份并填写依据后，再次取得同一题录，人工修改仍在。紧凑题录按题名、署名、刊物、日期、DOI、网址、语言、摘要排列，空标识不显示。390×844 下页面与对话框的内容宽度均为 390，无横向溢出；已查看桌面及窄屏截图。

## 双轴审查与处置

Standards 与 Spec 在固定 `cec4bfc` 分别独立审查；执行 Agent 均按用户要求使用 `gpt-6.1-sol`、`high`。Standards 未发现确证的项目标准违反项，另指出网络总时限可能被慢响应头突破。Spec 确认一项 P2：重复取得成功后重建预览，抹掉人工署名、选择与依据，不符合保留输入的用户故事。

两项均复现后修复。独立 Spec 审查者随后只读复核 `cec4bfc..f3c7785`，确认原 P2 解决，未发现新的实质错误；其 Node 定向状态检查、3 项时限及 3 项 DNS 检查通过。指挥方另独立操作重复取得及保存关联流程。修复作者的测试、独立审查与指挥方页面结果分别归属，不以同一作者重复自查代替独立审查。

## 证据位置与限制

本机临时目录 `database-assisted-intake-20261026` 保存全量检查日志、原站应用探测 JSON、开发及独立浏览器证据、桌面／窄屏截图和后续切换前后核对结果，仅原环境可查。公开仓库保留可重复的合成测试和本摘要，不上传数据库、附件、会话或截图。
