## 拆分方式

发布映射：1 → [#6](https://github.com/normaltank/DataBase/issues/6)，2 → [#7](https://github.com/normaltank/DataBase/issues/7)，3 → [#8](https://github.com/normaltank/DataBase/issues/8)，4 → [#9](https://github.com/normaltank/DataBase/issues/9)，5 → [#10](https://github.com/normaltank/DataBase/issues/10)，6 → [#11](https://github.com/normaltank/DataBase/issues/11)，7 → [#12](https://github.com/normaltank/DataBase/issues/12)。均为父任务 #1 的原生子任务。父规格正文保持发布快照。

每项交付一条能实际演示的完整操作，包含所需数据、接口、页面和验证。新增关系在引入时即接入历史、权限、冲突保护、已有操作兼容及完整备份；第 7 项负责可读导出及全流程恢复验证，不把基本保全拖到最后。

依赖顺序为：**1 → 2 → 3；1 → 4；3 和 4 → 5 → 6 → 7**。第 2、4 项可以从同一集成版本分别实施；共享文件的冲突由集成处理，不虚构业务依赖。

已完成的资料修订模块直接复用。本次检查未发现必须先做的大范围重构；施工中如有小范围整理，随所在完整流程一并验证。

## 1. 建立并共编人物 Wiki

**Blocked by：** 无功能阻塞；按照本轮顺序，待默认验证改进完成后进入人物施工。

**What to build：** 成员从作者目录搜索、建立和打开一个人物 Wiki，即使没有作品也能维护姓名、头像、分节介绍与出处，并查看历史、处理同时编辑的冲突。

**Acceptance criteria：**

- [ ] 有稳定人物编号及可直接打开的详情；人物与成员账号分开，同名人物分别存在，原名、中文名和别名可检索。
- [ ] 介绍支持已有的标题、段落、列表、表格和链接，经过正文安全处理；没有作品或头像时如实显示，不推断为无成果或低影响。
- [ ] 有效成员可以共同维护；历史显示修改人、依据与版本，恢复按当前权限处理。同时编辑档案或头像时拒绝过期保存并保留输入。
- [ ] JPEG、PNG、WebP 头像可上传、替换、移除，验证真实类型和 5 MiB 上限；失败保留其余输入，历史头像可读取和恢复。
- [ ] 隔离旧版样本先备份再增量升级，重复启动不重复建档、不自动解释旧署名；旧记录、引用、文件和历史保持。当前及历史头像与新数据进入完整备份，恢复到新目录后可继续编辑。
- [ ] 在桌面与 390px 页面实际完成搜索、新建、编辑、冲突和历史恢复；接口返回身份、版本及当前成员可用操作，后续能力复用这些真实接口。

覆盖：A01、A02、A08、A14、A15，A07／A17／A18 的档案部分；U35 的身份及版本基础。

## 2. 确认并纠正作品署名

**Blocked by：** 1。

**What to build：** 成员在有权查看的原始资料上维护有依据的署名关联，从署名进入人物或机构档案，从档案查看已确认作品；认错时可以纠正或退回待确认。

**Acceptance criteria：**

- [ ] 保留原始整段署名、各署名片段及顺序，支持多个个人、机构或共同署名；机构作者沿用机构身份，与发布方及期刊归属分开。
- [ ] 依据不足时保持待确认，不计入已确认作品；有依据后才人工确认，不按姓名自动建档或合并。可以改到另一人物／机构或退回待确认，保留前后身份、依据与责任。
- [ ] 公共署名关系的维护不授予原始资料正文编辑权；作品列表、搜索、计数、历史和入口均按可见范围过滤。
- [ ] 关系修改参与版本检查，冲突保留输入；两侧作品列表、原始署名与历史能通过实际操作核验。
- [ ] 已有资料／来源合并、来源类型更正和历史恢复保全新署名关联，拒绝不适用类型；新增关系及其历史随备份恢复保留。
- [ ] 桌面与窄屏完成多人及机构署名、纠正、退回待确认与跨页返回。

覆盖：A03、A04，A07／A08／A13／A17／A18／A19 的署名部分。

## 3. 记录任职经历与文章署名单位

**Blocked by：** 2（文章单位需要先能明确对应作品中的某位署名作者）。

**What to build：** 成员在人物 Wiki 维护有依据的任职经历，在具体作品记录作者的署名单位，从机构详情区分任职人物、机构署名作品与发布作品。

**Acceptance criteria：**

- [ ] 任职包含已有机构、角色、出处和已知时间精度；允许只有年份、起止不完整、时间未知及同时任职多家机构，不猜补日期或要求唯一单位。
- [ ] 文章署名单位属于具体作品中的具体作者，支持多单位和出处；更新当前任职不会改写历史文章信息，发布作品不自动等于任职关系。
- [ ] 人物和机构两端能阅读、维护及追溯关系；关系编辑、历史与冲突仍按当前权限及版本执行，界面保留冲突输入。
- [ ] 来源／资料合并、类型更正和恢复保全相关人物关系，类型不适用时明确阻止；备份恢复后关系及来历保持。
- [ ] 通过跨时期、同时任职、未知日期和更换任职样本，在桌面与窄屏走通操作，验证旧作品单位保持原样。

覆盖：A05，A07／A08／A17／A18／A19 的机构关系部分。

## 4. 将同一研究笔记关联多个研究对象

**Blocked by：** 1。

**What to build：** 从人物 Wiki 开始写研究笔记，或把已有笔记明确关联到多个人物、机构和期刊；各详情页显示同一份笔记，由负责作者及授权同事维护。

**Acceptance criteria：**

- [ ] 从人物建笔记预选该人物，沿用原有负责作者确认、授权及可见范围流程；已有笔记可选择多个研究对象，移除关联不删除笔记。
- [ ] 人物、机构和期刊页面汇集同一份笔记；引用某作品或登记发布来源不自动创建研究对象关系。
- [ ] 公共档案共编不扩大笔记正文及研究对象的修改权限；普通成员、作者、授权同事、管理员和受限读者的操作符合原规则。
- [ ] 档案列表、搜索、数量、历史和关联选择不泄露无权笔记的名称、摘要或存在数量；固定引用和正文不随关系整理改写。
- [ ] 关系修改参与冲突保护并保留输入；已有资料／来源合并、类型更正和历史恢复保全新关联并检查类型；完整备份恢复保留关系和历史。
- [ ] 在桌面与窄屏完成从人物建笔记、关联另一人物／机构／期刊、移除其中一个对象和跨页返回。

覆盖：A06，A07／A08／A13／A17／A18／A19 的笔记部分。

## 5. 比较、合并重复人物并保留可拆回依据

**Blocked by：** 3、4（完整预览及转接需要覆盖作品、任职和笔记三类关系）。

**What to build：** 成员核实两个档案属于同一人后，查看信息差异和有权看到的影响，选择保留的信息并合并；旧入口可追溯，能够把尚无后续独立改动的合并拆回。

**Acceptance criteria：**

- [ ] 比较页展示有依据的身份与信息冲突，明确选择当前介绍／头像等保留信息，其余内容进入可追溯历史。
- [ ] 从开始记录合并前身份、关系来历、版本及身份事件；旧编号继续解析并说明去向，当前和历史引用、附件及所有关系保持。
- [ ] 预览后档案、任一受影响关系或身份事件变动则拒绝旧提交；重复点击不重复执行，受控失败整体回滚。
- [ ] 预览、历史、提示按权限过滤；保全执行者不可见的关系但不显示其名称或数量，不改写个人正文、固定依据或作者授权。
- [ ] 能通过预览拆回一次没有后续独立改动的合并；自合并、循环或跨人物／机构合并被拒绝。已有后续变化而尚未支持的情形明确拒绝，不能覆盖变化。
- [ ] 合并事件、旧编号和关系来历进入完整备份；桌面与窄屏完成比较、合并、旧入口访问和简单拆回。

覆盖：A09、A10，A07／A13／A17／A18 的身份操作部分。

阶段边界：本项在集成分支中演示；第 6 项继续完成已确认的后续编辑及连续合并拆回能力。只有“立即撤回”不满足首版交付，不能据本项提前宣称人物功能完成或更新正式数据。

## 6. 合并后继续编辑，仍能安全拆回

**Blocked by：** 5。

**What to build：** 合并后已经补充作品、任职或笔记，甚至连续合并、纠正和移除关系，成员仍能比较并拆回；私人笔记不会阻塞公共纠错，笔记作者可以稍后处理自己的研究对象。

**Acceptance criteria：**

- [ ] 拆回预览区分原有转接、后续新增、已单独纠正及解除的关系；仅恢复仍未单独调整的转接，不覆盖后续编辑或复活已移除关系。
- [ ] 新增及归属不明内容由有权人员明确分配，或保留内容并标待确认；原有身份、来历与其他确定关系保留。
- [ ] 连续合并提供可执行的逆依赖拆回顺序；较早合并不能越过后续依赖强行回退，循环及无效操作明确拒绝。
- [ ] 无权编辑的私人笔记不阻塞公共拆回，也不泄露标题或数量；只把受影响且语义不明的研究对象关系标待复核，不计入已确认人物笔记，其他对象关系有效。
- [ ] 笔记作者或授权同事稍后能确认原对象、改选或移除关联；正文、原有引用快照和内容授权始终保持，身份更正有可见的依据说明。
- [ ] 拆回预览后档案、受影响关系或事件变化时拒绝旧提交，重新比较后可以完成；重复提交及受控失败不会留下重复事件或部分关系。
- [ ] 桌面与窄屏实际走通包含新增内容、归属纠正、移除、连续合并、私人笔记及延后确认的流程；相应状态进入备份且恢复后可继续处理。

覆盖：A11、A12、A20，A07／A08／A13／A17／A18 的复杂纠错部分。

## 7. 导出人物档案，恢复后继续研究与纠错

**Blocked by：** 6（完整可读导出和恢复演示需要覆盖最终身份状态及复杂纠错）。

**What to build：** 研究员导出自己有权阅读的人物档案与关联资料，维护人员把完整备份恢复到新目录后，能够继续编辑、研究和拆回身份误合并。

**Acceptance criteria：**

- [ ] 可读导出包括介绍、姓名写法、任职依据、当前与历史身份线索、可见作品及笔记研究对象关系；头像随导出保留或说明取得方式。
- [ ] 不同成员导出的内容遵守原分享范围，无隐藏内容的标题、数量、附件或凭据泄露；导出后的关系与依据可由人理解。
- [ ] 在受控样本完整备份中核查当前及历史头像、所有关联、历史和合并拆回事件；恢复到新目录验证清单、文件和数据，应用可继续编辑并拆回合并状态。
- [ ] 旧版备份仍能读取和增量升级，重复启动保持一致，原有资料流程和新增关系兼容场景 A19 全部验证。
- [ ] 在全部任务集成后运行完整自动回归，并实际走通桌面与 390px 的“建人物 → 关联作品和机构 → 多对象笔记 → 合并与复杂拆回 → 导出与恢复”；对应 A01—A20 保留实际证据和未完成项。
- [ ] 用稳定身份、关系及版本的实际读写验证后续评价／翻译的衔接基础；正式影响力评价和翻译服务仍留在后续范围。

覆盖：A16、A17，以及 A15／A18／A19 的全流程复验；U35 的接口与版本可延续性。

## 发布与施工边界

用户已核对并批准上述粒度及依赖，7 个子任务及原生依赖发布完成；父规格正文保持发布快照。实施按 [Matt 工作流](../docs/agents/workflow.md)，引用固定规格版本并使用隔离工作树、临时子 Agent 和集成分支。完整集成后由 Standards 与 Spec 分别审查，再按授权交付。
