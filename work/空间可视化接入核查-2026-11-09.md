## 可直接采用的决定

- 保留 Flask 与原生 JavaScript，在当前页面内挂载局部模块。Three 三场景从原型源迁入应用，数据改接当前账号有权读取的真实接口；ECharts、Cytoscape、React Flow 与 diff2html 可分别支持统计、关系、维护步骤与版本差异。不以独立 HTML 原型、演示数据或另起入口替代接入。
- 所有浏览器资产在构建时打包、本地随应用保存；运行时使用同源 ESM、外链 CSS 与同源 Worker。现行 CSP 可以保留，不加入 `unsafe-inline`、`unsafe-eval` 或 `blob:`。
- React Flow 可在独立 DOM 容器中用 `createRoot` 挂载；卸载调用 `root.unmount()`。ELK 可用，但须选 `elk-api.js` 与真正的浏览器 Worker；不能把只传 `workerUrl` 后的静默回退视作线程化成功。
- 条件轮询可以保留现行 `Cache-Control: no-store`；由当前页面持有已显示的数据和校验值，显式发送 `If-None-Match`。先重新鉴权和检查对象/依赖可见性，再比较 ETag。FTS5 与 SSE 本轮只完成实验，均不适合无条件替换现有方案。

## 当前代码约束与挂载契约

基线 [web.py](../platform_app/web.py) 的 API 请求先经过 `protect_request()` 的身份检查，具体路由再检查成员/管理员及对象权限；响应统一设置 `Cache-Control: no-store`。页面 CSP 为：

```text
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'
```

旧原型 `build.mjs` 把 IIFE 与 CSS 内联进 `prototype.html`，不能原样搬入这份策略。应构建为实际应用内的 ESM 文件和外链 CSS，例如普通脚本按需 `import('/static/vendor/space-three.js')`，再调用自身定义的 `mount(container, options)`。模块对外返回 `update(snapshot)`、`resize()`、`destroy()`；这是一份建议的项目契约，不是第三方库现成 API。

数据更新按稳定对象 ID 对齐；异步加载须绑定页面/账号/选中对象的世代。容器已销毁、账号已换或选择已变时，旧 Promise 完成也不得重新挂载。模块代码会被浏览器缓存，`destroy()` 回收的是实例、监听器、GPU/Worker、定时器和 DOM，不宣称能卸载 ESM 模块代码。

Three 的地球国别图只接当前选择的国别维度及完整有权查询聚合；机构所在地、来源国别与资料研究对象不能混合计数。关系空间图只画接口明确返回的具名边，节点点击进入现有有权档案/阅读器；不从共同出现推导合作或影响。时间空间图沿用 published/collected/updated 及真实日期精度，未知日期单列；不能以当前分页代替总体。三者都保留可聚焦文字入口、当前筛选说明及手机等价操作。原型的 fixture 必须退出日常应用数据路径。

原型地图有独立 `MAP-NOTICE.md`：Natural Earth 公共领域地理数据与 Three MIT 分开记录。迁入应用时保留来源、处理方式及未知/小国的文字入口，不能因为 Three 是 MIT 就删去地图来历。

生命周期的具体责任：

- Three：停止自有 RAF 或 `renderer.setAnimationLoop(null)`，移除监听器、断开 ResizeObserver、`controls.dispose()`，释放所有自有 geometry/material/texture，再 `renderer.dispose()`；独占 renderer 可调用 `forceContextLoss()`。共享资源由拥有者释放，不能在切场景时销毁另一场景还在用的纹理。
- ECharts：局部容器有尺寸后 `init()`；`setOption()` 更新数据，ResizeObserver 通知 `resize()`，离开页面 `dispose()`。tooltip 本轮验证 `renderMode: 'richText'`，避免把正文拼成 HTML tooltip；HTML formatter 若以后启用，需另做转义与 CSP 验证。
- React Flow：独立根挂载真实 nodes/edges，保留选中节点与视图状态；卸载 `root.unmount()`，同时撤销根外请求/监听器。轨迹只读时显式关闭新增连线、拖动改业务关系等能力。React Flow 的屏幕阅读与键盘支持仍需用项目数据验收，不从两节点渲染成功推断完整无障碍通过。
- diff2html：只把结构明确、受控生成的 diff 文本传入默认模板；不要把资料 HTML 当可执行模板。默认模板已预编译；`rawTemplates` 会调用 Hogan 编译器并可能触发 `new Function`，本轮不启用。中文短字段继续显示明确前后值，关系差异按稳定关系 ID 和目标身份表达；不要把 JSON 行差异冒充业务关系说明。

## 两个容易被误判的 CSP 适配

### Cytoscape 的动态 style

`3.34.4` 的 renderer 初始化会创建 `<style id="__________cytoscape_stylesheet">`，正文只设置容器 `position: relative`。即便绘图仍出现，也会触发 `style-src-elem` 拒绝，不能称默认配置完全兼容。该实现还检查同 ID 元素是否存在，因此可在挂载前加载：

```html
<link id="__________cytoscape_stylesheet" rel="stylesheet" href="/static/vendor/cytoscape-csp.css">
```

该外链 CSS 内容为 `.__________cytoscape_container { position: relative; }`。本轮实际复测后库调用阶段的 CSP 违规从一条降为零，选中节点和销毁继续正常。这个 ID 是**固定发行内部实现契约**，并非公开稳定 API；升级时须核对官方包 `src/extensions/renderer/base/index.mjs`，检查 ID/规则及零违规探针，不能只更新版本号。[官方固定发行包](https://registry.npmjs.org/cytoscape/-/cytoscape-3.34.4.tgz)。

### ELK 的真 worker 与假 worker

严格策略下，默认 `import ELK from 'elkjs/lib/elk.bundled.js'; new ELK().layout(graph)` 实际成功，不需要 eval 权限；不能仅因生成代码含有 `Function` 字样就判定不兼容。不过它在主线程执行，Promise 不等于线程隔离；本轮对这种假 worker 调用 `terminateWorker()` 实际报 `this.worker.terminate is not a function`。

同一个 bundled 入口只传 `workerUrl` 时，隔离包没有安装 Node 用的 `web-worker` 包，控制台警告后静默回退；结果坐标正常依然不证明真 worker 运行。可采用已实测的官方 API/浏览器 Worker 组合：

```js
import ELK from 'elkjs/lib/elk-api.js';
const elk = new ELK({
  workerFactory: () => new Worker('/static/vendor/elk-worker.min.js'),
});
const positioned = await elk.layout(graph);
// 容器销毁或整次布局取消时：
elk.terminateWorker();
```

使用包内经典 worker 文件，不把它错误声明为 module worker。API 与 worker 同版，worker 文件独立复制至同源静态目录并检查返回 MIME/内容，不用 Blob 包装。现行 CSP 未声明 `worker-src` 时最终回落 `script-src/default-src 'self'`，本轮同源 Worker 正常创建。浏览器 `worker` 事件记录到真实 worker URL，layout 给出两节点坐标，terminate 成功。[官方说明及 API](https://github.com/kieler/elkjs#browser)、[CSP worker-src 及回落规则](https://www.w3.org/TR/CSP3/#directive-worker-src)。

应用接入还须给布局设置超时、节点数量上限和世代检查：超时/切换时终止本次 worker，丢弃迟到结果；不支持 Worker 或初始化失败时保留可读确定性布局与完整列表。主线程无 worker 只用于有界小图的明确降级，不能据本次两个节点成功声称大型布局不卡顿。

## ETag 与 no-store 的读取契约

基线 [maintenance_agent.py](../platform_app/maintenance_agent.py) 已有 `GET /api/maintenance/jobs?view=summary`，由 SQL 选摘要列、做依赖可见性检查，返回上限 100 条的有权窗口及 `has_more`；并非仍需从零添加摘要接口。详情仍为 `/api/maintenance/jobs/<jid>`。这两个表示可各自设置 ETag；摘要哈希不能错误代表完整步骤详情。当前基线没有这组 ETag 实现，以下是接入建议及独立实验结果。

服务端顺序：身份有效 → 路由角色 → 目标及依赖当前可见 → 生成同一快照的表示 → 计算该表示 ETag → 判断条件 → 返回 200 或 304。If-None-Match 是 GET 的弱比较；使用 Werkzeug 的 `request.if_none_match.contains_weak(tag)`，覆盖弱标签和 `*`，不要手工去引号或比较原始头字符串。401/403/404 优先于 304；不能凭旧标签跳过权限。[RFC 9110 先决条件评估](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.2.1)、[If-None-Match](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2)。

摘要 ETag 绑定当前 actor、账号/权限世代、规范化筛选/窗口及实际返回字段，详情另绑定 job 和完整可见详情。账号、依赖失权、标题、状态、步骤或可见证据变化均需重新检查。可对规范化表示加账号/权限材料后散列，不把秘密写入 ETag；也不能用只含 job.updated_at、却遗漏依赖权限的标签。仅在经鉴权投影完成后再散列可节省传输，不能据此宣称省去数据库/JSON 计算。

保留 `no-store` 并不禁止发 ETag 或显式条件请求；它禁止 HTTP 缓存存储并复用响应。当前页面已显示的视图状态与校验值不写入 localStorage、IndexedDB、Service Worker 或公共缓存；条件 GET 用 `cache:'no-store'`，不要依赖浏览器自动把 304 合成为 200。实际探针中 `fetch()` 收到 304 时 `response.ok === false` 且正文为空，因此必须在通用 `!ok` 和 `.json()` 之前处理 304：当前同账号、同资源、同世代仍有已显示表示才保留；没有基体就发无条件 GET。[RFC 9111 no-store](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5)。

页面维护一个会话世代，切账号/退出/失权立即清空表示、ETag、图实例与选中详情并 abort 在途请求；迟到响应必须经世代和资源 ID 检查才可应用。`Vary: Cookie` 可作为辅助，不能替代上述隔离。轮询单次在途，隐藏时暂停/降频，回前台立即鉴权刷新；失败保留最后成功时间及陈旧标识，不把网络失败显示成任务完成。heartbeat 若包含在同一表示，改变就必须使 ETag 改变；如需避免每次心跳重绘，可另表示它，不能用“稳定标签”掩盖停滞。

本轮合成 Flask/Waitress 路由实际观察：初读 200；相同强标签及 `W/` 弱标签分别 304；304 保留 `ETag` 与 `Cache-Control: no-store`、无正文；未登录带旧标签仍 401；账号 b 带账号 a 标签返回自己的 200；撤销 a 权限后带旧标签返回 404。该探针证明这条兼容路径可运行，不证明应用真实账号切换、依赖失权或乱序响应已经验收。

## FTS5：中文召回与索引生命周期实验

现有 [search.py](../platform_app/search.py) 用 Unicode NFD、`casefold()` 和去组合音标，`web.py` 对 `q.split()` 中每个词做子串 AND；引号目前不是短语操作符。这与直接传入 `MATCH` 不同，不能悄悄更换检索语义。权限可见性先决定哪些资料和署名进入搜索。[SQLite FTS5 tokenizer/短语/外部内容索引](https://www.sqlite.org/fts5.html)。

本机 Python 3.12 所带 SQLite `3.49.1` 的内存库启用了 FTS5。四条纯合成文本：`拉脱维亚作者任职纠错`、`拉脱维亚 作者 任职 纠错`、`Latvijā Straße`、`同名作者 费用未知`。结果：

- `unicode61 MATCH 作者` 只命中空格分词那条，漏掉连写中文；`MATCH 拉脱维亚` 也漏第一条。它不是现成的中文分词器。
- 默认 `trigram MATCH 作者` 为零条，现有子串匹配为三条；三字以下查询不能直接依赖 MATCH。`拉脱维亚` 和 `任职纠错` 的连续长片段召回正确。trigram 的 `LIKE '%作者%'` 可返回三条，但无三字符连续片段时不能据此主张使用了高效 trigram 索引。
- 默认 trigram 查询 `latvija` 漏 `Latvijā`；`remove_diacritics 1` 可以召回，但仍不能把 `strasse` 匹配到 `Straße`，而现有 `casefold()` 可以。改用已经按当前 normalize 生成的独立索引文本是可研究路径，原文另留；只换 tokenizer 选项不足以保持语义。
- `MATCH '"拉脱维亚作者"'` 只有连写条目命中，说明 FTS 短语语义；这不是现有输入引号的行为。用户词中的双引号、AND/OR/NEAR、连字符等需当文字转义，不能直接把输入作为 FTS 查询表达式执行。LIKE 降级也要转义 `%`、`_`，因为现有子串把它们当普通字符。

外部内容索引生命周期也做了实际事务测试：先有正文再建 FTS/触发器时，旧正文 MATCH 为空；执行 `INSERT INTO idx(idx) VALUES('rebuild')` 后命中。随后 update 触发器同步删旧加新；事务 rollback 后旧词恢复；delete 后旧词消失；`integrity-check` 的外部内容核对通过。即“建表+触发器”不等于存量已入索引；正文更新、删除、恢复和事务都必须覆盖。[官方外部内容表陷阱](https://www.sqlite.org/fts5.html#external_content_table_pitfalls)、[rebuild](https://www.sqlite.org/fts5.html#the_rebuild_command)。

因此本轮不推荐直接替换现有检索。若后续接入，至少：保存规范化索引文本；有三字以上词时用 FTS 作候选且再用现有匹配复核；全部词都短时走有权范围的原子串降级；把当前资料、译文/机器概述、来源名称、作者关系、权限变化纳入更新/失效设计。计数、snippet、排序和分页必须在同一有权集合中完成，不能先对全库 LIMIT 再过滤；权限相关衍生文本尤其不能混进全账号共用索引。本次没有测试真实资料库、应用迁移、备份恢复或吞吐，不能给出性能结论。

## SSE：现有同步线程池的实验事实

基线生产启动和本地便携代码均使用 Waitress `threads=6`；这只是当前实现事实，不代表本轮需要选择/发布某种运行入口。Waitress 用固定线程池执行 WSGI 应用，网络 I/O 异步不代表 Python 生成器的等待释放请求线程；全部线程忙时普通请求排队。[Waitress 官方设计](https://docs.pylonsproject.org/projects/waitress/en/stable/design.html)。

本轮在随机端口启动自有 Flask/Waitress，线程数同为 6，以六条合成 `text/event-stream` 连接分别输出首条消息后在生成器内等待。最后一次实验：普通 `/fast` 基线约 0.017 秒；六条流都占用线程时，第七条 `/fast` 在客户端 0.4 秒限时内超时（实测约 0.411 秒），Waitress 输出任务排队提示；释放流后同接口立即恢复 200。这里只证明线程占用与排队机制，没有测真实负载上限，也不把这个短超时写成应用永久不可用。

结论：当前本地应用优先摘要条件轮询。若以后仍接 SSE，需要单独核验连接预算、观察窗口数量、断线取消、心跳、鉴权失效、流最长寿命及普通请求在并发下的响应；简单把 threads 调大不会改变“一条阻塞流占一个线程”的机制。EventSource 的重连/Last-Event-ID 也不自动补上业务权限和持久化游标。[WHATWG SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)。

## Monaco 的备选边界

只读短字段/简介差异先用 diff2html 和现有前后值。需要长文本逐处导航、原文与修改文本的编辑模型、复杂冲突处理时，Monaco diff editor 才有额外价值；它不会代替业务版本检查、授权或冲突时保留输入。Monaco 还增加 worker、CSS、模型生命周期及本地构建成本，维护者明确不支持移动浏览器；不能把它当手机阅读的唯一入口。本轮未安装、运行或选定 Monaco 版本。[官方 README](https://github.com/microsoft/monaco-editor#readme)、[官方 diff 样例](https://microsoft.github.io/monaco-editor/playground.html#example-creating-the-diffeditor-hello-diff-world)。
