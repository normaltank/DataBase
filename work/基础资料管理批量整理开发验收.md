# 基础资料管理：批量整理开发验收

2026-10-25；任务 [#16](https://github.com/normaltank/DataBase/issues/16)，依据 [基础资料管理规格 1.0](../docs/specs/基础资料管理第一批.md) U5—U12。此记录是开发方合成验证，整组独立验收、双轴审查及 PR 合并由父任务维护。

## 实现与衔接

从 `58d5009` 在专属工作树建立 `codex/database-bulk`，提交前合入最新集成分支 `5ff0d54`。新批量模块通过 #15 的 `window.librarySelection`、`library:selection-change`、`library:rendered` 与挂载点接入，不改连续阅读布局。#17 附件检索的服务与前端代码保持合入结果。

- `POST /api/library/bulk/favorites`：`{ids}`，仅幂等添加当前账号收藏，返回 `selected/added/existing`。
- `POST /api/library/bulk/collections/<id>`：`{ids,version}`，维护权限及版本检查后同一事务添加，返回数量及新 `version`。实际新增一批只增加一个版本及一条历史；全已存在时不制造修订。
- `POST /api/library/bulk/export`：`{ids}`，下载仅所选 CSV，复用原题录字段和转义；旧 `GET /api/export` 继续按筛选导出。

选择上限 100；全部编号在服务端重新检查，不存在、无权或已合并的失效编号统一拒绝。修改在 `BEGIN IMMEDIATE` 内校验并写入；专题冲突或中途存储失败整体回滚。正文、身份、可见范围、负责作者和编辑授权不受修改。页面保留选择用于继续整理；失败显示原因，专题冲突保留目标并可重新读取。迟到结果同时检查账号、会话、页面与请求代次，选中下载也受同样限制。

## 红绿过程与 HTTP 验证

沿用已确认的 HTTP／文件下载／实际页面边界，不对私有函数写镜像测试。三个完整流程各先观察新 HTTP 端点返回 404，再实现至绿：收藏去重和账号隔离、专题版本历史、仅选中 CSV。页面先观察缺少“收藏选中”按钮，再实现并通过桌面／窄屏流程；追加处理中关闭弹窗的场景，先观察结果提示缺失，再补齐列表反馈至绿。

`tests/test_bulk.py` 七项通过：

1. 部分已收藏、重复编号、重复添加及不同成员收藏隔离；资料正文、署名、作者、授权和版本保持。
2. 部分已有专题条目、共同维护、一次版本历史与纯重复无空修订。
3. CSV 仅选中编号且去重、UTF-8 BOM、中文／引号／换行与四种公式起始字符；旧筛选导出保持。
4. 三端点空选择、101 项、错误类型及无效／隐藏编号均拒绝；没有部分收藏或专题条目。
5. 他人私人专题、旧／缺失／错误类型版本拒绝，专题内容与历史不变。
6. 成员失去读取权限、退出会话及未登录请求重新检查。
7. SQLite 公共存储边界注入“第二条收藏写入失败”和“专题历史写入失败”，通过 HTTP 确认前段新增、版本和历史全部回滚，解除故障后可重试。
