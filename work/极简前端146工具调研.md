## 首轮建议（历史）

以下“未安装”“无新增运行时包”和布局建议描述首轮调研时点，保留为历史参考；本轮实际选择以上节为准。

## 建议先定下的方向

采用“低权重导航 + 可操作的大图形工作面 + 相邻结果 + 可扩展正文”的工作台。借鉴 Linear 的信息层级，以原生布局和既有图形引擎实现；建议新增依赖只考虑按需取用的本地 Lucide SVG。动效先用 CSS / Web Animations API；有实际时间线或对象插值需求后，再在 Motion 与 Anime.js 中选一个。以下是对当前约束的适配判断，不声称存在客观唯一的 SOTA。

## 六个指定站点

### MotionSites

- **核实事实：** 官方把自己定位为 AI 建站提示词与模板，覆盖页面布局、字体、颜色和网页动效；这不是运行时动画库。[官方中文首页](https://motionsites.org/zh)
- **借鉴：** 用“工作面、结果、阅读、空状态”等完整场景描述设计意图；可以借鉴画面留白和分区思路，页面需回到真实资料任务检验。
- **可用工具／此轮选择：** 作为设计参考，不引入其运行时、付费模板或外部建站流程。提示词本身不能证明本平台交互、性能和数据语义正确。

### Aceternity UI

- **核实事实：** 官方组件基于 React、Tailwind CSS、Motion；目录包含 Sidebar、Animated Tabs、Layout Grid，也包含大量背景、悬停和展示动效。[首页](https://ui.aceternity.com/) / [组件目录](https://ui.aceternity.com/components)
- **借鉴：** 提取选中态和短促展开反馈；正文一次显示完整内容，导航通过明确点击控制展开。其营销页面的 Spotlight、发光边框、背景粒子不符合本轮阅读任务。
- **可用工具／此轮选择：** 不整套引入。原生 JS 主体为采用它而增加 React/Tailwind/Motion 迁移，收益不足。后续既有 React 局部若选具体组件，需分别核对源码、依赖、授权和键盘行为；官方“production-ready”自述不替代本地验收。

### Showreel

- **核实事实：** 本环境请求 [指定首页](https://showreel.design/) 返回 HTTP 403，未取得可审阅正文与案例。
- **借鉴：** 暂无可验证的具体借鉴结论；不能把域名、搜索摘要或其他网站案例当成它的实际设计。
- **可用工具／此轮选择：** 不据此引入任何组件或依赖。若后续取得可访问页面，可补看案例；这不阻塞已有证据支持的工作台方案。

### Uiverse

- **核实事实：** 官方支持复制 HTML/CSS、Tailwind、React 元素；维护者 Galaxy 仓库收录按钮、输入、选择、提示等分类，并标明 MIT 许可。[官网](https://uiverse.io/) / [官方仓库](https://github.com/uiverse-io/galaxy)
- **借鉴：** 小控件的焦点、加载、选中反馈。单个漂亮控件不会自动形成一致的应用层级。
- **可用工具／此轮选择：** 不新增库；若有明确缺口，可挑一小段原生 HTML/CSS 后统一到项目样式，并保留对应许可。当前先自己实现一致的按钮、筛选和结果行，避免拼贴多套组件风格。

### React Bits

- **核实事实：** 官方提供动画组件与背景，可选择 JS/TS、普通 CSS/Tailwind，并以复制源码或 CLI 方式安装；普通 CSS 版本仍是 React 组件。[官网](https://www.reactbits.dev/) / [安装页](https://www.reactbits.dev/get-started/installation) / [维护者仓库](https://github.com/DavidHDev/react-bits)
- **借鉴：** 将动效做成局部、参数可控的反馈；只在解释任务变化时使用。
- **可用工具／此轮选择：** 不引入其背景和文字特效组件。已有 Three 工作面应直接改进交互，新增另一套展示性图形组件会增加生命周期与渲染成本核查工作。具体组件的依赖需单独检查，不能由首页推断全库统一成本。

### Anime.js

- **核实事实：** 官方支持 JS、DOM、SVG 动画及时间线；Scope 可按媒体查询调整行为，`revert()` 可回退作用域中的动画并执行清理。[官网](https://animejs.com/) / [Scope 参数](https://animejs.com/documentation/scope/scope-parameters) / [revert](https://animejs.com/documentation/scope/scope-methods/revert)
- **借鉴：** 让短序列说明“选择、筛选、结果变化”的关联，缩减动效偏好下立即呈现终态。
- **可用工具／此轮选择：** 原生 JS 适配良好，是复杂 SVG 时间线、对象插值的候选；本轮先不新增。只有出现原生动画维护明显困难的实际场景才采用，且与 Motion 二选一，不为按钮悬停安装动画引擎。

## 更贴合工作台的补充来源与工具

### Linear：采用工作界面的层级思路

- **核实事实：** 2024 redesign 调整侧栏、页签、页头及面板来降低视觉噪声、增强对齐和层级。2026-03-12 刷新进一步降低导航、图标和分割线的视觉权重，并强调操作位置一致；官方也介绍了通过开关比较新旧界面、逐步集成的过程。[2024 官方说明](https://linear.app/now/how-we-redesigned-the-linear-ui) / [2026 官方说明](https://linear.app/now/behind-the-latest-design-refresh)
- **借鉴：** 导航作为定位线索退到次级，图形、结果和阅读内容获得主视觉；通过间距、浅色表面和细边界传达关系。这里借用的是应用设计原则，浅色方案是本项目建议，不能从 Linear 深色截图推出通用最佳配色。
- **可用工具／此轮选择：** 不引入 Linear 产品或 SDK。建议在原型用真实长标题、空结果、加载与错误状态比较新旧方案；重构外观时明确保持现有业务含义。

### 原生 CSS 与 Web Animations API：首选

- **核实事实：** Web Animations 定义 DOM 动画的时间与控制模型；Chrome 官方建议优先动画化 `transform` 与 `opacity`，并提供减弱动效支持。[W3C Web Animations](https://www.w3.org/TR/web-animations-1/) / [Chrome 官方动效指南](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/motion)
- **借鉴：** 控件即时响应，面板和选中提示只做短过渡；阅读和持续探索时保持静止。
- **可用工具／此轮选择：** 建议采用，无新增运行时包。先覆盖焦点、选中、面板出现；宽度拖拽直接更新布局。新 CSS 能力按实际目标浏览器检查，基础功能不依赖 View Transitions 等增强能力。

### Motion：条件候选

- **核实事实：** 官方同时支持原生 JS 与 React；`animate` 有 mini 与 hybrid 入口，hybrid 还支持 JS 对象及 Three 对象动画；`scopeMotion` 用于集中清理动画与监听。[animate 官方文档](https://motion.dev/docs/animate) / [作用域清理](https://motion.dev/docs/scope-motion)
- **借鉴：** 若后续需要 DOM 与图形对象协调，可用一个编排接口管理过渡；原生 JS 无需为了使用 Motion 改为 React。
- **可用工具／此轮选择：** 本轮不新增；如确需共享编排，优先评估它与既有 React 局部的复用价值。它不能自动保存 Three 相机、选中对象、筛选或草稿；这些是应用状态与实例生命周期责任。官方体积声明不等于本项目实际构建增量。

### Lucide：最值得小范围采用

- **核实事实：** 官方有无框架依赖的 Vanilla JS SVG 包，支持按需取用；其无障碍说明要求有意义的控件提供名称，图标不能代替清晰标签。许可页列出 ISC 及部分 Feather 派生图标的 MIT 声明。[Vanilla 指南](https://lucide.dev/guide/lucide) / [无障碍](https://lucide.dev/how-to/accessibility) / [许可](https://lucide.dev/license)
- **借鉴：** 搜索、筛选、阅读、展开、缩放、复位使用一致线性图标，主要入口保留中文标签；把可访问名称放在按钮上。
- **可用工具／此轮选择：** 建议按需采用本地 SVG 小集合，保留许可，不加载在线图标字体、CDN 或全量图标扫描器；是否新增包由实际构建入口决定，静态 SVG 也可满足需求。

### Radix Primitives：只评估既有 React 区域

- **核实事实：** 官方提供无预置样式的组件，可渐进采用；包含 ARIA、键盘与焦点管理，应用仍需提供正确标签。官方示例及安装面向 React。[介绍](https://www.radix-ui.com/primitives/docs/overview/introduction) / [无障碍职责](https://www.radix-ui.com/primitives/docs/overview/accessibility) / [开始使用](https://www.radix-ui.com/primitives/docs/overview/getting-started)
- **借鉴：** 阅读抽屉、对话框、页签要有稳定焦点路径、关闭及返回行为。
- **可用工具／此轮选择：** 不为原生 JS 主体引入 React 组件层。若既有 React 区域确实缺少复杂对话框或弹层，可按组件评估 Radix；简单按钮、输入和原生对话框先用平台能力。使用组件库不代表整个应用自动符合无障碍要求。

## 工作面与阅读的落地建议

以下为工程和体验建议，尚待本地原型验证；不是上述官网为本项目作出的保证。

1. **探索时：** 大图形工作面与结果列表相邻，筛选和视图控制靠近图形。选节点/图形更新相邻结果；选结果显示同一项的正文。保留明确文字入口，让用户也可绕过图形直接查找、阅读。
2. **阅读时：** 正文可扩展为主面板，来源、作者、日期等定位信息靠近标题；返回探索时保留筛选、结果选中与阅读位置。窄窗口按明确模式切换，避免强塞三列。建议先验证 1440、1280、窄屏及系统缩放场景，尺寸是本项目候选检查条件。
3. **浅色层级：** 主内容白色、外围微灰、选中态单一强调色；用间距区分分组，只有需要表达结构时保留边界。正文与有效控件不能为了“克制”变得难辨；普通文本对比度按 4.5:1、大文本 3:1 核查。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
4. **Three 持久化：** 固定挂载图形容器，保留 renderer、scene、camera、controls；列表筛选、正文展开只更新必要数据和容器尺寸。离开工作空间时显式清理自有资源。官方说明静态编辑/图形类应用适合按需渲染，资源释放需调用 dispose，画布显示尺寸与绘制尺寸需协调。应用仍需自己保存相机、选中及视图状态。[按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html) / [资源清理](https://threejs.org/manual/pages/cleanup.html) / [响应尺寸](https://threejs.org/manual/pages/responsive.html)
5. **分栏和拖动：** 可调分栏提供可聚焦分隔条与键盘操作；图形和面板拖动另有点击按钮、复位或数值入口，键盘支持不能替代单指针免拖动途径。APG Window Splitter 页面明确注明示例及审阅尚未完成，作为模式参考，需自行验证。[W3C 分栏模式](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) / [拖动替代说明](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)

## 后续施工应取得的证据

这些是建议检查项，本次调研未执行，不能写成通过结果。

- **真实任务与保留状态：** 用“筛选资料 → 操作图形 → 查看相邻结果 → 打开正文 → 返回”贯通流程；记录筛选值、焦点、草稿、选中项、相机与滚动位置。重复开关阅读区和筛选至少 20 次，检查 canvas 与实例没有无意义重建；该次数只是建议的本地回归样本。
- **性能：** 同一设备、同一数据、同一窗口录制前后操作，比较主线程、布局、绘制、交互延迟与内存；记录可重复的数据规模，不只测空图。静止时不持续无意义绘制，容器缩放不失真，反复切换后资源不持续增长。用官方 DevTools Performance/Rendering 工具定位瓶颈，再确定实际预算。[Performance](https://developer.chrome.com/docs/devtools/performance) / [Rendering](https://developer.chrome.com/docs/devtools/rendering/performance)
- **无障碍：** 检查纯键盘遍历、焦点可见、关闭后焦点返回、缩放阅读、减弱动效、非颜色状态表达和图形的文字结果入口。可在现有 Playwright 流程评估 axe；自动扫描只能发现部分问题，仍需手工键盘与辅助技术检查。[Playwright 官方说明](https://playwright.dev/docs/accessibility-testing)
- **本地运行：** 检查网络日志，确认代码、图标、字体及图形资源均从本地同源提供；阻断外网后再走核心流程。按需复制的第三方源码保留许可来源。这里是本项目运行约束的验证，不是这些工具默认已经满足的能力声明。
