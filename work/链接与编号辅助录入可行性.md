# 链接与编号辅助录入可行性

资料截止：2026-10-26。状态：可行性调研，供讨论；未形成施工规格。本轮核查官方文档与源码，未测试试点站点、接入服务或操作真实库。

## 判断

研究员提交 DOI 或已知单篇 URL，系统生成待核对题录，技术上有成熟路径，范围明显小于批量爬取官网。它能减少手填，但“取得署名和期刊文字”与“确认库内作者、机构、期刊关系”是两步；后者继续遵循[产品规则](../PRODUCT.md#作者档案与研究关联2026-10-23-已确认2026-10-24-完成首版验收)。

## 已核查事实

- **DOI 可直接查题录。** [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) 提供单 DOI 记录；[DataCite REST API](https://support.datacite.org/docs/how-do-i-query-the-rest-api-and-whats-in-the-response)同样返回单 DOI 的 JSON 元数据。两者各有注册范围；[DOI 内容协商](https://www.crossref.org/documentation/retrieve-metadata/content-negotiation)可跨支持的注册机构返回 CSL-JSON、BibTeX、RIS 等，但格式映射可能损失类型细节。
- **URL 有通用提取与站点适配两条路。** 网页若暴露 `citation_title`、`citation_author`、期刊、日期、DOI 等标签，可按[Zotero 官方说明](https://www.zotero.org/support/dev/exposing_metadata)提取；[schema.org ScholarlyArticle](https://schema.org/ScholarlyArticle)也能表达作者、卷期与期刊关系。没有相应标记时，需要站点解析器或人工补录，不能保证任意网址同等有效。
- **无需让研究员安装 Zotero 才能借鉴其解析能力。** 官方 [translation-server](https://github.com/zotero/translation-server#endpoints)可独立运行 translators：`/web` 接收网址，`/search`支持 DOI、ISBN、PMID、arXiv ID。其他编号须按类型接对应数据源，ISBN通常指书，ISSN指连续出版物，不能当作单篇文章编号。复用仍需服务运维、版本与许可核查，不是现成的平台接口。
- **元数据不保证完整，题录不等于全文。** Crossref 的[字段要求](https://www.crossref.org/documentation/schema-library/required-recommended-elements/)将文章贡献者、ORCID、摘要等列为推荐字段；[DataCite 规范](https://datacite-metadata-schema.readthedocs.io/en/4.6/properties/overview/)也区分必填、推荐、可选，甚至允许未知值代码。[DOI 通常跳到落地页](https://support.datacite.org/docs/datacite-content-resolver)，[Zotero](https://www.zotero.org/support/adding_items_to_zotero)也只描述保存可访问的 PDF；网址或 DOI 均不保证取得全文。

## 项目推断与建议范围

单篇入口省去了全站的目录发现、分页覆盖、历史回填、周期调度与增量更新；仍要处理重定向、登录或访问失败、字段差异、重复与错误恢复。网页适配器随站点变化维护，公共 API 也需处理限流与故障，因此宜先支持 DOI 和明确的一组网页来源。

建议流程为“输入 → 提取题录草稿 → 显示字段来源、缺失和分歧 → 提示关联候选 → 研究员确认保存”。保留原始署名、输入地址、取得日期及元数据依据；提取失败可继续手填。作者作品关联须人工有据确认，姓名不自动合并；任职、文章署名单位、发布机构分别理解；期刊国别按主办方确认，不能从出版社推定。

[ORCID](https://info.orcid.org/what-is-orcid/)可提供个人持久标识，[ROR](https://ror.readme.io/docs/api-affiliation)可辅助匹配机构，但其官方说明也承认可能无结果或误配；本项目中适合作为候选依据。指挥 Agent 本轮代码核查：已有 DOI、URL、ISSN，以及[署名确认与依据基础](../platform_app/bylines.py)；[DOI 防重](../platform_app/record_revisions.py)尚未完整规范化 DOI URL 前缀，人物／机构缺少专用 ORCID／ROR 字段，表单仍为手填。可复用关系基础，仍需补获取、外部标识、字段依据及预览确认。

## 未知项与验证边界

尚未抽样核查拉脱维亚试点文章的 DOI 覆盖、标签质量、字段分歧、登录限制和解析维护频度；“能读文档”不证明这些站点已可用。后续若获准试验，应选含 DOI、无 DOI、标准标签、普通页面及失败样本，逐字段对照原站并记录人工纠错量，再决定支持范围。本轮没有成功率、工期、全文覆盖或正式运行结论。
