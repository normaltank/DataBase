# 研究工作页面布局开发验收

2026-10-25；开发交付记录，对应 [#22](https://github.com/normaltank/DataBase/issues/22)，父任务 [#19](https://github.com/normaltank/DataBase/issues/19)。适用[全站布局与视觉整理规格](../docs/specs/全站布局与视觉整理.md) 1.0（发布提交 `964e534`），覆盖 U13—U16 及相应 U17—U20。本记录是开发自测，不代替集成验收、整组审查或本机正式切换。

## 范围与实现

开发工作树为 `ui-workspaces`，从已完成公共骨架的 `0d20cf1` 建立；期间合入集成分支及共用章节组件 `2304b51`，没有复制通用跳转行为。

- 工作台保留“查找研究资料”入口和实际草稿、近期专题、本人成果；搜索区减少装饰空白，空态不重复提供相同新建操作，统计继续放在次要位置。
- 专题卡片按真实内容自然排列，显示已登记研究问题、范围、数量与创建者，不再靠固定高度或“说明待补充”占位。专题详情按研究问题、研究内容、报告与成果、资料与证据提供章节按钮；键盘跳转会聚焦相应标题，保持原应用路由。
- 草稿页保留题名、类型、时间、附件提示与继续编辑，归属说明在页头保留一次。原草稿键、账号隔离、附件保存、恢复与冲突处理均未改写。
- 维护页按账号与成员、导出与备份、采集入口、运行能力组织。宽屏用左右内容组，1024px及手机单列。可见内容导出与全库备份分别说明；完整备份包含个人与受限资料的警示及管理员操作边界保持明显。
- 运行说明改为支持题录、网页正文与可提取文字的本地附件检索；扫描件 OCR、自动采集和正式网络部署仍未提供。原导入事实放入可展开记录，不再与日常操作混排。

改动文件：`static/app.js`（专题卡片、运行说明）、`static/ux.js`／`ux.css`（工作台）、`static/workflow.js`／`workflow.css`（草稿及上述页面局部样式）、`static/operations.js`（专题、维护组）、`static/sources.js`（仅 `systemPage()`）、`scripts/check_workspaces_browser.py` 与本记录。未修改后端、数据模型、公共导航／阅读断点、来源其他函数、人物页面或模板。

## 实际验证

使用指定 Python 环境与 Playwright `msedge`，在独立端口 **8873** 启动隐藏服务，明确 `--no-import` 并使用 Temp 新建的合成库。所有样本通过公开 HTTP 创建；未接触8848、ThinkTank或正式库，也未复制真实库。脚本拒绝未知端口占用，结束只停止自己启动的服务。

新增专题章节行为先红后绿：原界面缺少“专题章节”导航，真实浏览器检查失败；接入共用组件后，通过 Enter 依次定位资料、成果、研究内容及研究问题，目标标题获得焦点、进入视口，URL不变。红阶段证据目录为 `database-workspaces-browser-rxqhs79h`，绿阶段为 `database-workspaces-browser-zqz8iwaa`（均在本机 Temp，仅原环境可查）。

`scripts/check_workspaces_browser.py` 的六项检查通过：

1. 从工作台继续真实输入的草稿，再经“我的草稿”恢复，题名与正文保留。
2. 成员可导出当前可见内容，管理员能进入成员管理；普通成员不显示完整备份操作。代交成果保留作者确认提示，提交者与管理员未获授权的正文修改均返回403。
3. 专题四章真实键盘跳转，焦点和路由保持正确。
4. 另一成员通过 HTTP 保存新版本后，网页保存发生冲突；本地研究问题仍在，关闭后可从草稿恢复并继续看到冲突提示。
5. 通过专题实际查找、加入及移出资料，原资料仍可读取；进入修改历史后恢复前一版本，资料关联恢复，可见范围保持当前共享设置。
6. 1440、1024、390、320px，以及720×500 CSS视口的放大等效走查：工作台、专题目录、草稿、维护、专题详情及宽表格共30个状态，无全页横向溢出，章节可操作，关闭按钮实际命中可点。
