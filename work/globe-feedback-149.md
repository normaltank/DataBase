# 国别地球辨识与操作手感（#149）

日期：2026-11-11—12。状态：开发自测完成，待独立审查与集成；最终交付归 [Issue #149](https://github.com/normaltank/DataBase/issues/149)。固定起点与交付前实际同步提交均为 `36deb96eec3a8a22d3a1e1cba88289d41389c731`。范围仅为研究对象国地球的辨识、输入与反馈；国家含义、底图、查询、账号与权限沿用原协议，没有真实采集、AI 调用或运行副本升级。

## 研究依据与采用方式

本轮先由独立研究代理阅读一手资料，再由施工者结合锁定的 Three `0.187.0` 和实际代码选取方案。下列来源支持原则或 API 语义；参数是本项目选择，测量另列。

- 直接操纵需要及时、可理解的反馈；约 0.1 秒是常见感知参考，不能作为设备保证。国名、按钮和浮雕先反映 URL 选择，资料仍异步加载。[NN/g 响应时间](https://www.nngroup.com/articles/response-times-3-important-limits/)、[系统状态](https://www.nngroup.com/articles/visibility-system-status/)
- 普通 WebGL 线宽不可作为任意加粗的保证；最终用 `BufferGeometry` 和 `ShaderMaterial` 将每段边界展开为两个三角形，按画布 CSS 尺寸偏移顶点。普通边界为浅色 2.7px 外线与深色 1.15px 内线，选中为 3.3px / 1.7px；浅线与深线分别帮助区分深浅资料色。两层关闭深度写入、固定绘制顺序，共享国界按端点去重。宽度是设计参数，投影实现是项目选择；没有使用无效的原生 `linewidth`。[Three ShaderMaterial](https://threejs.org/docs/pages/ShaderMaterial.html)、[Three BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)
- 有意义的图形边缘与状态需可辨；仅靠相近颜色不足以说明选择。选中用暖色顶面、深色侧壁、轮廓与文字，悬停只预览轮廓和国名，无资料明确为 0 条。未据此宣称整页满足 WCAG。[W3C 非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 浮雕的顶点和侧壁均沿球心径向构造，顶面基准半径 2.508、抬升 0.067，约 2.67%；曲面细分避免大国三角弦面沉入海洋。保留多块领土、日期变更线拆分与孔洞，继续使用原 Natural Earth 资产。高度属于本项目调试选择，非地理资料或来源标准。[Three BufferGeometry](https://threejs.org/docs/pages/BufferGeometry.html)
- 拖动直接交给 OrbitControls，无拖动中插值；释放后才按最后角速度作指数衰减，时间常数 55ms、最长 220ms，静止后释放不续动。新输入接管；缩放距离 3.4—15，拖动速度 0.65、缩放速度 0.8。官方支持这些控制能力，但不规定“最佳手感”数值。[Three OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)
- 鼠标最大位移超过 6 CSS px、触摸超过 10px 后整段手势不再提交选择，即使回到起点；释放时确认，多指、取消、失捕与画布外释放不提交。触摸归属只在地球区域声明。阈值是本项目选择。[W3C Pointer Events](https://www.w3.org/TR/pointerevents3/)、[指针取消](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html)
- 国家文字按钮及原生“多选国家”复选框提供可聚焦入口；画布方向键旋转、加减键和按钮缩放、Home 复位。减少动态时保持同样的最终浮雕，关闭惯性；正常状态也直接呈现选择，未采用研究阶段建议的抬升过渡。[W3C 键盘](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)、[减少动态](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion)
- 地图适合按需绘制；相机、数据、悬停与尺寸统一申请一帧，惯性结束后停止，隐藏与 dispose 清理。未引入新的动效或地图依赖。[Three 按需绘制](https://threejs.org/manual/pages/rendering-on-demand.html)

## 验证边界与证据

## 2026-11-12 接续核查

先保留中断前的九个修改路径及外部备份，再在同一工作树接续；之后按指挥方要求补充根使用指南和便携包使用说明，共十一条交付路径。`performance-3` 首次有效对照发现：旧地球每帧约 596 个绘制调用，帧间隔中位 63.7ms；当时的双层 `LineSegments2` 版本约 180 个调用，却达到 573.9ms。只关闭 `alphaToCoverage` 的 `performance-4` 没有改善；仅临时移除两条全局边界的 `performance-5-no-outline` 恢复到 50.7ms。这些诊断版本均非交付版本，原始样本保留。

最终使用专用屏幕线段四边形及共享端点边界去重；每段每层两个三角形，替代通用线段六个三角形的路径，仍保留双层边界和原地理数据。`performance-7-final` 使用同一 Chromium 129.0.6668.29、1440×960、ANGLE/SwiftShader 和 18 条合成可见资料，明确断言旧 bundle 路由确实命中。旧／新每帧绘制调用约 596／180，帧间隔中位 50.3／51.0ms，绘制提交中位 5.9／2.7ms，拖动采样均无长任务。选拉脱维亚的单次 Event Timing 为 56／64ms；这是含观察开销的实验室样本，不是 INP，也不证明 60fps、硬件 GPU 或真实触屏体验。最终版本修复了中间方案的明显退化，但没有据此宣称帧率优于旧版本。

补齐浮雕命中后的 `performance-8-final-picking` 为最终产品代码样本：相同浏览器／软件后端／场景下，旧／新帧间隔中位 51.4／65.4ms，绘制提交中位 5.2／2.0ms，绘制调用约 596／180；长任务分别 5／22 次，最长 58／55ms，单次选国 Event Timing 均为 80ms。两个版本均无页面错误。样本波动明显，最终样本的新边界仍有额外成本，因此不能声称已完全回到旧版本帧率；消除初版约 574ms 的严重退化与“达到旧帧率／60fps”分别判断。

速度采样和释放间隔改用输入事件自身的时间戳，防止事件处理延迟被当成用户停顿。`acceptance-8-ribbon` 在真实指针释放后记录到九次相机变化，末次在 296.2ms；确认惯性确实运行，再逐项检查输入接管、完整取消序列、慢／迟到响应、同一画布／镜头、真实浮雕及侧壁、减少动态、390px Chromium 触摸模拟、空闲停止与销毁。最终脚本另有明确的 315ms 实验室停止断言，并记录 CSP 违规；该窗口包含帧调度时间，配置中的 220ms 是惯性计算上限。

`acceptance-9-final` 使用最终产品资产及补强的停止时间／CSP 断言通过全组检查：末次相机变化为 282.8ms，桌面与手机均无页面错误或 CSP 违规，空闲三秒新增绘制为零。`research-continuity-final` 通过保存检索、慢／迟到响应、历史导航、同一画布、阅读返回、年份草稿、320／390px、原生 200% 缩放、失权和账号切换。`refresh-access-final` 通过刷新、失败后仍可操作、焦点／草稿／缩放保留、权限／账号重验与销毁；其中隐藏检查是受控 DOM 组件测试，非原生系统可见性证据，服务线程已关闭。相关资料分布单元测试五项通过；JavaScript／Python 语法、差异空白与重复单入口构建一致性检查通过，其他生成资产和许可文件没有变更。

图形检查仍为开发自测，独立 Standards／Spec／视觉审查由指挥方另行组织。最终设计 detector 对三份源码的扫描为零反模式、22 条提示；它没有解析运行页面，不构成整页质量认证。旧探索配色提示保留历史身份；新增常规文字采用既有设计系统颜色，地图暖色顶面和侧壁用于区别选择与数据色。

### 浮雕顶面命中与最终输入夹具

指挥方追加核对抬升后的视觉／命中一致性。`red-raised-pick` 复现拉脱维亚海岸内侧 `(24,57)` 的可见顶面没有取消选择：解析基面交点已落入海面。最终先对当前可见浮雕顶面／侧壁做真实三角形命中，再用基面近交点距离排除背面遮挡；普通未抬升国家继续使用解析基面。`green-raised-pick` 通过内陆中心、海岸内缘、北界内缘 `(24.75,57.87)` 与斜侧视角；最终整组还验证了点击美国背面投影不会取消背面的美国。

`acceptance-10`／`acceptance-11-timing` 的整组检查在快速释放条件处保留失败。后者的真实输入时间表明最后 move 至 up 间隔为 94.3ms，而 up 处理延迟仅 0.7ms：逐步等待自动化命令没有提供小于 70ms 的快速释放条件。产品门槛及惯性移动／315ms 停止断言没有放宽。最终夹具使用 Chromium CDP 可信原生鼠标事件，明确脚本化 16ms 输入时间戳，并先断言收到的间隔为 15—17ms，再用页面 rAF 观察相机确实移动及停稳；另以普通鼠标验证拖动跟手和静止持有后释放不续动。该夹具证明规定输入节奏下的浏览器行为，不证明真人、物理输入或真机延迟。

`acceptance-12-final` 通过上述补强后的全部检查，末次相机变化为 301.7ms，三秒空闲新增绘制为零，桌面与390px页面无 CSP 违规或页面错误。历史通过记录保持原版本身份，以本次整组结果覆盖最终产品代码；独立审查、集成、CI 和运行副本更新仍待指挥方推进。
