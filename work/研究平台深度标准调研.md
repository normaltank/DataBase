# 研究平台深度标准调研

日期及公开来源访问日期：2026-10-26。状态：一手资料调研与建设建议，不是施工规格、标准符合性声明或验收。项目基线：`8c5267296dc9b94ef537d714d558a6c52a63b6a3`。只读项目文档；未访问真实数据库、ThinkTank 或内部研究原件，未向外提交内部材料。原始 FAIR 论文页面访问受阻，原则条文核对 GO FAIR 维护页面；下文分别标明标准、宣言与本项目建议。

## 1. 专家会补做什么

最值得补做的是验证“一位不参与录入的研究员，能否沿一条结论找回原始依据、判断其是否被准确使用，并说明什么会推翻它”。这比再建一套分类或评分更接近研究平台的核心质量。

**标准与倡议原文：** W3C PROV-DM（2013 Recommendation）用实体、活动、责任主体及派生关系描述来历；它提供质量判断的依据，并不认证内容真实。[PROV-DM 摘要及组件](https://www.w3.org/TR/prov-dm/)。FAIR 的 A1.2 允许身份认证与授权，R1.1、R1.2 要求清楚的使用许可和详细来历；内部共用材料不因此必须公开。[FAIR 条文](https://www.gofair.foundation/fair-principles)。DORA 建议评价具体研究内容、考虑多类成果及政策实践影响，公开指标数据和方法；CoARA 主张以定性判断为主、同行评议居中、负责任地辅助使用定量指标。这些是评价倡议，不是本平台已经获得的认证。[DORA 第 1、3、11、14 条](https://sfdora.org/read/)、[CoARA 协议](https://coara.eu/agreement/the-agreement-full-text/)。

**建议采用的简化做法：** 选一个真实课题的一条核心断言，检查原句上下文、译法、推断步骤、相反材料与适用时期。事实、来源自身的主张及研究员解释分别记录；“没找到”附搜索范围，避免变成“不存在”。不把本库收录量当作总体影响力，也不把被提及、被批评、被采用混为一类。

**已有基础：** [PRODUCT](../PRODUCT.md) 已规定出处、责任、纠错与双维度影响；[研究流程规格 B3/B4、C4](../docs/specs/研究资料工作流程.md) 已覆盖摘录位置、资料版本、引用快照、导出及恢复；[长期路线](../docs/长期研究愿景与演进路线.md) 已提出相反解释和覆盖偏差。建议检验这些规则在真实研究中是否成立，复用现有摘录、笔记和报告。文档中的历史合成验收不能证明真实材料已这样使用，更不能仅凭“版本快照”推断已固定原件。

## 2. 从哪些最原始材料开始

从发布者的正式 HTML/PDF、标题页、署名和单位、出版日期、卷期页码、参考文献、附件与更正通知开始；机构关系查章程、正式组织页或公告，人物归属查原始署名及有日期的机构介绍。已有整理表用于发现线索，不能自我证明。

这里还有一层区别：核实“报告写了什么”可以查正式原文；检验“报告的实证结论是否成立”，还需其抽样方案、问卷、获授权的匿名访谈记录、原始统计表及分析过程。后者未公开或不可取得时，说明只能复核公开报告的陈述与论证，不能声称完成原始研究复现。数据库建设本身不取得访问受限研究数据的授权。

政策／社会影响优先寻找政策原文、引用位置、会议记录或采用文件：机构宣传只能证明该机构作出某种表述，政策引用也不能单独证明因果影响。检索日志和被排除材料同样重要，否则样本只留下容易获取或支持预期的内容。

**外部对照工具：** DOI 可用 Crossref 核对题录和更新，Crossmark 可发现更正、撤稿，但官方明确其存在本身不保证正确；缺少更新记录也不能证明从未更正。[Crossref 数据来源](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[Crossmark 限制](https://www.crossref.org/crossmark/)。ORCID 要查看具体断言由本人还是机构提供；ROR 用于机构消歧，有收录范围，未找到不能推断机构不存在。[ORCID 断言来历](https://info.orcid.org/interpreting-the-trustworthiness-of-an-orcid-record/)、[ROR 官方收录口径](https://github.com/ror-community/ror-updates/blob/master/README.md)。这些服务与原站可能共用上游数据，多处一致不必然是独立证据。

## 3. 具体方法与工具

建议先做一条小样闭环，而非增加专门系统：

1. 明确问题、时段、语言、检索入口与纳入／排除理由；在现有专题／笔记记下实际检索词、日期和未能获得的材料。
2. 对选中原件记录发布地址、取得时间、所据版本和保存范围；用 PDF 阅读器核页码，网页同时记录标题、段落及上下文。提取文字、OCR 或译文均作为衍生内容，关键句回看原页；自动文本不能替代原件。
3. 用现有摘录保留原句、定位与译文，再在报告逐断言说明支持、反驳或仅提供背景。含数字时复算分母、单位与时间窗；更正一个身份或译法后，判断哪些结论需要重审。
4. 让非录入者只拿现有可读导出包复核，再独立回原站对照。包内说明题录、摘录、原件分别保存了什么；文件清单及 SHA-256 可检出相对既定基线的字节变化，缺件或无法定位如实报错。

NDSA 的保全指南建议在接收及后续保管阶段校验文件完整性；这里借鉴基本做法，不声称达到某个保全等级。[NDSA 原始分级说明，2013](https://www.ndsa.org/documents/NDSA_Levels_Archiving_2013.pdf)。散列只支持完整性核验；若首次保存的就是错误文件，或文件与清单一起被替换，散列不会证明作者身份、来源真实性或观点正确。

## 4. 除用户和建设方外，谁／什么能验证

出版社、原始发布机构、DOI 更新记录可核实发布事实；具备相关语种能力的独立研究员可检查译文、上下文和论证；图书馆员／资料管理员可复核题录、版本与查找路径；另一位未参与实现的人员可在新目录恢复、离线检查附件和关系。复核者需有材料访问授权，独立性来自不同责任、方法与证据来源，而非仅换一个账号。

测试通过只证明所测程序行为；恢复成功只证明保存与恢复链；内容复核只能支持明确检查过的断言。美国国家科学院区分同数据同方法的计算可复现与使用新数据的研究重复验证，因此“再次算出同一结果”仍不等于现实结论正确。[NASEM 定义及限制，2019](https://www.nationalacademies.org/read/25303/chapter/3)。多个 AI 的一致意见可用于找疑点，不能当作独立验证。

## 最值得落实的三件事及未知项

- 用一个真实研究问题，完成原件→摘录→报告核心断言→非录入者复核；尚无课题时，只能称来源／题录忠实性抽查。
- 把现有导出加深为可说明留存范围、核对文件字节并离线检查的证据包；保持“保存可靠”和“内容成立”分别出具结论。
- 做一次来源更正或译法纠错演练：保留旧报告当时依据，指出受影响断言，由内容责任人决定修订；实际暴露缺口后再改产品。

仍未知：首个课题与比较范围、人员语种能力和独立复核安排、关键来源是否可获得及允许留存／共享、样本覆盖偏差、真实原件与历史引用能固定到何种粒度。本调研未逐条检查真实资料，也未测代码，因此不能报告真实证据链通过或判断某项工程缺口已被修复。
