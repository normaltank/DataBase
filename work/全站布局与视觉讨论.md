# 全站布局与视觉：讨论与取舍

## 本地核查

结构与视觉两个独立子 Agent 均采用 gpt-6.1-sol / high，只读核查代码和既有规格。两者一致指出：当前已具备阅读与研究功能，主要缺口是各页的排版、组件和操作层级不同；继续在样式末尾追加覆盖会加剧差异。来源介绍和来源内容实际已经前置，本轮不能把已有功能写成新建。

指挥方查看本地运行页面，约 503px 宽的资料库首屏只有标题、操作、搜索和常驻筛选，尚看不到第一条资料；常驻图标侧栏进一步压缩可用宽度。中屏双栏偏窄是代码推断，需在施工中实际验证，不作为已复现截图结论。

## 采用的方案

- 先统一公共骨架、排版和样式职责，再分别整理来源／人物与工作台／专题／维护；共用文件设单一负责人。
- 窄屏使用有文字的折叠菜单，高级筛选按需展开；已用条件常显。主列表尽早显示实际材料，低频整理操作收拢。
- 来源、人物、专题保持各自业务结构；长详情用章节定位，不重写为统一字段卡片。文字与颜色帮助区分内容、出处、状态和操作。
- 16px 正文、17px 长文、至少14px必要说明；蓝白为主体，柔黄少量强调。黄对白对比不足，不能用作普通文字或白字按钮。
- 删除装饰口号和重复空说明，保留原名、权限、依据、未知状态、冲突、身份纠错与备份后果。维护页过期的附件能力说明随本轮校准。

## 未采用与边界

全站重写、换框架、统一全部详情路由及装饰图表不能直接改善本轮问题，不纳入施工。来源采集、评价、自动翻译仍按原路线后续推进。视觉判断须通过实际桌面、中屏、手机和放大显示验证；没有真实研究员试用数据，不宣称已经获得使用满意度结论。

## 讨论来源

三位子 Agent 均使用 gpt-6.1-sol / high。完整只读笔记保存在本机临时目录 `database-ui-structure-discussion.md`、`database-ui-visual-discussion.md`、`database-ui-workflow-discussion.md`，包含代码指针、尺寸建议及需保留的交互；公开文档只保留可维护结论。

第三位从操作与可访问性提出：中屏样式必须与阅读的角色、焦点和滚动断点共同调整；章节定位不能掩盖权限和待复核提示；表单报错与冲突持续可见并保留输入；批量与筛选导出作用范围须清楚；移出专题、解除关系、历史恢复及合并继续表达不同后果。上述建议已并入规格，现有能力作为回归，不假称新增。

## 官方参考及取舍

- [Zotero 资料组织](https://www.zotero.org/support/collections_and_tags)：同一资料可以属于多个集合，移出集合不等于删除资料。本轮借鉴清楚的组织与作用范围提示；平台独立使用，专题仍围绕研究问题组织，业务模型未变。
- [Carbon 数据表格](https://carbondesignsystem.com/components/data-table/usage/)：内容需要足够横向空间，工具栏、行内及批量操作区分影响范围，手机操作不能依赖悬停。本轮采用这些原则检查资料列表与工具区，不引入其组件库，也不把所有对象改成表格。
