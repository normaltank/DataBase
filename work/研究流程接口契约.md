## A（接口已落盘，尚在针对性验证）

- `GET/POST /api/records`、`GET/PUT /api/records/<id>` 沿用原记录接口。新增 kind：`directory_translation`（共编目录译稿）、`research_note`、`research_report`；`compilation` 为个人成果。读取始终返回 `can_edit`。
- 新字段：`body_html`（允许列表处理，最多 50 万字符）、`body_text`（服务端生成）、`coverage`、`original_catalogue`（原目录出处文字）、`aliases`（文本，每行一个）、`related_source_ids`（来源 ID 数组，多对多，独立于发布机构 source_id 和所属期刊 serial_id）。正文、关系与附件 ID 进入版本快照。目录译稿要求题名、编译者 authors、coverage、至少一个 related_source_ids，且 visibility=shared、editors=[]。
- 所有内容仍使用原 multipart `data` JSON + `file` 上传，附件一次一个、可追加。来源详情用 `/api/records?source=<id>` 获取直接归属及一般关联内容，同一记录只返回一次。
- 来源详情／修订接口新增 `introduction_html`、服务端生成的 `introduction_text`、`aliases`。当前所有有效成员可编辑介绍（原来源版本机制）。
- 搜索 q 纳入正文、介绍、别名；列表返回纯文本 `search_snippet`，前端须转义后显示。资料原筛选保持；来源 q 支持多词。
- `GET /api/records/<id>` 还返回 `author_id`、`author_confirmed`、`author_name`、`owner_name`、`last_modifier`（name、created_at）。个人成果新建可指定 author_id，本人提交自动确认，代交待指定作者确认。负责作者与署名 authors、上传者 owner_id 分开。
- `POST /api/records/<id>/author`：`{version, author_id, confirm}`。未确认时，上传者可指定有效负责作者（confirm=false）；指定作者本人 confirm=true。历史个人成果 author_id=null、author_confirmed=0，上传者可显式选择本人并 confirm=true 认领，或指定他人待其确认；管理员不能越权。确认后只有作者／作者授权 editors 可以编辑或恢复；只有作者能调编辑授权和可见范围。编辑人员选择应包含管理员，管理员身份本身不赋予个人正文权限。原始资料旧维护权限不变。
- 保存冲突 409 时不要关闭表单；保留全部输入，GET 最新记录／来源作对照，用户明确选择已对照后才更新待提交 version。需实现刷新／关闭后的草稿恢复（用户隔离）；附件选择若持久化用 IndexedDB，避免只保存文件名。
- 历史列表／恢复沿用现有接口；恢复不回退当前 ACL 和作者确认信息。旧版本没有新增字段时保留当前字段。

## B/C

### B（已通过后端针对性验证，8850 已运行完整 A/B/C）

- 摘录复用 `kind=research_note` 的记录及其作者权限／历史。`POST/PUT /api/records` 新字段：`evidence_record_id`（原始资料）、`quote`（原文摘录）、`translation`（译文）、`interpretation`（自己的说明）、`locator`（页码／段落等）、`evidence_url`（HTTP/S 链接）、`evidence_attachment_id`（原文附件）。关联原文后 quote、locator 必填；服务端保存 `evidence_version` 与 `evidence_snapshot`。改摘录不自动刷新原文依据，明确 `refresh_evidence=true` 才更新引用版本。
- 原文详情新增 `excerpts`；`GET /api/records?kind=research_note&evidence_of=<原文id>` 列举可见摘录。笔记详情 `evidence_file_url` 可下载所据历史附件；无权限读取原文时，关联摘录也不可见。
- 原文 `evidence_snapshot` 保留 id、kind、title、original_title、authors、published_on、url、doi、version；实际引用文字保存在 quote（并分别保存 translation、interpretation）。新快照不复制未引用的整篇正文。前端“引用时原始资料快照”应展示上述元数据，兼容旧快照可选的 body_html/abstract；不要仅渲染这两个可选字段而留下空白。
- 报告／个人编译成果保存 `evidence_ids` 数组，引用笔记或摘录。详情 `evidence_citations` 每项含 excerpt_id、excerpt_version、current_version、snapshot（原文摘录／译文／解释／定位等）。保留已有引用不自动刷新快照，明确 `refresh_citations=true` 且提交 evidence_ids 才更新；返回原文或笔记使用原编号（合并后自动指向保留编号）。
- `GET /api/duplicates?type=source|record` 返回 items（keep、duplicate 各含 id/name，reason），仅疑似提示。`POST /api/merge/preview` 传 `{type,keep_id,duplicate_id}`，返回 keep、duplicate、allowed、blocked_reason、impact、explanation。`POST /api/merge` 传前述三字段加 `{keep_version,duplicate_version,confirmed:true}`，返回 `{id,previous_id}`。公共资料／来源合并需管理员；个人内容合并需两条作者编辑授权；类型、可见范围、提交责任或编辑授权冲突会阻止。图关系自环／循环、引用快照冲突也阻止，事务不部分写入。
- 保留记录正文为主，另一记录正文与历史归档保留；旧名称和编号进入 aliases，旧 URL 编号可继续打开保留记录。详情 `previous_ids` 可进入 `GET /api/merged/<source|record>/<旧id>` 查阅旧内容，受当前及原归档可见权限约束。
- 历史列表补 target_id、restorable；归档旧对象历史不能直接恢复为主记录。`GET /api/history/<修订整数id>` 返回 snapshot、action、target_id，受编辑及证据权限检查，可用于内容对照。

### C

代码已落盘，正在测试。`GET /api/collections/<id>` 返回专题元数据和可见 `items`、can_edit、can_manage_visibility；POST 原 `/api/collections` 和 PUT `/api/collections/<id>` 支持 name、description、visibility、research_question、comparison_html、stage_judgment。PUT 必须带 version；comparison_text 服务端生成。中心专题成员可共同整理，个人专题仅本人；可见范围仅创建者可调。

`GET /api/collections/<id>/history` 列版本；`POST /api/collections/<id>/restore/<修订id>` 携带 `{version}` 恢复正文和成员可见的原有资料集合，若历史资料已无读取权限则拒绝恢复，保持当前可见范围。通用 `GET /api/history/<修订id>` 可看专题历史快照；隐藏不可见记录编号。原 `/api/collections/<id>/items` 可加入普通资料、研究笔记、摘录和报告，移出只解除关联。

`GET /api/members`（管理员）含 id、username、name、role、active；`POST /api/members` 传 username、name、role（researcher/admin）、password（12—200字符）；`PUT /api/members/<id>` 可传 name、role、active（布尔）、password（重置）。保护最后一个有效管理员；停用/重置凭据会使旧会话失效；停用不删除署名或版本。返回 reauthenticate=true 时本人需重新登录。

`POST /api/account/password` 传 old_password、new_password，修改本人的密码；当前会话继续有效，其余旧会话失效。前端不要把密码写入草稿存储。

`GET /api/export/content` 接受原资料列表筛选参数（q/source/kind/collection 等），下载 ZIP：index.html、每条记录独立 HTML、content.json、可见附件；包括可访问的引用笔记和原文，保留引用快照。按当前读取权限过滤，不含账户凭据；完整历史与全库恢复使用管理员完整备份。原 CSV 导出保留为清单导出。恢复工具现兼容 schema 1—5。
