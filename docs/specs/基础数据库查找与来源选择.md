# 基础数据库查找与来源选择

版本：1.0。日期：2026-10-26。状态：已实现并完成本轮本地验证，见[验收记录](../../work/基础数据库查找与来源选择验收.md)；CI、合并及本机切换由任务 [#28](https://github.com/normaltank/DataBase/issues/28)／[PR #29](https://github.com/normaltank/DataBase/pull/29) 维护。固定审查基线为 `32f66da964a70034909f7bdedf1f916828c15e6e`。需求出处见 [R016](../需求讨论记录.md#r016基础数据库建设与完整使用流程)，长期规则沿用 [PRODUCT](../../PRODUCT.md#地域与国际属性已确认)。

## Problem Statement

研究员在资料库筛选时面对全部机构和期刊的长名单，无法先按国别或国际办刊定位缩小范围。同类问题也出现在资料录入和来源关系维护中。用户尚未体验全部功能，要求建设方主动检查完整基础流程，不能把体验改进局限于用户已经报告的控件。

维护区把门户类登记称为“采集入口”，容易让人误以为只有这些网站可以采集，或系统已经配置了采集任务。当前登记只用于发现资料，机构与期刊自己的官网也可能成为后续采集地址。

## Solution

围绕查找、阅读、录入编辑、来源维护、专题整理和导出做一次任务式核查。本轮完成来源范围查询、可搜索的来源选择、筛选上下文保留和发现网站入口说明；核查发现的其余问题分别说明实际影响与处理状态。

研究员可以先选机构、期刊或其他出版物，再按来源国别缩小范围；期刊可叠加独立的国际办刊定位。无需指定某一家来源即可查询这一范围内的资料，也可搜索并选定具体来源。录入中的长来源选择使用同样清楚的名称、类型和国别信息，保留各字段自己的关系含义。

## User Stories

1. 作为研究员，我希望按来源类型筛资料，以便区分机构、期刊与其他出版物。
2. 作为研究员，我希望按来源国别筛资料，以便找到指定国家的机构或出版物所关联的材料，无需逐家选择。
3. 作为研究员，我希望期刊国别沿用有依据的主办国、出版方另记，以免把出版商所在地当作期刊国别。
4. 作为研究员，我希望国际办刊定位与国别并存，明确区分是、否与未知，以免把未知当作非国际。
5. 作为研究员，我希望多国主办来源可从任一已确认国别找到，缺少归属依据的来源可从“待确认”找到。
6. 作为研究员，我希望通过显示名称、原名和别名搜索具体来源，并在有界的候选区看到类型与国别，以便识别长名称和同名条目。
7. 作为研究员，我希望变更上层条件时明确处理已选来源与新范围的冲突，以免隐藏条件造成莫名的空结果。
8. 作为研究员，我希望来源国别与资料研究对象国有不同标签，能够组合使用，以便查找某国来源研究另一国家的资料。
9. 作为研究员，我希望类型、国别与国际条件约束同一个关联来源，以免一篇资料分别关联不同来源就误满足组合条件。
10. 作为研究员，我希望看到已应用条件和结果总数，逐项清除或重置筛选；新条件从第一页开始，空结果能提示调整条件。
11. 作为研究员，我希望刷新、前后导航和分页保持已应用的查询，清除筛选保留所在专题；改变查询后原批量选择不能误用到新结果。
12. 作为研究员，我希望列表、清单导出和完整内容导出使用同一查询规则，并保持现有可见权限。
13. 作为贡献者，我希望在资料新建与编辑时搜索发布机构、所属刊物与一般关联来源，以便准确登记出处而不逐项滚动长名单。
14. 作为来源维护者，我希望搜索期刊主办方、出版方及机构关系的目标，并保留既有多选、移除及必填规则。
15. 作为编辑者，我希望在搜索或缩小候选后仍能看到已选值；草稿恢复、校验失败和保存冲突保留我选择的来源。
16. 作为键盘或窄屏使用者，我希望来源选择有明确标签、可操作的焦点、选择与清除反馈，长名称不会遮挡提交按钮或撑破页面。
17. 作为成员，我希望维护区及其管理、详情和表单一致称为“资料发现网站”，清楚知道它用于保存门户与检索网站，尚未自动采集。
18. 作为成员，我希望机构与期刊官网继续保存在原档案，明白后续采集可关联官网的文章列表、刊期或订阅地址，无需重复建一份机构记录。
19. 作为使用者，我希望建设方主动核查阅读返回、人物档案、专题与导出等基础操作，把已实证的问题、当前修复及尚待处理的影响分开记录。

## Implementation Decisions

- 来源范围是查询的派生视图，复用既有来源身份、合并重定向和目录中的国别依据。机构采用登记国家；期刊和其他出版物采用现有主办国别推导，缺少依据保持待确认。国际定位仅用于期刊；界面须清楚处理不适用类型。
- 新的来源查询条件独立命名，既有资料研究对象国含义不变。组合条件须由同一来源满足；具体来源也是该交集的一部分。资料通过发布机构、所属刊物或已登记的一般关联命中，界面不得将所有关联描述为发布关系。
- 公共资料查询与两种导出复用同一匹配边界，权限先行。旧来源编号、来源档案分区查询、收藏和专题范围继续可用。无效条件应有明确反馈，不能悄然变成无筛选查询。
- 候选名称搜索用于选择来源，不自动变成资料关键词。选择器保留稳定编号和原字段提交方式；固定单一类型的字段只展示适用对象。已选多值与未选候选分别可辨，搜索或候选过滤不删除已选值。
- 提交资料、一般来源关联、来源主办／出版方和机构关系等长选择复用统一交互；已经具备有效搜索的人物任职和署名选择只核查一致性，不为统一外观强行改写业务流程。
- “资料发现网站”是现有门户类登记的显示名称调整。保持原编号、网址、关系、历史和维护入口兼容，不重分配真实来源或建立抓取配置。
- 沿用普通共编、草稿、版本冲突、作者授权和现有主题。预计无需数据库结构迁移；若实现发现必须改变业务模型，应先反馈原因。

## Testing Decisions

- 沿用已授权的公共 HTTP、导出文件和真实浏览器边界；测试验证用户可观察的结果和数据保全，不用内部函数或页面源码字符串代替行为。
- 隔离样本包括多国主办、主办国与出版国不同、归属待确认、国际定位三态、跨来源组合误匹配、原名与别名、长名单、一般关联、合并旧编号、私人资料及空结果。
- HTTP 检查查询、分页、筛选组合、权限及 CSV／内容 ZIP 的条目一致性；复用既有来源档案和导出验证模式。
- 浏览器在桌面和窄屏验证来源范围及名称搜索、清除与键盘选择、返回刷新、专题范围、批量选择失效、单选与多选、草稿恢复和保存。用合成资料验证写入，不把测试数据加入真实库。
- 主服务切换前完整备份并记录真实库表与文件摘要，切换使用禁导入启动，确认健康状态、资源版本和数据保全。开发检查、指挥方独立验收、双轴审查分别记录。

## Out of Scope

自动采集、RSS 订阅执行、批量下载、OCR、机器翻译、影响力计算及新权限体系。来源资料事实核验和研究结论质量不由本轮软件测试代替；全面流程检查也不等于所有未知使用问题已经解决。
