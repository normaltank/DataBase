# 机构与期刊研究档案

2026-10-26；版本 1.0。状态：代码已集成，开发与独立页面验证完成；[验收记录](../../work/机构与期刊研究档案验收.md)保留证据，最终集成与部署结果由[任务 #26](https://github.com/normaltank/DataBase/issues/26)维护。用户在比较字段表、长文 Wiki 和混合档案后答复“按你的计划去做吧”。本轮延续[产品规则](../../PRODUCT.md)和[术语](../../GLOSSARY.md)，实施基线为 `e5bfafff8c249236443a9c4ebb0760bd5d93fba2`。

## Problem Statement

人物已有独立档案页；机构和期刊虽有可共编介绍、结构字段、关系及研究笔记，主要仍在来源抽屉内。直接访问、长文阅读、连续整理及内容分类不够清楚，来源关联内容容易与实际发布或刊载作品混淆。研究员需要围绕同一对象持续积累并查阅，而不是在不同页面重复登记。

## Solution

机构、期刊与其他出版物使用可直接访问的独立研究档案，沿用既有身份、资料、关系和历史；来源目录保留快速预览。正文适合介绍背景和沿革，结构字段与有依据的关系用于查找、筛选和未来分析。统一阅读、编辑和历史操作，按机构与出版物分别呈现适用内容。

公共介绍全员共编；关于对象的研究笔记通过明确的研究对象关系汇集，继续遵循作者授权。已收录原始资料、目录译稿和中心成果分别表达，普通来源关联不推定为发表关系或研究对象关系。

## User Stories

1. 作为成员，我希望从目录名称进入机构或期刊的独立档案，以便完整阅读和继续研究。
2. 作为成员，我希望复制当前地址后能重新打开同一档案，刷新和直接登录后也能到达，不必再次搜索。
3. 作为检索者，我希望在目录快速预览，再进入完整档案；关闭预览后仍保留原筛选和位置。
4. 作为读者，我希望档案提供清楚的简介、信息、关系、资料、研究笔记及历史入口，并在窄屏也能阅读和定位。
5. 作为机构研究者，我希望看到机构类型、所在地、隶属／设立等关系、相关人员和主办刊物，机构字段不出现 ISSN。
6. 作为期刊研究者，我希望看到办刊介绍、主办方与出版方、主办国别、国际定位及 ISSN，保留各自依据与未知状态。
7. 作为其他出版物的整理者，我希望沿用适用的出版物档案，采集入口仍在维护区管理。
8. 作为资料使用者，我希望分清实际发布／刊载资料、一般关联资料、目录译稿和中心成果，不把中心笔记当成机构公开作品。
9. 作为译目整理者，我希望在对应档案新建、查看和继续编辑不同卷期／覆盖范围的目录译稿，已有附件入口保持可用。
10. 作为研究员，我希望查看和新建明确研究该机构或期刊的笔记，一份笔记可以在多个对象处出现，责任与可见范围不变。
11. 作为共同维护者，我希望修改介绍和信息后回到原档案，关闭编辑能保留草稿，并能查看历史及按原权限恢复。
12. 作为共同维护者，我希望别人先保存时，我的输入保留并得到冲突提示，不被最新档案覆盖。
13. 作为读者，我希望返回目录时保留筛选，打开关联人物、机构、期刊和资料后可以继续原来的阅读路径。
14. 作为使用旧链接的人，我希望合并前编号能指向当前对象并说明去向，缺失或不可访问的对象有明确提示。
15. 作为读者，我希望大量内容可分页或继续查看，数量只统计有权限看到的内容，空态和未知不被写成不存在或影响力低。

## Implementation Decisions

- 复用现有数据库、来源稳定编号、介绍、字段、关联、历史、冲突与权限机制，预计无需结构迁移。阅读页和快速预览共享领域呈现，避免两套内容和权限实现。
- 独立档案使用现有前端路由体系和可直接访问的地址。保存、核对、历史恢复、归并及草稿续作更新当前视图；上下文返回保持目录筛选，页面跳转不得留下过期抽屉或详情对象。
- 页面采用蓝白柔黄、正文可读和按对象分节的现有视觉基础。机构与期刊分别提供主要资料入口；低频维护操作收拢，辅助文字只说明必要区别。其他出版物沿用适用模板。
- 资料分区依据已存明确关系及内容类型：机构发布、刊物刊载、一般来源关联分别解释；目录译稿显示覆盖范围；研究对象笔记沿用明确关联。中心成果可以独立汇集，一般来源关联不能伪装为对该对象的研究。多重关系允许同一记录在有明确意义的入口出现，避免同一分区重复。
- 仅依据当前有权限访问的内容计算数量并分页。若复用资料查询需要补充过滤条件，在现有公开接口增加窄范围参数并验证其与权限、别名／合并编号及其他筛选一致；不在浏览器取前 100 条后冒充全部结果。
- 背景和沿革先用可编辑介绍积累，不从叙述自动提取或猜测新的时间关系。学术及政策影响评价保持已有长期方向，不生成分数。

## Testing Decisions

沿用此前确认的实际页面和应用公开 HTTP 边界；技术实现由建设方决定，无新测试边界。通过界面行为、响应和公开下载验证，不断言内部函数或 HTML 字符串实现。

1. 使用隔离合成材料，先证明独立档案直达或分类行为在基线失败，再逐项实现。若修改资料筛选，HTTP 用明确的发布、刊载、仅关联、目录译稿、私密内容及超过单页的样本验证分组、计数和分页。
2. 实际浏览器检查目录→独立档案、快速预览、刷新、直接链接、返回筛选、跨对象与资料往返、旧编号和缺失对象。
3. 实际操作介绍编辑、草稿续作、并发冲突保稿、历史恢复、目录译稿和研究笔记；核查普通成员与未授权者的编辑边界，既有作者及原文流程保持。
4. 检查桌面、平板和 390／320px 窄屏，长名称、长文、表格、空态及键盘章节定位；全页不横向溢出，正文表格可局部滚动。复用既有档案、阅读和布局检查并调整真实交互路径。
5. 最终集成运行相关回归、完整检查、双轴独立审查及 Windows／Linux CI。部署前备份并只读比对真实库和原附件，开发与验收仅用合成内容，真实库不导入测试数据。

## Out of Scope

新建通用 Wiki 引擎、重建数据库、真实资料清洗、自动采集／翻译、正式影响力评价、独立卷期数据库、关系时间模型改造、实时协作、权限重设、门户 Wiki 化及正式多人部署。普通文章继续使用资料阅读页。此次页面可用性验收不等于已完成真实研究课题的独立复核。
