# 两阶段材料交接与研究界面简化

版本：1.0；日期：2026-11-04。状态：按用户最新明确要求冻结，实施及交付状态以关联 GitHub Issues 为准。

## Problem Statement

研究员希望上传材料给负责人查阅、退回或通过，网站却要求录入线下会议决定和逐篇文章分工。缺少分工时进入编译入口消失，结束整期成为显眼动作；用户因此把结束当作进入下一阶段。阅读和档案页又让维护、核验、处理自证及重复空态占据首屏。

用户最新明确：第一阶段上传、负责人审阅及退回；线下决定选篇，无需站内会议或分工。负责人直接进入第二阶段，成员继续上传，负责人审阅，再结束本期。本轮以此替代旧版强制会议分工流程，不用旧实现反推用户需求。

## Solution

把主题工作做成两阶段材料交接板：选题材料、编译材料均可直接上传并逐份审阅，负责人直接推进阶段及结束。日常页面首先展示材料、状态和当前动作；重复的核验、免责和流程自证文字删除，文件来源及历史按需查看。

## User Stories

1. 作为成员，我在选题阶段直接上传材料，不必登记文章或会议。
2. 作为成员，我可以提交多份材料，同一人多篇继续可用。
3. 作为成员，我能对已有材料提交新版本，先前文件和署名继续留档。
4. 作为负责人，我首先看到本期成员的材料及待审状态，能直接打开文件。
5. 作为负责人，我能对选题材料的具体版本通过或退回；退回意见和附件可选，不强迫另写会议说明。
6. 作为成员，我能看到退回状态和已提供的意见，并就原材料重交。
7. 作为负责人，我通过的是具体版本，新版本重新待审，不继承旧版通过。
8. 作为负责人，我能直接进入编译，不以会议、文章分工、原文入库、全员交齐或全员通过为前置。
9. 作为成员，我在编译阶段沿用同一上传、查看状态及重交流程。
10. 作为负责人，我在编译阶段沿用同一查看、通过及退回操作，自己也是作者时亦可体验完整流程。
11. 作为成员，我能切换查看两个阶段的材料，不把查看页签误当成改变业务阶段。
12. 作为成员，我进入编译后仍可按原权限补交选题材料，历史不会因切阶段消失。
13. 作为负责人，我能结束本期，结束不以汇总或全部材料通过为前置；必要确认只简短表达当前影响。
14. 作为读者，我能在结束后查阅、下载及导出已存材料，期内写入停止。
15. 作为有效负责人，我能重开已结束期，恢复原阶段及材料，不清空历史。
16. 作为负责人，即使本期已结束，界面仍正确标识我的负责身份；可用操作另行判断。
17. 作为旧用户，已有选题报告、会议、分工稿件、退回、定稿、汇总及固定采用继续真实留档、可读及可恢复。
18. 作为旧用户，升级不会编造空会议、虚拟文章分工、通过记录或转换历史，也不会重新播种我的试用库。
19. 作为普通成员，我的材料由本人维护；负责人审阅权不变成改写作者原件的权利，维护管理员不自动取得业务审阅权。
20. 作为试用者，现有临时身份、本人归属、参与人选择和主机维护边界继续可用。
21. 作为研究员，首屏能看清题名、当前阶段、材料状态及一项突出动作；结束整期与进入编译有明确区别。
22. 作为研究员，我不用阅读每个模块反复出现的免责声明；机器译题、机器译文、待审、退回、通过等以对应短状态表达。
23. 作为读者，无论从检索、来源还是人物档案打开资料，正文或摘要都先于作者维护、关联建议及核验信息出现。
24. 作为档案读者，我先看到介绍、任职及作品；空区和已处理建议保持紧凑，待办、维护与历史按需打开。
25. 作为提交者，失败、版本冲突、重试和连击不会丢文件或重复提交；账号切换后旧操作不会借新账号继续写入。
26. 作为键盘或手机使用者，我能完成上传、审阅、切阶段与结束，控件可辨、焦点正确，窄屏和放大不遮挡动作。
27. 作为主机使用者，新旧材料、审阅及阶段事件进入材料包和备份恢复校验，真实数据升级前备份、保留端口与运行路径。

## Implementation Decisions

- 本轮改变主题编译的业务前置，而非隐藏旧表单。两阶段直接材料和按版本审阅由公开业务接口承载；阶段转换直接表达负责人的推进决定。具体存储与接口由实施者安排，复用现有原件保存、身份和并发边界，不造通用审批平台。
- 会议与文章分工从普通研究员主流程撤出。已有记录保持历史身份；旧定稿与新流程的通过分别表达。汇总及成果关联保留为按需功能，不作为进入编译或结束前提，不自动把审阅通过当成成果发布。
- 结束与重开沿用当前有效负责人规则；没有全员交齐或全员一篇的新增门槛。服务端继续按成员、作者、负责人资格、实际版本及结束状态核权。
- 设计语言保留蓝白工作台：题名和阶段先于材料清单，状态贴近文件，主动作突出，维护与收尾次级。正文阅读以白色内容面为主，浅蓝用于选中状态，减少包围盒及重复说明。
- 直接删除正常阅读中的重复核验、免责、空态辩解、合成包处理自证及流程自证。真正影响当次操作的错误和后果就地短述；原始证据与历史保留入口，不让后台约束变成常驻小字。
- 同一次操作的保存与阶段改变须如实表达：若提供合并动作，整体成功或整体失败；不得以两次独立请求冒充原子行为。普通上传及审阅不自动切阶段。
- 本轮正常运行会涉及版本升级，先在合成旧库验证迁移、材料包及恢复。恢复接手和诊断不手改真实期次；最终升级前完成备份，保持实际正在使用的便携目录、数据、身份和端口。

## Testing Decisions

- 沿用已授权的公开 HTTP、真实 JS/DOM、真实浏览器及原生包边界；补足之前遗漏的完整材料流，不让截图或渲染字符串代替可执行流程。
- 最小红例包括：没有会议和分工时负责人直接切阶段；选题期材料可退回及通过；闭期负责人身份仍正确；从档案打开资料正文被维护区挤出首屏。
- 两种独立成员身份实际走：选题上传→负责人退回→本人新版本→通过→直接进入编译→多份材料上传→退回/重交/通过→结束→重开；额外单人负责人兼作者也可完成。
- 验证新版本不继承通过、旧版本可下载、非法成员和纯管理员不可越权、旧表单闭期拒写、并发审阅/切阶段/结束及未知结果重试。
- 合成旧库覆盖既有候选报告、旧会议分工、稿件、退回/定稿及固定汇总。备份在新目录恢复，核实际文件字节、作者、版本、阶段及历史；不伪造旧记录。
- 1366、900、390及200%等效放大，检查首屏材料/动作、阅读顺序、键盘和关键短状态；清理小字后仍可辨认机器内容、空状态与真实错误。
- 集成后按 Matt 流程完成必要检查、独立双轴及统一返修；两份同提交包验收，便携单一固定运行路径和仅回环合成测试，不用真实收费服务。

## Out of Scope

- 自动记录线下会议、强制选篇审批、在线写稿、自动研究结论或新增采集源。
- 删除旧材料、改写历史署名/定稿/采用，自动清理用户身份，改变期刊独立业务或成果作者授权。
- 生产免登录、重设凭据、ThinkTank 导入、真实收费实验，或与本轮无关的基础设施和防御框架。

## Further Notes

本轮依据是用户对两阶段上传审阅的最新明确描述及直接删减防御小字的要求。旧两阶段规格记录曾有的会议分工约束，由本版在对应业务范围取代；旧讨论和已交付验收保留历史身份。GitHub Issues 是唯一任务台账。
