# 标准题录交换

版本：1.0。日期：2026-10-27。状态：本轮实施基线；任务、集成与最终交付由 [#36](https://github.com/normaltank/DataBase/issues/36) 跟踪。

本轮依据：用户要求接手后继续基础数据库建设，技术路线在既有业务范围内由建设方决定。采用一种格式完成闭环；已交付的出版字段沿用 PR #50。代码基线为 `2f6845bb65e23df565b684e0ade600bd1a606c9f`。权限、身份及研究质量规则沿用 [PRODUCT](../../PRODUCT.md)，不改变其业务含义。

## Problem Statement

研究员从期刊或机构取得题录文件后，尚不能在平台预览、纠正和保存，也不能将选中的资料以标准题录交给其他工具复用。已有卷、期、页码、ISSN、CSV、可读内容包和完整备份各有用途，不能代替标准文件交换。旧 #36 所称正式出版字段缺失仅对应当时基线。

## Solution

首版采用 UTF-8 RIS。成员选择小文件，查看逐条结果，修改题录、核对重复与可选身份／来源候选，明确保存一条后继续下一条。从资料库选中可交换的外部资料，下载同格式文件，在独立解析器中核对输出。平台本身独立运行，不安装或调用 Zotero。

## User Stories

1. 作为资料贡献者，我希望从资料库进入文件导入，以便沿着既有查找和录入流程整理题录。
2. 作为贡献者，我希望看到文件中各条题录、缺项、不支持类型及格式错误，以便决定处理或跳过哪条。
3. 作为贡献者，我希望修改题名、署名、日期、刊名和出版字段，以便纠正外部题录后再保存。
4. 作为贡献者，我希望原始条目与我的修订分别保留，以便之后解释题录的来历。
5. 作为贡献者，我希望看到当前有权查看的 DOI、网址及相近题名重复线索，以便打开已有资料核对。
6. 作为贡献者，我希望文件内的重复也有提示，保存时再次检查，以免连续操作新增重复。
7. 作为成员，我希望人物与来源候选只是线索，身份关联仍需选择和依据，以免同名误并。
8. 作为贡献者，我希望不确认人物也能保存原始署名，随后继续整理身份。
9. 作为贡献者，我希望保存失败、冲突或慢响应时保留编辑内容，并明确知道哪些条目已经保存。
10. 作为贡献者，我希望同一预览条目重复提交不重复入库，网络结果不明时能够重新核对。
11. 作为成员，我希望导入的新资料沿用既有共享、待核对、历史及共同编辑流程。
12. 作为资料维护者，我希望后来修改与历史恢复继续保留交换依据、出版字段和署名责任。
13. 作为阅读者，我希望从详情和可读内容包查看该条原始题录与导入时间、文件名等出处信息。
14. 作为使用者，我希望导出当前明确选中的资料，权限已变化或类型不适用时得到明确提示。
15. 作为使用者，我希望导出的多语题名、署名、日期精度、卷期页码和标识符在其他解析器中可读。
16. 作为维护者，我希望完整备份恢复后仍能查看、修改和导出这些资料，而无需重新导入原文件。

## Implementation Decisions

### 格式与映射

- 一种格式：RIS，接受 UTF-8／UTF-8 BOM、LF／CRLF。每文件至多 1 MiB、100 条，单条及字段沿用现有长度限制；超限明确拒绝，不截断后冒充完整。
- 首版接收 `JOUR`（期刊文章）、`RPRT`（外部报告）、`WEB`（网页），兼容旧 `ELEC`，以及 `GEN`（一般外部资料）。WEB／ELEC／GEN 暂存为“其他”，显示原类型并允许人工选择受支持的外部资料类别；绝不自动转成个人报告。其他类型逐条标明未支持并允许跳过。
- 支持题名 `TI/T1`、有序重复署名 `AU/A1`、刊名 `JF/JO/T2`、日期 `PY/Y1/DA`、卷 `VL`、期 `IS`、起止页 `SP/EP`、ISSN `SN`、DOI `DO`、网址 `UR`、摘要 `AB/N2`、关键词 `KW`、语种 `LA`。别名优先级固定并记录冲突警告；重复署名不按逗号拆人。年份／年月不补造具体日期，不能解析的日期保留原值并要求核对。
- 页码可为页段或文章编号；多 ISSN 保留。期刊字段与机构／期刊身份分别表达，出版商、作者地址、主题词不自动成为主办、任职或研究对象国。
- 未映射字段、重复字段、原始顺序及每条原文保留在该条交换依据中；页面明确哪些未进入可编辑字段。原文件整体不存入共享记录，避免把跳过或其他范围的条目一起公开；保存每条原文、文件名（不含本机路径）、文件摘要和条目序号，说明保留范围。
- 交换文件是题录，不下载附件、不执行其中的 URL、不调用翻译接口、不将 HTML 当作可执行内容。原始文件路径和附件标签只作为不可执行的原始依据展示。

### 预览、核对与保存

- 从资料库既有整理入口进入，上传前明确支持范围；预览不写入正式资料。格式错误可以定位到条目；结构无法可靠分段时拒绝文件并说明原因。完整有效条目仍可逐条处理，不能把损坏片段静默吞掉。
- 每条独立核对、保存或跳过，复用当前录入表单、来源选择及身份核对能力。保存成功后在队列留下编号与状态；失败保留输入，未处理项不自动保存。不提供覆盖已有资料或自动合并。
- DOI／规范化网址检查当前可读资料；题名匹配只作疑似线索，不自动合并。文件内部重复也显示。实际保存在同一写事务中复查 DOI、网址和预览条目是否已提交；不可读重复只返回通用冲突，不暴露其题名、编号或人物等细节。
- 原始依据由服务端签名并绑定当前成员，保存时验证；客户端不能伪造原始依据。重复提交同一条目不得新建第二份，成员可以重查结果或按提示核对。字段、关系和历史同时成功或整条回滚。
- 原始署名默认待确认；只有显式选择身份并填写依据才沿用现有确认流程。来源手动选择已有档案，不自动创建人物、机构、期刊、任职、主办或研究对象关系。
- 账号切换、关闭预览、替换文件和迟到响应互相隔离；队列中的编辑与已保存状态不因另一个条目保存而丢失。关闭未保存内容前沿用草稿／离开保护，恢复时检查所属账号及已保存状态，防止恢复旧状态重导入。
- 新资料沿用现有可见范围与 pending 状态；正式编辑、历史恢复、可读导出及完整备份保留本条交换依据。整文件哈希只用于辨认输入一致性，不证明题录真实。

### 选中导出

- 复用资料库明确选择，1—100 条；在同一读取快照核查每条当前可见性和有效状态。失效、不可读或不支持的选中项使整次请求失败并保留选择，不静默遗漏。
- 当前期刊文章导出 JOUR，外部报告导出 RPRT；仍保持“其他”的已导入网页可导出 WEB，其余可支持的一般外部资料用 GEN。个人成果、研究笔记、摘录、目录译稿不在本轮 RIS 导出范围，仍用既有内容包。
- 导出当前可维护题录，UTF-8、规范标签与 CRLF，重复作者逐项表达；未拆分的署名不猜姓名边界，保留其原文。当前原始署名与结构化署名不一致时不得沿用过期作者列表。
- 页段、文章编号、中文与变音符、部分日期、缺项均有明确往返样本；不丢弃原语题名或用机器译文覆盖它。已采用的中文与其他原始映射外内容继续由内容包保全，标准输出说明覆盖范围。
- 不直接回放整段旧 RIS，也不将任意未知标签、内部路径、成员身份、权限或历史快照写入标准题录。无法用本轮标准字段表达的内容留在交换依据／内容包中，不能宣称 RIS 无损替代完整备份。

## Testing Decisions

- 沿用公开 HTTP 边界做 red→green，真实临时 SQLite 与合成文件；不读取、导入或写入真实研究库、ThinkTank。
- 固定独立期望：多语多作者、机构署名、跨年／月份精度、卷期页段／文章号、多 ISSN、重复标签、别名冲突、未知标签及未支持类型；原始输入与预期值各自固定。
- 检查未登录／停用账号／CSRF、签名篡改与跨账号重放、不可见重复、预览后新增重复、URL／无 DOI 重试、末尾写入失败回滚、历史恢复及新目录完整恢复。
- 浏览器实际验证 1366px 与 390px：选文件、错误定位、改字段、身份候选、重复核对、保存后接续、失败与草稿保全、切换账号／文件后的迟到响应、选中下载。主动走完整流程并查看布局。
- 输出交给与应用实现独立的 RIS 解析器（拟采用固定版本 rispy）读取，并逐字段比对固定样本；再在另一临时库导入和读取。单纯使用平台自己的 parser／writer 往返不算外部独立验证。
- 全部集成后运行完整合成检查；独立 Standards 与 Spec 对同一基线／提交只读审查，发现统一由一个修复代理处理并复核。CI 只报告相应最终提交实际完成的结果。
- 这轮验收证明软件及合成题录映射，不证明任意网站方言兼容、材料真实、专业译文质量或真人跨人研究复用。

## Out of Scope

- BibTeX、CSL 等第二种格式，所有 RIS 类型及任意供应方的全部扩展。
- 持续网站采集、全文／附件下载、自动翻译、自动创建或确认人物身份、批量覆盖／合并已有记录。
- 参考文献排版、个人成果标准交换、整个文件的共享保全、真实数据库批量改写或本机服务升级。

## Further Notes

按两个纵向任务交付：先完成文件预览、逐条核对保存与证据读取；再依赖其稳定映射与证据接口，完成选中导出、独立解析与跨库复用。技术与验证边界沿用本轮授权，未扩大产品规则。工作分支由独立 merger 集成，任务记录保留同步 SHA、提交和验证证据。

格式依据为 [Clarivate RIS Direct Export 说明](https://support.clarivate.com/Endnote/s/article/EndNote-Directions-for-implementing-EndNote-Direct-Export?language=en_US)，独立工具参考 [rispy 官方仓库](https://github.com/MrTango/rispy)。供应方方言差异通过限定范围、警告和原始条目保全处理，不以支持 RIS 名称推定全格式兼容。
