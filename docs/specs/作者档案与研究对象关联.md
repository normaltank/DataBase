## 1. 问题

以下记录 2026-10-23 规格制定时的问题背景，当前实现状态见顶部及验收记录。

目前原文作者主要以整段署名文字保存在资料中。研究员无法稳定地进入同一人的档案、汇集其作品与研究笔记，也无法可靠地区分同名者、不同姓名写法及机构署名。平台个人成果已有的负责作者账号解决的是内容维护责任，不能用来代替外部人物身份。

机构和期刊已有独立身份，作品与研究内容已有若干关联，但发表出处、文章署名单位和现实任职关系仍需分清。已有来源／资料合并保留历史，并不具备本轮要求的人物误合并拆回能力。

这些缺口影响未来定性研究和分维度影响力评价的数据可信度。本轮先建立能实际维护和使用的人物档案、作品关系及笔记研究对象关系。

## 2. 方案

提供中心内部使用的人物 Wiki：成员可以先建立作者档案，维护头像、姓名写法、带出处介绍和机构经历；依据原始署名及核实线索关联作品；从档案阅读相关作品、记录研究笔记，并返回其依据。

公共档案共同维护，独立研究笔记继续遵循作者授权。人物、机构、期刊作为笔记研究对象连接同一份笔记；作品引用、发表归属和研究对象关联保持各自含义。机构署名复用机构档案。

首版同时提供人工确认后的重复人物合并、作品归属纠错和误并拆回，保留历史、后续新增内容及原有研究依据。独立身份、可追溯关系和内容版本作为以后研究评价、中文阅读与翻译服务的衔接基础。

## 3. 用户场景

1. **U01** 作为研究员，我希望从作者目录或资料页进入人物 Wiki，以便持续了解同一位作者。
2. **U02** 作为研究员，我希望用原名、中文名或其他已登记写法找到作者，以便跨语言查找同一人。
3. **U03** 作为研究员，我希望在尚未收录作品时先建立档案，以便开始积累研究对象的信息。
4. **U04** 作为贡献成员，我希望维护姓名、头像、介绍与参考出处，以便同事能辨认档案中的人物。
5. **U05** 作为贡献成员，我希望用标题、段落、列表、表格和链接整理介绍，以便直接在网页里维护人物 Wiki。
6. **U06** 作为阅读者，我希望没有头像或某项信息时页面仍然清楚可用，以便理解哪些信息已经知道。
7. **U07** 作为共编成员，我希望同时保存发生冲突时保留我的输入，以便比较新版本后继续处理。
8. **U08** 作为共编成员，我希望查到修改人、依据和历史版本，并纠正误改，以便持续维护可信档案。
9. **U09** 作为研究员，我希望从作品署名关联一个已核实的人物，以便档案中的作品归属有依据。
10. **U10** 作为研究员，我希望保留完整原始署名和署名顺序，以便随时回看作品发表时的事实。
11. **U11** 作为研究员，我希望证据不足的署名可以保持待确认，以免为了补齐档案而误认作者。
12. **U12** 作为研究员，我希望同名者可以保持不同档案，以免把他们的作品和研究积累混在一起。
13. **U13** 作为研究员，我希望有依据的不同姓名写法能关联同一人，以便汇集其作品。
14. **U14** 作为研究员，我希望多位个人或机构共同署名时分别登记其身份，以便保留合作作品的作者构成。
15. **U15** 作为研究员，我希望机构作为署名作者时进入原有机构档案，以便区分机构作者与作品发布方。
16. **U16** 作为研究员，我希望记录作者在某篇作品上的署名单位，以便理解发表当时的信息。
17. **U17** 作为研究员，我希望分别记录任职机构、角色、时间与出处，以便理解人物经历及其变化。
18. **U18** 作为研究员，我希望一个人可同时关联多家任职机构，未知时间可以留缺，以便如实保存材料。
19. **U19** 作为研究员，我希望作者换机构后旧作品的署名信息保持原样，以便研究历史变化。
20. **U20** 作为研究员，我希望从人物档案创建关于此人的研究笔记，以便直接积累研究发现。
21. **U21** 作为笔记负责作者，我希望把已有笔记明确关联到多个作者、机构或期刊，以便复用比较研究。
22. **U22** 作为阅读者，我希望在各对象档案看到同一份相关笔记，以便通过不同入口访问相同内容。
23. **U23** 作为笔记负责作者，我希望移除一个研究对象关联时保留笔记本身，以便调整研究范围。
24. **U24** 作为笔记负责作者，我希望公共档案共编不会扩大他人对笔记的编辑权限，以便保留内容责任。
25. **U25** 作为阅读者，我希望档案、搜索、历史和数量只呈现我有权访问的资料，以便保持既有共享边界。
26. **U26** 作为共编成员，我希望确认同一人的重复档案时先看到依据和影响，再合并，以便避免错误整理。
27. **U27** 作为阅读者，我希望合并后旧档案入口仍能说明去向，以便旧链接继续可用。
28. **U28** 作为共编成员，我希望能纠正作品归属和拆回误合并，以便修复身份错误。
29. **U29** 作为共编成员，我希望拆回时保留合并后的新增内容，并处理归属不明项，以免纠错造成新的丢失。
30. **U30** 作为研究成果作者，我希望身份更正可以查见，而已有正文及原有引用依据保持原样，以便自行判断是否修订结论。
31. **U31** 作为维护人员，我希望升级前可备份、旧署名保持原样，重复启动不会重复建档，以便平稳接续原有资料。
32. **U32** 作为研究员，我希望导出可阅读的档案及有权访问的关联内容，以便继续利用已整理的资料。
33. **U33** 作为维护人员，我希望完整备份能恢复头像、档案、关系、历史及合并纠错状态，以便恢复后的平台仍可继续工作。
34. **U34** 作为研究员，我希望电脑及窄屏页面都保持简洁、学术和易读，以便日常使用。
35. **U35** 作为后续建设者，我希望研究评价与译文可以关联同一人物和已有内容版本，以便扩展时沿用这些积累。

## 4. 实施决定

以下为建设方在已确认业务范围内选定的实现边界；具体函数、表名和路由由建设 Agent 决定。沿用现有本地应用、关系数据库、成员会话、正文编辑及修订机制。

### 4.1 对象与模块边界

| 能力 | 应保存的业务信息 | 边界 |
| --- | --- | --- |
| 人物档案 | 稳定身份、显示姓名、原名／中文名／其他写法、介绍、出处、头像引用、版本与修改责任 | 人物身份与登录账号分开；姓名不作为唯一身份键 |
| 作品署名关联 | 作品、原始署名片段及顺序、个人或机构身份、确认情况、依据、确认人及修订 | 保留原始整段署名；关系更正不覆盖原文或登录账号字段 |
| 文章署名单位 | 某位署名作者在某篇作品中标注的机构及出处 | 属于该篇作品的发表信息，不能代替任职经历 |
| 作者任职经历 | 人物、机构、角色、已知时间精度与时段、依据及修订 | 允许多机构和未知起止时间，不猜补日期 |
| 笔记研究对象 | 同一笔记明确关联的作者、机构或期刊 | 复用现有笔记；与原文引用及来源展示关系分别表达 |
| 身份整理记录 | 合并前身份与关联、影响范围、后续变化、操作人、依据、合并／拆回事件 | 合并与拆回是专门的身份操作，普通正文恢复不代替它们 |

人物模块提供查询与身份维护；作品署名、任职及研究对象关联使用明确的关系接口；身份整理统一处理合并、拆回和旧入口解析。各模块复用现有权限与版本服务，避免把人物资料塞入原文署名字段或另造一套笔记正文。

### 4.2 页面与编辑

- 提供独立作者目录及可直接打开的档案详情；姓名搜索覆盖原名、中文名和已登记别名。同名结果显示各自介绍或机构线索供辨认，不合并搜索结果身份。
- 资料页的已确认个人署名可进入人物 Wiki，已确认机构署名可进入机构档案；尚未确认的署名如实展示，并提供有权限时的关联维护入口。
- 人物 Wiki 包含基本身份、头像、可分节编辑的介绍、任职经历、已确认作品、研究笔记及历史入口。可先建档后补作品；空列表与信息留缺清楚呈现，不能解释为无成果或低影响。
- 介绍复用现有网页编辑能力，支持标题、段落、列表、表格和链接，保存和呈现沿用正文安全处理。资料事实说明与研究员独立判断保持清楚区分。
- 头像先支持成员手动上传 JPEG、PNG、WebP，可替换或移除；没有头像使用中性占位。记录来源链接或来源说明，上传时验证真实文件类型及大小，首版单张上限 5 MiB；类型不符或超限时明确提示并保留其他输入。
- 头像作为受控文件纳入权限、版本引用和备份。仅被历史版本引用的头像仍需保留；不因替换当前头像而破坏旧版本。
- 沿用蓝、白、柔黄配色和简洁学术风格；必要的依据、待确认状态和纠错说明保留，避免宣传标语、堆叠小字和无意义的空字段。桌面与 390px 宽度均需可读可操作。

### 4.3 维护权限

| 操作 | 首版权限 |
| --- | --- |
| 新建／编辑公共人物档案、维护任职信息 | 有效中心成员可执行，记录责任与版本 |
| 维护作品署名的身份关联 | 对成员可见的原始资料开放公共关系维护；不因此取得原始正文、题名或其他受控字段的修改权限 |
| 编辑研究笔记正文及其明确选择的研究对象 | 沿用笔记负责作者及授权同事权限 |
| 从人物或来源档案读取作品、笔记、历史及导出 | 逐条沿用现有可见权限；隐藏内容的标题、摘要、数量和链接不得通过汇集入口泄露 |
| 人物身份合并、作品归属纠正及误并拆回 | 有效成员核实依据并确认影响后执行；身份解析变化不授予其修改私人研究正文的权限 |
| 完整备份与恢复 | 沿用现有管理权限和恢复到新目录的操作边界 |

公共档案可共编不表示关联笔记也变成全员可改。历史恢复继续使用当前权限，不能恢复旧授权以扩大访问。

### 4.4 作品归属与机构署名

- 新结构增量连接已有作品，原始整段署名和资料编号保留。初次升级不自动将所有署名拆为人物，也不把提交者或个人成果负责作者映射为原文作者。
- 同一作品允许多位个人、机构或二者共同署名，分别保留位置和原始写法。原始姓名相同不触发自动身份合并；候选提示只辅助查找。
- 确认或纠正关联需要可追溯的依据，至少能定位到作者主页、机构介绍、作品署名或其他具体材料；只有姓名相同不构成确认依据。
- 不确定署名保留待确认状态，不计入已确认人物作品。已经误认时可改到正确人物／机构，或退回待确认；纠正前后身份与依据可查。
- 机构署名引用原有机构身份；作者身份、作品发布机构和所属期刊分别表达。不得自动由发布关系、相同域名或机构主办期刊推定作者身份或任职。
- 作品关系的公共维护与原始资料正文修改分开检查权限。界面与服务端均保持这条边界。

### 4.5 任职及文章署名单位

- 任职关系记录已有机构、角色、依据以及已知的起止时间；支持只有年份、部分时段或完全未知，不将未知填成当前日期。
- 可同时记录多家机构及多个时期；不要求指定唯一现任单位。机构名称与已有机构身份关联，避免为同一机构另建人物侧副本。
- 文章署名单位按作品中的具体作者记录，可有多家；当前任职更新不批量改写旧作品署名单位。
- 从机构详情能查到有依据的关联人物及关系说明；作品发布、作者任职、机构署名作品分别展示。

### 4.6 研究笔记关联

- 从人物 Wiki 新建笔记时预选该人物为笔记研究对象；仍走现有笔记创建、负责作者确认、编辑授权和可见范围流程。
- 已有笔记由有编辑权限的人关联一个或多个作者、机构或期刊。各档案引用同一份笔记，不复制正文；移除关系不删除笔记。
- 作者、机构和期刊详情分别汇集其明确关联的笔记。笔记引用某篇作品不会自动创建人物研究对象关联，也不会自动把资料的发布来源列为研究对象。
- 身份更正需要提醒研究人员重新判断时，以可追溯身份说明呈现；不自动重写笔记结论、报告正文或固定的引用快照。

### 4.7 人物合并、纠错与拆回

1. **先比较再确认。** 仅合并已经核实属于同一人的人物档案。比较页显示姓名、依据、信息冲突及当前成员有权查看的受影响作品和研究关联；明确选择保留的当前介绍／头像等信息。其他内容继续保留在可追溯历史中，不能静默丢弃。
2. **保护身份引用。** 保留原有稳定编号、合并前的身份归属与关系来历。旧入口说明合并去向；引用原编号的资料和研究内容继续可访问。不得直接套用不可拆回的旧来源合并流程。
3. **提交时重新检查。** 合并或拆回预览后，任一参与档案、受影响关系或相关身份事件发生变化，提交必须提示重新比较；不得用过期预览覆盖新修改。合并和拆回各自在一次事务中完成，失败时不留下半套关系，重复提交不重复执行。
4. **纠正单条归属。** 允许成员把误认作品改为正确身份或待确认，记录原因、依据、修改人及前后值。人物与机构档案中的作品列表同步反映当前归属，原始署名保留。
5. **拆回保留后续工作。** 拆回前展示原合并、此后新增或修改的内容及关系。仅因这次合并而转接、此后未被单独调整的关系可按来历恢复；合并后已明确纠正的归属、已移除的关系和独立编辑必须保留，旧快照不能将其覆盖或复活。后续新增或语义不明的关系由有权人员明确分配，或保留内容并标待确认，不能随意全部塞回某一人。
6. **研究作者责任保持。** 拆回或合并可以改变当前身份解析和纠错提示，但不得改写个人笔记／报告正文、既有作者授权或固定引用依据。涉及笔记研究对象的语义重选由有编辑权的人确认；无权修改者不能借身份操作代改判断。
7. **可处理连续合并。** 后续合并形成依赖时，提示并支持先拆回依赖的后续合并，再处理较早一次；禁止循环、自合并及把人物与机构混合为同一身份。拆回能力不能只在“合并后没有任何修改”时有效。
8. **审计与可见范围。** 合并、拆回、关系纠正和待确认事项均保留可追溯事件。预览、历史和提示按权限过滤；系统保全所有关系，不能因执行者看不到某条私人笔记而丢弃该关系，也不能显示隐藏笔记的名称或数量。

笔记研究对象的待确认状态属于身份纠错信息，只标记受此次身份拆回影响且归属不明的关系。原笔记、原有目标及其来历继续保存；对有权阅读该笔记的人显示“研究对象待复核”及相关身份更正说明，不把这条待确认关联计入有关人物的已确认研究笔记，也不自动替换为另一研究对象。笔记其他已确认的人物、机构或期刊关联继续有效。笔记作者或授权同事可以确认原对象、改选对象或移除关联；在其处理前，正文和固定引用依据继续保持。其他成员可以完成公共身份拆回，不必等待其无权修改的私人笔记被重新指定。

### 4.8 操作契约与版本保护

- 查询返回稳定对象标识、当前版本、当前成员可用操作和可见的关联内容。列表筛选、分页及搜索沿用现有交互习惯，数量基于可见范围。
- 保存基本信息、头像、任职、署名及研究对象关联时，携带所依据的版本。关系修改也参与并发检查，不能只检查人物介绍的版本。
- 新建、更新、历史读取／恢复、关联维护、身份比较、合并和拆回分别具有明确操作边界。身份整理返回可追溯操作结果，重复提交不得创建重复合并或重复关系。
- 参数无效、无编辑权、内容不可见和版本冲突沿用现有接口约定；冲突保持明确的冲突响应及前端保稿行为。任何失败均不得显示为成功。
- 对象身份、关系类型、证据及版本在页面之外也可通过应用接口读写，后续评价和译文可引用同一身份及内容版本。当前接口服务本轮真实操作，不提前冻结外部翻译供应商或评价算法。
- 不新增外部网络调用作为保存、查询或身份确认的必要步骤；可核实外部标识可以记录，但不因此自动认定不同记录属于同一人。

### 4.9 迁移、导出及完整恢复

- 增量升级前沿用已有备份流程，保留旧资料编号、原始署名、附件、修订、专题和成果引用。新结构初始化可重复执行，不自动确认或合并真实人物。
- 原有资料在未补齐人物关联前仍能阅读、搜索和使用；旧界面入口和正文权限继续有效。人物初始数据以小批有据样本逐步登记，试点源目录保持只读。
- 现有来源／资料合并、来源类型更正及历史恢复须认识新增关系：保全人物署名、任职及笔记研究对象的引用，并检查目标类型仍然适用。遇到类型冲突应说明并阻止不安全变更，不能静默遗失关系；这里只补本轮新增关系所需的兼容行为。
- 可读导出包括人物介绍、姓名写法、任职依据、当前及历史身份线索，以及当前成员有权访问的作品和笔记研究对象关系；头像能够随导出保留或明确说明取得方式。导出不改变原有分享范围。
- 完整备份包含新对象、所有关联、身份事件、历史版本和当前／历史头像文件；恢复工具同步支持新数据版本及文件清单验证。不能出现“库能恢复但头像或拆回依据丢失”的结果。
- 完整恢复仍先进入新目录，验证数据库、文件及身份关系可继续使用；包括恢复合并状态后仍能拆回。旧版备份继续可由升级后的应用读取和增量迁移。

## 5. 验证与验收

### 5.1 验证入口

主要自动验证入口沿用现有应用的 HTTP 请求／响应边界，使用真实的临时数据库和受控文件，通过多个成员会话执行完整业务操作。重点检查用户能够观察的结果、权限和历史，不以私有函数结构、表名或界面文案逐字匹配作为通过依据。

已有工作流程验证提供共编、负责作者授权、关系维护、版本冲突、引用快照及合并的先例；阅读验证提供受限内容过滤和固定引用的先例。新人物能力在这些边界上补充场景。备份恢复另从现有完整备份及恢复入口验证，恢复后再通过相同应用接口读取和继续编辑。

页面验收覆盖真实点击、编辑保稿、图像显示、关系选择和跨页返回；以桌面和 390px 窄屏验证实际可用性。数据库迁移在隔离的旧版数据副本验证，真实数据导入与人物确认按后续明确派工范围执行。

## 6. 本轮范围之外

- 正式影响力指标、综合评分、自动生成研究结论、完整外部引文或合作网络分析。
- 自动抓取人物资料、头像或外部学术标识；按姓名批量建档、自动身份合并及真实库的未核实批量迁移。
- 翻译供应商接入、批量机器翻译、完整原译版本工作台；保留中文为主、原文与译文并存的长期方向。
- 实时多人同步输入、外网部署、公开人物网站或对外开放账号。
- 通用机构／资料合并全面改造及任意拆分工具。本轮人物误并拆回是必需能力，不因该边界被省略。
- 与本轮使用流程无关的技术栈更换、空的分析接口和复杂任务基础设施。
