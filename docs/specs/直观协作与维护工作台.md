# 直观协作与维护工作台

版本：1.0；日期：2026-11-09。状态：已按用户授权冻结，待施工与独立验收。

唯一任务台账：[父任务 #134](https://github.com/normaltank/DataBase/issues/134)。本文为本轮行为与验收的唯一维护稿；固定版本发布、子任务、施工进度和最终交付由父任务关联记录，本次冻结不表示功能已经实现、验收或部署。

依据：[PRODUCT](../../PRODUCT.md)、[术语表](../../GLOSSARY.md)、[现行设计语言](../../DESIGN.md)、[两阶段材料交接规格](两阶段材料交接与研究界面简化.md)及[AI 自主维护与反馈纠错规格](AI自主维护与反馈纠错.md)。用户已授权既定业务内适用方案直接施工；本版采用已经明确的公开 HTTP 与真实合成浏览器验证边界，不重复征询授权。

## Problem Statement

研究员已有材料原件、版本和逐版审阅，却需要展开多段历史才能找到“谁提交了哪版、负责人针对哪版说了什么”。当前版与旧版、同一人的多份材料容易混读，上传或审阅时的输入也不能因切换阅读而丢失。需要的是节点、原件和责任对应的可操作沿革，而非给原列表换颜色。

维护员已有任务、步骤、实际取得材料与正式变更记录，但每约5秒读取最多100份完整任务及证据，再重绘整个列表，阅读中的内层展开、焦点和位置会丢。研究员的对象反馈已有处理结果，却缺少同样直观的“点一步，查看当时材料和修改前后”联读。缺口是摘要与详情分离、真实步骤到证据的联动，以及刷新时保持阅读上下文。

## Solution

首批交付两条完整路径，沿用现有对象、权限、业务动作与蓝白灰／淡金工作台。

- **A：研究员材料沿革。** 在现有两阶段主题材料中选择一份材料，桌面显示“成员提交／负责人审阅”双责任轨道及对应连线。点击真实版本或审阅节点，固定详情区联动该版原件、说明、责任人、日期、适用意见和审阅附件，并能回到当前版。手机和放大模式提供等价的顺序入口及版本选择。
- **B：维护工作台与处理轨迹。** 维护员先看轻量近期任务清单与真实状态，按该窗口状态筛选；选择任务后按需读取详情，点击实际步骤联读动作、出处与真实修改前后值，并能打开当前对象。研究员“指出问题”的对象处理记录复用同一联读能力，保持研究与管理权限分流。后台更新只改动变化部分，保持用户正在读和输入的内容。

## User Stories

1. 作为研究员，我希望按稳定身份选择一份材料及其版本，以便同一人的多份材料各自接续、互不混淆。
2. 作为研究员，我希望看到成员提交与负责人审阅的两条责任轨道及对应连线，以便理解谁在何时对哪版作出决定。
3. 作为研究员，我希望点击历史版本后固定详情区显示那一版原件、说明、提交人和时间，以便核对当时实际交付。
4. 作为研究员，我希望点击审阅节点后看到针对该版的意见和审阅附件，并仍辨认原件身份，以便准确接续修改。
5. 作为研究员，我希望一键回到当前版并看清其真实状态，以便旧版通过不会误导我认为新版本也已通过。
6. 作为研究员，我希望没有审阅的版本如实写待审，缺失的历史字段保留未知，以便区分实际记录与尚未发生的事。
7. 作为旧材料作者，我希望接续旧材料时仍保留其原身份、署名及真实历史，以便新界面不会改造我的旧会议、分工或采用关系。
8. 作为提交者或负责人，我希望阅读历史时文件和文字输入保留、写入目标明确，以便选择旧节点不会悄然改变正在提交或审阅的对象。
9. 作为提交者或负责人，我希望失权、闭期、过期令牌、保存失败或冲突时得到准确提示并保留文件和输入，以便重读状态后接续处理。
10. 作为键盘、手机或放大模式使用者，我希望用完整文字、可聚焦入口和足够大的目标完成版本选择及回当前版，以便不依赖颜色、悬停或精细拖动。
11. 作为维护员，我希望先读取轻量任务摘要和真实运行原因，以便快速定位异常而不反复下载全部证据。
12. 作为维护员，我希望知道近期窗口的范围和是否还有更多有权任务，并按窗口内状态筛选，以便不会将窗口数量误认为全库总量。
13. 作为维护员，我希望选择任务后查看其实际步骤，并点击一步联动动作详情、材料出处及真实修改，以便独立复核处理过程。
14. 作为维护员，我希望每项字段或关系变更显示适用的原值、新值及对象入口，以便把当时修改与当前档案对应起来。
15. 作为维护员，我希望无步骤队列、等待、错误、未完成、无变更完成及未知费用分别如实表达，以便“已执行”不会被误读为成功或人工已核对。
16. 作为维护员，我希望刷新保留选中任务、步骤、内层证据展开、滚动和焦点，新步骤只提示到来，以便阅读不被后台进展打断。
17. 作为维护员，我希望读取失败时保留最后可读内容、看到未更新提示和手动刷新入口，以便恢复网络后继续检查。
18. 作为研究员，我希望从可读对象的“指出问题”处理记录进入同样的步骤和变更联读，以便知道反馈依据什么处理、实际改了什么。
19. 作为研究员，我希望普通 AI 关系立即参与查找与使用，人工核对另行表达，以便反馈查看不会重新变成逐项人工采用。
20. 作为研究员，我希望看到自己的有权处理结果而不出现管理员费用和配置，以便日常反馈与维护管理保持各自用途。
21. 作为切换账号或失去对象权限的成员，我希望旧请求和旧缓存停止展示，以便不会读到上一身份或已失权对象的材料。
22. 作为不支持新增浏览器动画能力或偏好减少动态效果的成员，我希望仍能完成同一组操作，以便视觉增强不成为使用前提。

## Implementation Decisions

### A. 两阶段主题材料的选择与责任联动

- **身份与系列。** 复用现有材料稳定 `ref`、各版本 `ref` 和该版实际 `reviews`。不同材料系列分别呈现，阶段查看不改变业务阶段。旧材料的 `legacy`、`source_ref` 保留真实接续含义；本轮不迁移 schema、不把旧流程补造成新提交或审阅。
- **节点与详情。** 桌面提供真正可点击的提交／审阅双责任轨道。节点有版本、操作者、日期与状态文字；审阅连向其实际版本，选择时突出相应节点、连线和责任区，详情身份、原件预览／下载目标、意见及附件同步对应。日期相同按稳定顺序展示，不编造时间精度。无审阅仅显示待审文字，不产生虚拟审阅节点。
- **当前与历史。** 默认明确当前版及其真实状态；可查看历史并回当前版。旧版通过不向新版本传播。历史原件不可用、意见为空或字段缺失按实际结果表示，仍提供适用的原件下载与恢复读取入口。历史选择只用于阅读，不能构成更新、恢复、发布或其他写操作。
- **写入与保稿。** 上传及审阅继续使用原有真实接口、权限、令牌、版本冲突和幂等语义。当前可执行动作与适用版本保持明显；展开表单时明确绑定其材料／版本，切换历史选择不改变这个目标。选择节点只更新阅读区，不重建正在输入的上传／审阅表单或文件输入；权限与业务状态变化仍须由服务端判定。失败和冲突保留文件及输入，不借新身份继续旧写入。
- **手机与放大。** 窄屏及浏览器原生200%缩放改为有文字的事件顺序入口与稳定单一详情区，提供版本选择及回当前版；所有触控入口至少44px。无需精细拖动或横向追逐节点。键盘可聚焦并选择节点，选中态有合适的可访问语义，焦点不被阅读切换或刷新夺走。仅把内容改成彩色有序列表不满足桌面联动要求。

### B. 有权近期摘要与选中任务详情

- **兼容接口。** 为任务列表增加轻量 summary 模式或独立摘要端点，具体命名由施工者决定；旧列表 API 默认表示与现有调用保持兼容。选中任务继续使用已有受权 `GET /api/maintenance/jobs/<jid>` 详情接口。对象反馈继续使用现有提交、对象处理历史与详情接口，不更换任务框架。
- **摘要投影。** 摘要由数据库读取／聚合必要元数据生成，按当前身份检查目标及依赖材料权限；不能先构造完整任务再删除字段，也不能为摘要读取完整证据文本。返回适用的稳定身份、题名、实际状态、原因、时间及可可靠取得的步骤数或末步摘要等轻量字段。摘要不含完整 `arguments`、`results`、AI 上下文或证据全文；没有可靠数据的计数留缺，不为展示强造字段或全库统计。
- **窗口语义。** 按当前权限形成有权近期窗口，建议上限100。返回并展示窗口定义、实际加载范围与 `has_more`，后者针对是否还有该用户有权任务；不能仅先截取全局100行后过滤而声称已经覆盖用户的近期窗口。若用游标，排序、权限和后续读取语义须一致。筛选明确作用于当前近期窗口；结果长度、分状态数与近期变化均不冒充全库总量，0、未知与未加载分开。
- **真实轨迹。** 选中任务后呈现其实际步骤的有序轨迹与固定细节区；选择稳定 `step.id` 后同时标明动作、结果、该步实际材料及修改。步骤与证据、对象间只使用显式 ID 或实际记录中的关联，不从邻近时间或名字猜配。可选择证据反向定位其对应步骤；若没有对应材料或修改，清楚显示实际缺口。节点与细节需要真实联动，不能只是静态图或长 JSON 改色。
- **变更与当前对象。** 依据实际 `changes` 展示中文可读的字段／关系名称、`before/after`、对象身份及已有出处。长值按需展开，历史值与当前对象入口分别标明；打开当前对象不偷换历史依据。关系类型与稳定目标身份继续区分，原始署名与引用版本保留。不从上传说明推断 Word 正文差异，不把原始 HTML 当可执行内容。
- **状态含义。** 展示真实队列、步骤状态、错误和完成理由；未完成、等待与费用未知沿实际 reason 表达。工具已执行不保证结果成功，`finish` 不等于每项字段补齐，无变更完成仍可成立。维护轨迹不画固定必经阶段、虚假百分比、ETA、吞吐、流量或健康分。AI 正常写入即时正式生效，人工核对独立显示，沿用当前业务规则。
- **研究员复用。** 对象“指出问题”的每条反馈记录复用步骤、材料和前后值联读；重复提交、丢失响应与重试沿现有幂等和输入保留边界。研究员入口只展示其有权对象的处理信息，不出现管理员费用明细或配置；不新增人工采用关卡。缺少持久化显式接续 ID 时，新旧反馈按记录查看，不画反馈接续因果线。

### 刷新、异步与渐进增强

- 摘要轮询只更新变化的行、状态和运行信息；选中详情可按需重读，内容未变时保持原 DOM。按稳定身份保留选中 job／step、内层证据展开、滚动位置和焦点；新增步骤不抢选、不自动滚到末尾。正在填写的查找、反馈、上传或审阅表单不因状态刷新重建。
- 每条轮询链保持单次请求在途，避免定时积压；手动刷新与自动刷新协调。校验身份、所在页、请求代次与选择代次；迟到响应不覆盖新选择或新身份。离页、换账号停止旧读取并清理身份相关状态。
- 对象或依赖材料失权时清空相应缓存与详情，停止展示；任务仅因筛选／近期窗口变化而暂不在清单时，可保留经重新鉴权仍可读的选中详情并说明范围。读取失败保留此前有权内容，标明状态未更新和最后成功更新时间，提供手动刷新；明确失权响应优先于保留内容。
- 采用原生 HTML、SVG／CSS 即可实现两条路径，不增加第三方依赖或更换技术栈。局部短动效可在 View Transitions 与 WAAPI 中选适用能力，先检测支持；不支持或 `prefers-reduced-motion` 时直接完成切换。动画不承担权限、保存或加载成功语义，不做全页入场或强制位移。
- 桌面保持清单、轨迹与内容对应；窄屏采用可读顺序。所有动作有键盘及文字等价入口，状态不只靠颜色。现行字号、导航与焦点规则沿用 DESIGN；施工完成后据实际行为更新实现和使用说明。

## Testing Decisions

### 验证边界与先例

沿用已冻结的最高公开边界：合成数据库上的公开 HTTP、真实 JavaScript／DOM 事件和真实浏览器。既有两阶段材料 HTTP／备份恢复用例及维护任务、反馈、前端乱序事件用例是可复用先例；现有事件替身不能代替真实浏览器的文件输入、焦点、滚动或布局验证。测试以独立预置真值核对外部行为，避免复制实现算法后相互证明。

纯文档冻结只做文档检查；以下均是施工与验收必须落实的测试决定，不是本次已执行结果。各施工范围先运行相关检查，全部集成后运行完整必要套件一次；后续只因新改动、失败或未解决风险补跑受影响项。最终结果绑定同一交付 SHA，另做独立 Standards、Spec 及视觉验收。

### A. 材料沿革

1. 通过真实接口建立同一材料 v1退回、v2通过、v3待审，以及同一成员的第二份材料和真实审阅附件；预置每版可区分原件字节、说明、责任人和日期。点旧版、对应意见、新版及回当前版，逐项核对详情、预览和下载的版本 ref／字节，验证系列不串联、v3不继承通过。
2. 验证无审阅版本不出现审阅事件，意见为空仍准确；旧材料的 legacy／source_ref 接续、既有署名、历史与采用关系保持。当前动作与所选历史阅读的身份同时可辨认。
3. 实际选择文件并输入上传／审阅文字后切换节点、切换材料及刷新；文件、输入和明确写入目标保持。分别模拟闭期、成员失权、纯管理员越权、令牌过期、并发版本冲突、保存失败及未知响应重试；拒写准确，不丢稿、不静默覆盖、不重复提交。
4. 真实浏览器在1366、390、320宽度及原生200%缩放完成同一流程；用键盘选择与返回，核44px入口、焦点、文字及当前动作可见。覆盖 reduced-motion 和新增动画 API 不可用的直接切换路径。截图须包括桌面节点连线、选择前后不同详情及窄屏等价入口；额外声称动画连续性须另有短录制或中间帧，性能结论另测。

### B. 维护与反馈联读

1. 真 SQL 合成数据含长证据、完整工具参数／结果、AI 上下文、多种对象与权限依赖。公开摘要响应不含这些全文，读取轨迹／查询观测确认没有先构造 fulljobs 或访问完整证据文本路径；不能仅用响应已删除字段证明轻量。目标或依赖失权均不可见，禁止从计数、`has_more` 或摘要泄漏。
2. 预置超过窗口上限的有权任务，并穿插更多无权任务，验证近期顺序、窗口范围、`has_more`、状态筛选与0／未知语义；窗口外有权数据不被全局先 LIMIT 遗漏。旧 API 默认 full 表示及既有调用保持兼容。
3. 包含无步骤 queued、running、pending步骤、error结果、真实 changed 与 finish、无变更完成、未知费用和未完成原因。逐步点击核对真实动作、该步证据 ID／来源、对象、before/after 及当前对象入口；没有显式关联的不补连线，没有变化的不造差异，错误不一律显示成功。
4. 控制实际响应时序，覆盖定时与手动刷新、延迟和乱序、快速切任务／步骤、切页面、换账号、失权、暂离窗口、断网及恢复。核对单次在途、迟到响应隔离、失权清理与失败保内容。展开内层证据并滚动、聚焦或输入后跨多次刷新，验证位置、焦点、输入、job／step选择保持；新增步不抢选，未变化详情不被重建。
5. 管理员维护入口与研究员对象反馈入口分别实际走通；反馈含重复提交、响应丢失重试、成功提交后读取失败、新旧记录并存。研究员仍可看实际处理材料与变更，不能读管理费用／配置或已失权材料，不画无显式 ID 的接续因果，不恢复人工逐项采用前置。
6. 1366、390、320、原生200%及 reduced-motion 下用键盘和文字入口完成筛选、选任务／步骤、展开材料、查看差异、打开当前对象和刷新恢复，检查无动画仍有完整等价操作。

### 数据与证据隔离
