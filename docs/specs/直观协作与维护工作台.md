# 直观协作与维护工作台

版本：2.0；日期：2026-11-09。状态：依据用户最新“整合成果、完成适配、其他技术可尝试”的指令冻结，待施工与独立验收。

唯一任务台账：[父任务 #134](https://github.com/normaltank/DataBase/issues/134)。本版维护当前行为和验收，子任务、实际提交及交付记录由父任务关联。规格1.0及其局部交付保留为[固定历史版本](https://github.com/normaltank/DataBase/blob/4357b6c6eea25f9fa3dbb110720f629b7376fa4e/docs/specs/直观协作与维护工作台.md)，不再用旧的“原生组件首批／不接Three等库”排除条款限制本轮。

依据：[PRODUCT](../../PRODUCT.md)、[术语表](../../GLOSSARY.md)、[现行设计语言](../../DESIGN.md)、[两阶段材料交接规格](两阶段材料交接与研究界面简化.md)及[自主维护规格](AI自主维护与反馈纠错.md)。项目目前是一个尚未投入使用的本地网站；多个临时原型／预览不是多个需要用户选择的部署环境。整合、适配及启动入口由建设方处理。

## Problem Statement

已有资料发现、主体档案、材料版本、审阅、AI维护步骤和反馈记录，也已有Three国别地球、关系星图、时间透镜的独立交互原型。但原型仍依赖512条合成资料，日常页面只有局部HTML/SVG改进，研究员和维护员不能从同一应用实际使用这些空间交互。技术调研与局部优化不能代替成果接入。

成员需要在保持原件、身份、权限、责任和编辑上下文的前提下，通过有表现力的图形发现资料、理解关系、接续协作和复核维护。视图必须连到同一份现有数据和真实接口，能够点击、筛选、返回和处理失败；不能以另开演示站、iframe样例、安装未调用的库或虚构图表作为完成。

## Solution

沿用蓝白灰／淡金的现有视觉身份，将已有三类空间机制与研究、协作、维护流程接入同一本地应用。

- **国别探索：** 通过日常导航或资料检索首屏可见的入口进入可旋转、缩放和点选的Three地球；选择研究对象国立即进入同一查询的资料结果。紧凑清单与文字国别入口保留。
- **时间探索：** 在同一资料查询中使用ECharts年份概览和明确的区间刷选，并可切换Three时间透镜查看当前有权资料窗口。点击真实资料点打开既有阅读器，日期未知资料独立查阅。
- **主体关系：** 文章阅读中的实际一跳作者、机构、期刊和引用成果关系提供Cytoscape平面图与Three空间图；同一数据模型、对象选择和文字依据联动，链接仍进入原档案／资料。
- **协作与维护：** 将实际版本／审阅和任务／步骤呈为React Flow流程图，按已验证的ELK同源布局路径排布。选节点联动具体原件、意见、动作和依据；长文本实际修改采用diff2html阅读，短字段及结构关系继续清楚表达原值／新值。
- **稳定更新：** 在现有轻量任务摘要和按需详情之上接入鉴权后的ETag条件读取，保留选择、文件、草稿、滚动和焦点。研究员反馈复用有权步骤阅读，维护管理与研究权限仍分流。

## User Stories

1. 作为成员，我希望所有能力属于同一本地应用、同一组身份和数据，以便不用在独立演示页之间猜测哪些功能已接入。
2. 作为研究员，我希望日常页面有首屏可见的空间探索入口，并能返回紧凑清单，以便按任务选择查找方式。
3. 作为研究员，我希望拖转地球并点选国家或代表点后，查询条件和资料结果实际改变，以便从地理线索进入材料。
4. 作为研究员，我希望文字国别控件完成同样的选择、清除与未知值查询，以便小国、无底图或键盘操作仍可用。
5. 作为研究员，我希望图上计数明确属于哪个有权查询范围，并区分资料研究对象与来源所在地，以便不会误读地域或全库覆盖。
6. 作为研究员，我希望发表、首次收录和最近修订三种时间口径明确，并同步作用于选区、清单和网址，以便不会混淆新增与发表。
7. 作为研究员，我希望在年份概览拖选范围后看清起止年并应用／清除，也能用起止年字段完成同样操作，以便不用逐年反复点击。
8. 作为研究员，我希望时间透镜中的每个资料点对应当前有权查询中的真实记录，以便点击后打开正确题名、原件和现有阅读功能。
9. 作为研究员，我希望透镜说明实际加载窗口、完整匹配总量及是否还有更多，以便不会把有限图形窗口当成全部资料。
10. 作为研究员，我希望年份、年月和完整日期保留原精度，未知日期独立查找，以便图形不会编造月份、天数或坐标。
11. 作为研究员，我希望时间刻度与资料点使用同一坐标域，筛选、单年和重置都准确，以便原型的空间效果不会扭曲时间。
12. 作为研究员，我希望点击关系图中的作者、机构、期刊或成果后，文字详情和可用档案入口同步对应，以便查看下一条有据线索。
13. 作为研究员，我希望平面／空间关系图切换时保留同一对象和关系，以便比较遮挡和阅读方式。
14. 作为研究员，我希望关系方向、类型、依据以及AI／人工来历有文字，以便不把共同出现、原始署名或机器关联误当成已核实事实。
15. 作为研究员，我希望从图进入档案或另一篇资料后能回到原查询、页码和阅读位置，以便探索不丢上下文。
16. 作为研究员，我希望没有关系、原始署名未归属或依据缺失时如实显示，以便不被填满画面的假节点误导。
17. 作为协作者，我希望各材料系列独立呈现真实版本与该版审阅，以便同一人的多份材料不混读。
18. 作为协作者，我希望在流程图选择历史版本／审阅后，正确原件、提交说明、责任人、时间、意见及附件联动，以便准确接续。
19. 作为协作者，我希望明确当前版与历史版并一键返回，以便旧版通过不传播给新版本。
20. 作为提交者或负责人，我希望查看图形和历史时保留文件输入、文字草稿和当前动作目标，以便读旧版不会改投上传或审阅。
21. 作为协作者，我希望失权、结束、冲突或状态刷新后保留输入并正确停用不可执行动作，以便不会静默覆盖或越权。
22. 作为维护员，我希望从轻量近期任务清单进入可点选的实际处理流程图，以便直接定位动作、材料与修改。
23. 作为维护员，我希望图中只表示已记录的步骤顺序与显式材料关系，以便不把动态工具选择画成固定必经流程。
24. 作为维护员，我希望无步骤、等待、失败、无修改完成及未知费用如实表达，以便已执行不被误当成成功或人工核对。
25. 作为维护员，我希望短字段和结构关系清楚显示实际前后值，长文本能阅读行内／逐行差异，以便不用靠记忆比较。
26. 作为维护员，我希望关系保留稳定编号、原始依据及已记录的历史名称，当前名称清楚标明时点，以便不拿现档案替换历史。
27. 作为研究员，我希望“指出问题”的处理记录也能点步骤、看依据和前后值，以便在原对象上下文复核反馈结果。
28. 作为普通研究员，我希望反馈阅读不出现管理员配置／费用控制，以便研究与维护管理权限保持原有边界。
29. 作为成员，我希望后台未变化时条件读取不重复传完整内容，以便保持已有阅读区稳定。
30. 作为成员，我希望任何304都发生在重新鉴权之后，账号、可见范围或对象资格变化时旧内容能清除，以便缓存不扩大权限。
31. 作为成员，我希望轮询或新步骤到来时保留任务、步骤、展开、滚动、缩放、焦点和输入，以便后台更新不抢读。
32. 作为成员，我希望断网保留最后有权内容并提示未更新，明确失权时清空相应图形／详情且可在恢复后重新读取，以便错误处理准确。
33. 作为成员，我希望快速切对象、场景、页面和账号时旧请求／旧布局结果不覆盖新选择，以便不混入他人的材料。
34. 作为键盘使用者，我希望用有名称的按钮、列表和字段完成同样操作，以便不依赖悬停、颜色或精细拖拽。
35. 作为手机或原生200%放大使用者，我希望图形与文字顺序布局仍可读、目标至少44px并有明确详情定位，以便无需缩小文字维持桌面密度。
36. 作为减少动态效果的成员，我希望相机过渡与动画可直接切换、自动旋转默认关闭，以便操作不依赖运动。
37. 作为WebGL或可视化模块不可用的成员，我希望已有文字、平面入口、清单和阅读继续可用并能重试，以便图形失败不阻断任务。
38. 作为本地应用维护者，我希望依赖、样式、worker及许可证均在同源本地资产中，以便断网可运行且不放松现有CSP。
39. 作为成员，我希望隐藏或离开图形后释放GPU、worker、监听和无用绘制，以便多个视图不会持续占用资源。
40. 作为建设方，我希望对原本地数据、附件、身份、AI设置和未提交改动做保全，以便整合不变成替换成合成库或重新开始。

## Implementation Decisions

### 同一应用与原型适配

继承现有视觉身份、普通导航、角色与领域接口；这是所选原型机制向现有页面的适配，不新建独立展示站或替换产品世界。资料清单、阅读器、主体档案、两阶段材料、中心成果、AI正式维护与反馈继续属于同一应用。空间探索入口必须在日常导航或资料检索首屏可见，不能只藏在深层折叠。紧凑列表仍可直接使用。

地球、关系星图、时间透镜可复用原型中的几何、拾取、相机及资源生命周期做法，但生产入口不能导入512条样本、fixture或内嵌原型HTML。全部题名、标识、计数、日期、关系和步骤来自当前身份可读接口；已有数据与业务写入规则保持。

### 同源可视化资产

使用Three、ECharts、Cytoscape、React Flow、ELK、diff2html等已核实的锁定依赖；React仅用于局部流程图根，不迁移整个应用框架。单一资产构建与懒加载适配层提供统一的加载、样式、更新和销毁。依赖构建输出、worker、外链样式及许可在本地分发，普通运行不需要Node或CDN。

维持现有CSP，禁止增加全局unsafe-inline／unsafe-eval、远程脚本或blob worker以迁就库。ELK采用实际严格CSP验证的官方API与同源显式worker；Cytoscape注入样式的兼容路径须与锁定版本一并验证，不能静默留下策略错误。第三方产物如保留GLSL字符串合法空白，第一方源码空白检查与生成产物一致性检查分别记录，不伪称所有产物均无诊断。

### 图形与查询口径

保留旧分布API默认语义及所有现有筛选。空间视图可增加只读投影：完整当前结果的统计，与排除本维度筛选但保留其他条件的上下文分布，必须有不同字段及明确的范围标识。国家多值可重复归组，不将国家数量相加当成总量。未知／未识别国别保留文字入口；国家代表位置不表示机构坐标。

时间透镜按需读取有上限的轻量有权记录窗口，建议上限300；返回真实loaded、total、limit、has_more及适用时间口径，保留资料稳定身份、题名、类型、原日期及精度。不得先截取全局结果后再过滤权限，不能把分页或图形窗口当作全量。坐标域来自实际可见日期范围，轴与点共用；纵向类型及为避免遮挡的纵深不表达影响力或强度。选区复用原查询条件，未知日期不放入某个伪造年份。

图形与清单共享同一生效查询、清除、未知值及返回语义。切换时间口径后，实际筛选及网址应可解释且一致。图形只读选择不产生资料修改，也不能绕过原件／对象读取权限。

### 有据主体关系

用同一有权一跳模型驱动Cytoscape平面图、Three空间图及可聚焦文字入口。正式作者、机构作者、发布者、期刊、文章署名单位和实际引用成果分别标注；保留AI与人工来历及原始未归属署名。不能从共同出现推断任职、隶属、合作或引用。布局和边长不表示研究强弱、地理或影响力。

图中对象进入现有档案／阅读器；返回保留原查询与位置。读取、刷新和切身份重新核权，失权清除旧图与详情；布局结果和网络响应绑定账号、页面及选择代次，过期结果丢弃。

### 协作与维护流程

React Flow节点仅绑定真实材料版本／具体审阅或实际任务／步骤；ELK只安排已有节点与有名称的边，不增加业务关系。材料版本的登记顺序、对应审阅、已发生步骤顺序及显式证据归属分别表达，不能画出无依据的审阅导致后续提交、反馈接续或固定必经流程。

保留规格1.0已经实现的当前／历史分离、具体版本字节、原件／意见／附件、回当前版、独立当前动作和窄屏定位能力。图形选择仅改变阅读，上传／审阅表单与文件输入不得因React重挂载或刷新而重建；不替用户变更写入目标或新造审批、在线Word编辑。

维护清单继续数据库直接摘要、先鉴权再近期窗口及has_more，旧full默认接口兼容。当前对象入口与历史快照分开；无变化、字段／关系变化及未完成按实际记录显示。diff2html只用于实际记录的较长纯文本前后值，安全转义、提供完整原新值；短字段和结构关系保持语义化对照，不把文件名或有限提取文字冒充Word/PDF正文diff。

研究员反馈复用步骤／证据／差异阅读，不增加费用配置权限或人工逐项采用门槛。未知费用及原账本保护保持。

### 条件更新与能力回退

任务摘要及所选详情采用当前授权表示的ETag。每次条件读取先验证账号、目标及依赖资格，再比较表示；可见范围变化、状态／步骤／结果变化必须使旧缓存失效。304只复用本账号、同URL且仍有效的表示；不使用公共缓存或跨账号持久化敏感详情。

单次在途、页面／账号／选择世代隔离、读失败保留最后有权内容、明确失权清缓存、恢复后重读继续适用。更新保留图形视口、选中节点、详情展开和输入；新增节点不自动抢选、滚动或缩放。

库加载、WebGL、布局worker失败时保留文字、平面图或清单，并提供明确状态及重试。默认无自动旋转；隐藏／离开时暂停并释放实例。手机和200%可选择更易读的列表，但图形功能仍有明确入口；只把字体缩小、关闭所有新能力或重回纯换色SVG不算适配。

### 技术尝试与取舍

SQLite FTS5、SSE/EventSource和Monaco可做隔离兼容实验，采用须有当前流程价值及可复核结果。FTS不能改变现有中文短词、去音标子串或权限语义；SSE不能耗尽本地同步服务线程、扩大可见范围或伪造持久事件；Monaco不作为只读差异阅读的强制依赖。不为凑齐技术名称而新增不可维护的运行服务，也不以“只借原理”代替本版明确选用库的实际调用。

## Testing Decisions

验证边界沿用已授权的公开HTTP与真实本地浏览器，新增只读投影、条件请求及可视化仍在同一边界；数据窗口／布局／拾取与既有业务写入通过这些外部行为验收，不重新询问技术选型许可。

1. **先红后绿的完整切片。** 从日常入口进入地球，点击国家／文字控件，核对实际HTTP查询、已知合成计数、列表、清除及阅读；新资料进入同一查询后图形更新。原型fixture或仅安装包不能使此验收通过。
2. **查询与窗口。** 保留旧接口契约；用已知多国、三种日期口径、年份／年月／日期精度、未知日期及超过300有权记录夹杂无权记录，独立核对上下文范围、总量、窗口和has_more。候选点、轴和打开对象身份实际对应。
3. **范围与拾取。** 实际操作ECharts刷选、起止年输入、单年、清除／重置、Three资料点和场景切换，验证列表／网址及所选记录一致；不靠检查私有renderer状态代替可见操作。
4. **关系与往返。** 使用不同类型、同名作者、AI正式关系、未归属署名、无证据及受限对象，点平面／空间节点与文字入口，核实际依据、档案目标、返回位置及权限。
5. **协作保稿。** 真正通过公开接口生成多材料／多作者、v1退回／v2通过／v3待审及附件；核原件字节与意见归属、图形选择／当前写入目标、文件输入保留、刷新与并发、闭期／失权／恢复、迟到请求。
6. **维护联读。** 真实摘要及详情包含无步骤、等待、失败、无修改完成、关系依据／状态／署名引用变化、长文本与未知费用。图节点、原新值、证据及当前对象入口对应；长文本含HTML等内容仍作为文字安全呈现。
