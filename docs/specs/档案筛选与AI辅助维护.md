## Problem Statement

研究员按国家查找资料和档案时，同一国家的中文、英文及大小写写法分裂为多个筛选项，选项计数、实际结果、导出和常用检索可能不一致。“更多筛选”还把默认发表时间和外部主筛选重复计入，窄屏下拉会遮挡后续操作。机构缺少国家筛选，期刊主办国入口不易发现，作者目前只有姓名搜索。

机构、期刊档案已经可以共同维护，但取得官网依据、逐格录入和持续核对仍费操作。现有 AI 只承担文章翻译、分类和概述，没有来源档案补全与作者持续建议闭环；模型回答也不能代替平台实际取得的材料。用户需要系统取得依据并提出建议，人员就地核对采用，避免为填满字段猜测事实，也避免同名作者或机器处理覆盖既有人工作业。

## Solution

统一确定的国家名称等价及中文展示，同时保留各个业务维度；资料、机构、期刊和作者按适用含义筛选，计数与结果使用同一集合。作者提供“任职机构国别”和“作品研究对象国”两个独立入口，不推断国籍。

维护者为一个或一组既有来源排队，由平台有界取得官网与适用正式接口材料，再由 AI 整理空缺或疑似差异。界面直接列出“原值 → 建议值”，就地查看实际依据，勾选采用或拒绝。作者建议接续 #64，复用同一小型候选与证据机制，提出已有作者、新建有据人物及关联本篇等建议，经人确认后正式生效。正常阅读不被未确认署名或维护任务阻断。

## User Stories

1. 作为研究员，我希望 Latvia、LATVIA 和拉脱维亚归为同一中文筛选项，以便一次找到同一国家的全部匹配资料。
2. 作为研究员，我希望筛选项数量与结果及导出选择一致，以便准确判断实际查得的范围。
3. 作为研究员，我希望分别选择资料研究对象国和来源国家，以便区分文章研究哪里与来源来自哪里。
4. 作为研究员，我希望从机构类型页面直接找到所在地国家筛选，以便按国家查找智库或其他机构。
5. 作为研究员，我希望从期刊页面直接找到有依据的主办国筛选，并独立组合国际定位，以便找到所需期刊。
6. 作为研究员，我希望按作者任职机构国别查找人物，以便发现具有相关任职经历的作者。
7. 作为研究员，我希望任职时间不详或历史任职如实保留，以便避免把所有登记误解为现任。
8. 作为研究员，我希望按作者可见已确认作品的研究对象国查找人物，以便发现实际写过相关地区作品的作者。
9. 作为研究员，我希望作者两个国家维度分别多选，并与姓名搜索组合，以便表达具体查找需要。
10. 作为研究员，我希望多国、多任职及同一国多个别名只对同一人物计一次，以便数量准确。
11. 作为研究员，我希望未知值仍可筛选、未识别原词仍可查找，以便发现待补信息而不丢失旧资料。
12. 作为研究员，我希望历史国家、地区及组织称谓保留各自含义，以便不被强行归成某个现行国家。
13. 作为已有用户，我希望旧网址和常用检索仍可使用原国家写法，以便继续已有工作。
14. 作为资料维护者，我希望原始字段、导出原值、历史版本与已冻结批次保持原据，以便复核过去的结果。
15. 作为研究员，我希望“更多筛选”只计折叠区域内实际生效的非默认限制，以便看懂当前条件。
16. 作为研究员，我希望已选但零结果的条件仍可见可清除，并在阅读返回时保持条件，以便连续查阅。
17. 作为窄屏或键盘用户，我希望展开、选择、关闭和清空筛选均可操作，以便完成同一查找流程。
18. 作为维护者，我希望为单个或一组既有来源排队生成补全建议，以便集中整理缺项与疑似差异。
19. 作为维护者，我希望平台优先使用已登记官网并发现少量同站介绍页，以便少量入口确认后无需逐格抄表。
20. 作为维护者，我希望缺官网、取不到材料或依据不足时进入异常处理，以便补充可靠入口而不是采用猜测。
21. 作为维护者，我希望每个建议旁边都有原值、建议值与实际片段、网址和取得时间，以便判断是否采用。
22. 作为维护者，我希望名称、介绍、地点、研究范围、ISSN 等只按对象适用字段提出建议，以便维护真实档案。
23. 作为维护者，我希望主办、出版和其他机构关系分别显示证据，以便不把出版方当作主办方。
24. 作为有相应权限的成员，我希望勾选少量建议即可采用，也可拒绝单项，以便减少重复填写。
25. 作为共同编辑者，我希望建议生成后有人修改档案时提示冲突并保留输入和建议，以便保护人工修订。
26. 作为资料核对者，我希望采用 AI 建议后仍保留机器来历与原核对边界，以便不把采用等同于“已核对”。
27. 作为维护者，我希望拒绝、重跑和新证据各自可追溯，以便比较版本并避免无变化的反复推荐。
28. 作为读者，我希望原始署名及顺序保留，未确认身份也能正常阅读，以便不被档案整理阻断。
29. 作为维护者，我希望 ORCID、文章页明确个人主页等材料用于召回身份候选，以便快速找到有据的人物。
30. 作为维护者，我希望姓名相同只作为候选线索，以便避免将同名异人自动合并。
31. 作为维护者，我希望系统提出关联已有作者或新建有据人物并关联本篇的建议，由人确认，以便形成正式作品关系。
32. 作为维护者，我希望文章署名单位、人物任职、机构署名和来源主办分别处理，以便每条关系表达真实含义。
33. 作为维护者，我希望批量和逐条核对都能少操作并看依据，以便有效处理积累的候选。
34. 作为已纠正身份的成员，我希望既有确认和人工改正不被重跑改回，以便整理能够积累。
35. 作为维护者，我希望人物合并及拆回继续先看影响预览，以便候选采用不隐含身份合并。
36. 作为受限资料的读者，我希望作者统计及候选查阅遵守当前权限，以便不泄露其他账号的作品或依据。
37. 作为维护者，我希望后台任务不依赖读者刷新并能在中断后继续，以便排队目标可以持续完成。
38. 作为管理员，我希望任务遵守统一网关、月额度、暂停、次数和未知费用保护，以便新增能力仍受现有控制。
39. 作为管理员，我希望失败、失效、缺材料及待采用各自可见，以便任务失败不会显示为已经补齐。
40. 作为后续接手者，我希望候选、证据、处理及采用历史能随授权导出和完整备份恢复，以便在新目录继续核对。
41. 作为用户，我希望三项完整流程统一验收后交付，以便正式交付包建立在经过核查的版本上。

## Implementation Decisions

### 国家等价与筛选

- 共用一份小型、明确可核的国家等价集合：稳定匹配键、中文展示名及确定的别名。资料研究对象、来源国家、机构所在地、期刊有据主办国、作者两个国家维度分别取值，只共享等价规则。类型、机构性质及期刊国际定位仍是独立条件；按当前档案类型提供直观可发现的适用入口。
- 归组只作用于查询、展示和计数，保留原字段、历史及导出原值。旧 URL、常用检索中的原别名继续匹配同一集合；已保存批次的成员与原报告引用依据不回溯重算。CSV、内容包及其他现有选择导出使用与列表相同的筛选身份集合。
- 同一对象的同一规范国家只计一次，权限与当前查询过滤后、分页前形成总数及分面。多值先形成对象集合，不能把各别名数量直接相加；机构及人物旧 ID 合并后按有效身份去重。
- 未知仍能筛选，各维度使用符合含义的未知或待补标签；作者无可用任职国、无可见已确认作品研究对象时如实说明，不能暗示无作品或影响低。未识别词保留原词和有条件的匹配，不能丢弃后变成无条件全查。
- Yugoslavia、Socialist Republic of Macedonia 等历史称谓不等同某一现行国家；Arctic、Asia、EU、Western Balkans 等保留地区或组织语义。有争议的等价不凭机器猜测加入集合。
- 作者任职机构国别取未移除、有依据登记的任职关系及所连机构国家，可含历史及时间未知任职，不自动标为现任。作品研究对象国仅取当前账号可见、署名已确认且未移除、原始署名来源同样可见的有效作品；使用人工优先、有效机器分类回退的既有研究对象投影。先遍历完整可见作品集合再分页，不能只取作品第一页。
- 两个作者分面各自多选为 OR，两个维度之间及与姓名关键词之间为 AND。待确认候选不计入已确认作品；姓名、来源国家、文章单位及作品研究对象均不推断作者国籍，本轮不增加国籍字段。
- “更多筛选”只计其内部非默认且有效的限制，默认发表时间及外部关键词、主国家筛选不重复计入；默认值不制造多余条件标签。已选零结果、清空、阅读返回均保持可理解的状态。移动下拉及键盘操作可完成后续流程，沿用简洁文案，不增说明小字。

### 来源取证与字段候选

- 复用现有安全公网取得边界，优先已登记官网，自动发现少量同站简介、编辑部、联系方式或结构化页面，按对象使用适用的正式题录／身份接口。单目标的页面数、深度、时间、大小和重试须有明确上界；逐跳检查地址、重定向和连接，沿用私网隔离及传输限制。
- 平台取得材料后才交 AI 整理；保存实际原响应、使用片段、最终 URL、取得时间和校验值，并将建议关联到所用版本。网页内容只作为待整理材料，不取得执行指令的权力；模型自述、补造网址及未取得页面不能充当依据。
- 现有可编辑且对该对象适用的名称、中文名、介绍、机构类型、地点国家、研究范围、ISSN、官网和资料入口、主办／出版及国际定位等可提出建议；每项展示原值、建议值及就地依据。主办、出版、关联角色分别有据，不从单一角色反推其他关系或期刊主办国。
- 支持一个或一组既有来源显式排队，整理空缺与疑似差异；少量入口确认后无需逐格抄表。缺官网、材料不足、相互冲突或取得失败作为异常处理并保留已有信息，不要求补齐所有字段。维护工具放在合适维护入口，普通阅读首页保持日常研究用途。
- 人工选择采用或拒绝。采用复用现有领域校验、共编权限、版本检查及修订历史，保护人工修订；目标版本变化时保留建议与当前输入，提示处理冲突，不能静默覆盖。采用不自动标为“已核对”、改变可见范围或开启持续采集。

### 作者建议接续 #64

- 原始署名、顺序、原名和取得来历保留。利用 ORCID、文章页明确个人主页及适用正式身份材料召回已有身份或新建有据人物候选；姓名及名称相似仅召回候选。没有可靠依据时保留未确认署名，不阻断读文章。
- 展示候选身份、建议操作、关联本篇及依据，支持逐条和批量核对；包括“已有作者＋关联本篇”“新建有据人物＋关联本篇”等完整操作。人工确认才写入正式档案和作品关系；ORCID 等明确标识也不绕过本轮确认。已有确认保持，不以本轮收紧批量降级旧关系。
- 机构署名沿用机构身份；文章单位、作者任职、资料发布／刊载、来源主办及机构关系分别表达。机构发布文章或机构地址本身不证明作者任职。身份冲突保留多候选，不自动合并人物；合并、拆回仍走专门影响预览及确认流程。
- 已拒绝的同一证据／输入建议不在无变化重跑中无限推荐；新证据可以产生可比较的新版本。人工改正、移除及已确认关系受保护，重跑差异作为建议保留，不覆盖正式事实。

### 共用候选、后台与恢复边界

- 来源与作者复用小型持久候选／证据／人工采用边界，不建设通用 AI 框架。候选存在本地数据库，可从中断恢复；包含目标与基准版本、字段或关系建议、多候选、证据及输入版本，保留拒绝、失效、失败和采用记录。机器处理来历与采用人及时间分别可追溯。
- 正式事实由现有来源、人物、署名与任职等领域保存服务维护；候选层只管理待核对建议及处理历史。来源目标不得伪塞进只支持文章外键的既有任务；任务、证据和目标绑定须在产生、查看、采用、导出及恢复时校验，串目标或损坏证据应拒绝。
- 任务排队后由持续 worker 执行，不依赖读者刷新。沿用租约、幂等、权限复核、有界重试及失败续作，分别表达取得失败、AI 失败、暂停、无可用建议和待采用。只执行已授权排队目标，不自动扩大来源或默默补全全库；失败不能变成虚假的成功。
- 所有 AI 请求复用统一网关及现有权限、费用预留结算、暂停、次数和未知消耗保护；公开外部材料为默认输入，内部报告不自动发送第三方。本轮开发不读取凭据、不发真实付费请求、不解除本机 50 CNY 月上限及已暂停状态。
- 按当前权限导出可读的候选、依据和处理／采用历史；完整备份及新目录恢复同时保全候选、实得材料、关系及费用历史。恢复不盲目重发未知费用请求，不改变原权限和人工事实。

## Testing Decisions

### 可观察接缝与先例

按已获授权的公开 HTTP、实际浏览器和新目录恢复边界，先在可观察接缝形成失败信号，再完成行为；只断言外部结果、权限、可追溯材料和实际保存状态，不用内部函数调用次数代替用户结果。软件样本使用独立临时合成库、合成公开站点和 mock AI，端口与输出目录隔离；真实库、原件和 ThinkTank 不参与修改。

沿用现有阅读筛选／常用检索、来源目录、作品署名／任职、辅助取得、统一费用网关、自动 worker、可读内容包和完整恢复的测试方式；既有先例分别见 [tests](../../tests) 中的 reading_feed、saved_searches、source_catalog、bylines、affiliations、assisted_intake、ai_budget、automatic_processing、content_export 与 person_recovery 测试组。新接缝尽量落在这些公开行为上，不为测试另建全套框架。

### 必须覆盖的行为

1. **等价集合。** Latvia／LATVIA／拉脱维亚及同记录多别名，跨资料研究对象、来源、机构、期刊和作者两个维度；筛选项、查询、CSV／内容包选择、旧 URL 与常用检索返回同一身份集合，原字段与原导出值不变。覆盖多国、历史称谓、地区、未知、未识别词、旧 ID 合并、选中零结果及冻结批次保全。
2. **作者权限与完整性。** 姓名组合、维度内 OR／维度间 AND；超过一页的作品（至少 21 篇）及人物，页外作品仍影响分面。已结束及未知时间任职、移除关系、无作品或未知国、同作品多署名均有样本；其他账号私有作品、不可见原始署名来源、待确认候选不进入当前人的结果或数量。
