# 基础资料管理第一批

2026-10-25；版本 1.0。状态：交付规格，行为范围不变。用户在 R011 确认基础数据库优先后要求“开始建设”；建设方在该授权内选定本批流程与技术边界。产品规则以 [PRODUCT](../../PRODUCT.md) 为准，本批不改变对象身份、资料可见范围或个人成果授权。发布快照和执行状态见 [父任务 #14](https://github.com/normaltank/DataBase/issues/14)，子任务 #15—#17；实际验证见 [整组验收](../../work/基础资料管理第一批验收.md)。

## Problem Statement

研究员已有筛选、单条收藏、专题、阅读与导出，但日常整理仍需逐条操作，浏览和阅读之间往返较多；平台附件中的文字尚不能被检索。中心不能直接使用 Zotero，需要在本平台完成这些基础工作。

## Solution

在现有资料库增加紧凑列表与保留上下文的连续阅读；明确选择若干资料后，批量收藏、加入专题或导出题录；把可提取文字的本地附件纳入有权限保护的检索，并显示命中出处及页／段位置。沿用蓝白柔黄、清楚题名和少量必要说明。

## User Stories

1. 作为研究员，我希望切换紧凑列表与现有卡片，以便比较长题名、署名、日期、来源及阅读入口。
2. 作为研究员，我希望切换视图时保留查询、筛选、排序和页码，以便继续当前查找。
3. 作为研究员，我希望阅读一篇资料时仍能看到列表，并连续查看同页其他资料，以便少做返回操作。
4. 作为窄屏或键盘用户，我希望阅读与关闭操作可达、焦点合理恢复，以便不丢失列表位置。
5. 作为研究员，我希望明确勾选资料并看到选中数量，可以选择当前页、逐条取消或清空，以便知道批量操作影响哪些内容。
6. 作为研究员，我希望同一查询翻页时保留选择，改变查询／筛选／排序或离开资料库时清空选择并有反馈，以免误操作看不见的旧结果。
7. 作为研究员，我希望一次收藏多条选中资料，重复执行不会取消原收藏，以便稳定完成整理。
8. 作为研究员，我希望把多条资料加入自己有权维护的一个专题，已有条目保持一份，以便组织材料而不复制原文。
9. 作为研究员，我希望下载仅含选中资料的 CSV 题录，以便在其他工具中继续处理，不改变原有筛选结果导出。
10. 作为研究员，我希望批量操作失败时清楚知道没有完成并保留选择，成功时知道实际处理结果，以便继续工作。
11. 作为资料作者，我希望批量整理不修改正文、署名身份、分享范围或编辑授权，以便保持原有责任规则。
12. 作为成员，我希望账号切换或权限变化后不残留其他账号的选择、阅读内容及批量结果，以便尊重现有访问范围。
13. 作为研究员，我希望在已获阅读权限的资料中查到 PDF、DOCX 及纯文本附件里的文字，以便找到摘要没有提到的内容。
14. 作为研究员，我希望看到命中来自哪份附件、PDF 哪一页或文本哪一段，并能打开原附件，以便核对上下文；提取文本不冒充人工摘录。
15. 作为研究员，我希望对已有附件主动建立或重建索引，看到成功、无可提取文字、格式不支持或提取失败，以便知道没有搜索命中是否源于未索引。
16. 作为研究员，我希望扫描件、损坏文件或超出处理限制的附件仍可按原有方式保存与下载，文本索引失败不破坏资料保存。
17. 作为成员，我希望历史恢复、合并和权限调整后搜索只使用当前可见资料的当前附件，不暴露历史或无权访问的文字。
18. 作为维护人员，我希望备份恢复后原始文件和资料继续可用，派生索引可重新生成，以便搜索缓存不成为资料唯一副本。

## Implementation Decisions

- 保持当前技术栈及资料服务边界。列表和连续阅读复用现有详情、阅读动作与权限结果；桌面显示列表与阅读区域，窄屏采用可返回的单页或抽屉，不重做富文本编辑器。
- 第一切片交付列表、连续阅读与明确选择状态；第二切片依赖第一切片，交付批量动作；第三切片独立交付附件检索，最后在同一集成分支验证。
- 选择只包含用户明确勾选的稳定资料编号，“选择当前页”不隐含选中全部搜索结果。选择状态隔离账号，重新加载时不盲信旧授权。设置合理批量上限并给出说明。
- 批量操作在服务端重新检查全部编号、当前阅读权限及目标专题维护权限。修改动作在同一事务完成；混入不可见／不存在资料、无权维护专题或版本冲突时整体不写入，错误不披露隐藏内容。收藏和加入专题采取幂等添加，沿用专题历史与版本规则。
- 选中导出复用现有题录字段和文本转义规则，显式检查每条资料权限；CSV 处理电子表格公式注入。保留既有按筛选条件导出和完整可读包。
- 附件检索先支持文本型 PDF、DOCX、UTF-8 TXT／Markdown，实际可上传类型沿用现有规则；不增加外部请求，不读取外链文件。使用成熟 PDF 文本解析依赖和必要的格式读取，不自建 PDF 渲染器。按页／段保留定位，派生索引与原附件分开。
- 提取在上传后或用户主动索引时执行，使用文件大小、页数／字符数、解压体积及执行时间等适当边界；普通查询不触发全库解析。上传的业务成功不依赖索引成功。旧附件可逐份建立索引，不批量改写正式资料。
- 检索沿用现有查询与权限语义，支持在资料文字和当前附件文字中匹配，显示可核查的命中片段。搜索前过滤授权，历史附件、孤立附件及已不可见资料不参与结果或计数；重建时重新检查授权。
- 索引可丢弃、重建，恢复／合并／附件关系变化后不能返回旧关联文本。完整备份继续保护原文件；缓存策略由实施方确定，并通过新目录恢复验证，不增加空的未来框架。

## Testing Decisions

沿用此前已确认的最高边界：应用 HTTP 请求／响应、公开文件下载及实际页面操作，使用隔离临时数据库、多成员会话和合成文件。内部模块替换不应破坏测试；每条行为先红后绿，不断言内部调用顺序。既有权限、修订、专题、可读导出及恢复测试作为先例。

1. 两种视图、查询／排序／分页和连续阅读保持同一组结果；桌面及约 390px 窄屏实际操作并保留截图，检查长题名、键盘与返回位置。
2. 同查询跨页选择、切换条件清空、账号切换清空；选择当前页和全库结果有明确边界。
3. 批量收藏与专题加入的重复请求、部分已存在、事务失败、无权限及失效编号；请求失败后检查没有部分新增。
4. CSV 只包含选中且有权读取的条目，汉字、引号、换行与公式起始内容正确处理；旧筛选导出保持。
5. 合成 PDF、DOCX 和纯文本包含仅在附件内出现的独立测试短语，通过上传／索引／搜索／下载验证命中、定位及原文件不变。
6. 扫描型无文字、损坏、格式不支持、超限与重复索引明确反馈；正文与原附件仍可用。
7. 多成员受限资料、权限改变、历史恢复、资料合并及索引重建后不泄露旧文本；索引文本不修改人工摘录和引用快照。
8. 完整备份恢复到新目录后重新生成索引并重复关键查询，验证旧资料和附件完整；沿用现有应用完整检查及双系统 CI。

## Out of Scope

通用网站采集、自动下载外链、OCR、Zotero 依赖或同步、复杂引文排版、PDF 标注器、自动翻译、影响力评分、实时协作、批量改写资料正文／权限、正式多人部署。来源目录全面重排及研究分析工作台属于后续候选，不把本批资料库阅读改进宣称为全部 UI 重建。
