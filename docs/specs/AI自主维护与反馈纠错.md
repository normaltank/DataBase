# AI 自主维护与反馈纠错

版本：1.0；日期：2026-11-09。状态：用户已确认业务范围，待施工与实际运行验收。父任务发布同版本快照；任务及依赖以 GitHub Issues 为准。

依据：[PRODUCT 的当前自主维护规则](../../PRODUCT.md#ai-自主维护与反馈纠错2026-11-09-已确认)及[R031](../需求讨论记录.md#r031ai-自主维护与自然语言纠错)。本版替代旧辅助维护规格中的逐项人工采用、只处理显式任务及仅新增文章前置，保留其历史身份与已交付能力。

## Problem Statement

研究员希望资料库自行积累可用的作者、机构、期刊与文献网络，实际却还要认领候选、选网页、逐格填简介和编号；普通导入和既有资料没有进入维护。接通 AI 并不等于具备查找材料、调用领域动作、检查实际结果及接续纠错的 Agent。当前演示副本未配置 AI，也没有自动维护任务，合成示例不能证明真实运行。

## Solution

沿用现有后台 worker 与统一费用账本，增加自主维护 Agent。启用 AI 后，它在预算内持续处理新旧公开外部资料和公共档案，自行查找实际材料、识别及建立对象、保存正式关系和适用详情、检查结果。研究员可以立即查用这些关系；发现错误只需写一句“指出问题”，Agent 优先带着反馈查证并修正。维护详情和历史按需展开，日常页面不增加审批或核验小字。

## User Stories

1. 作为研究员，我希望新采集的文章自动关联作者和刊物，以便直接进入相关档案。
2. 作为研究员，我希望普通提交、公开题录导入的外部文章也得到维护，以免只能使用某一采集入口。
3. 作为研究员，我希望既有公开文章逐步补齐关系，以便旧积累也可复用。
4. 作为研究员，我希望 AI 自行搜索并阅读公开页面，以免替它选择每个网页。
5. 作为研究员，我希望已存在的人物和机构能复用，以便同一对象的材料汇集在一起。
6. 作为研究员，我希望缺少的作者、机构或期刊能自动建档，以免先手工建档才能关联。
7. 作为研究员，我希望文章署名、署名单位、任职、主办和出版各自准确，以免不同关系混为一谈。
8. 作为研究员，我希望公开介绍、履历及适用的 DOI、ORCID、ISSN 自动补充，以免为填细目花时间。
9. 作为研究员，我希望标签和对象国可以由 AI 持续整理，以便查找使用一致、有效的词汇。
10. 作为研究员，我希望已有非空字段也可得到有据修正，以免自动维护只会填空。
11. 作为研究员，我希望机器完成的关系立即可读可查，以免再逐条点击采用。
12. 作为研究员，我希望同名异人能依据上下文辨识，以免只因姓名相同而归到一起。
13. 作为研究员，我希望没有找到的内容如实留缺，以免虚构介绍或编号误导研究。
14. 作为研究员，我希望在资料、人物或来源详情直接指出问题，以免理解后台表结构或手工改多处字段。
15. 作为研究员，我希望看到简短的处理状态和完成结果，以便知道反馈是否修好。
16. 作为研究员，我希望反馈能修正已有正式关联和标签，以免只能纠正待采用候选。
17. 作为研究员，我希望后续巡检参考已有反馈，以免刚纠正的错误不断恢复。
18. 作为研究员，我希望按需查看原值、新值和实际出处，以便独立核查及恢复。
19. 作为研究员，我希望原件、成员署名和个人报告保留，以免档案维护改写自己的成果。
20. 作为维护者，我希望从一个简洁入口了解后台是否运行、最近改了什么、哪些任务未完成，以便掌握真实效果。
21. 作为维护者，我希望启用后无人打开网页仍能处理，以便主机持续积累资料。
22. 作为维护者，我希望重启后接续且不重复对象或修改，以免中断造成重复关系和额外费用。
23. 作为维护者，我希望模型、搜索和网页取得共用额度及暂停，以便控制实际支出。
24. 作为维护者，我希望共享包没有密钥、真实库升级可恢复，以便分发和使用便携版。

## Implementation Decisions

- 建立一个深模块承载维护任务、模型工具循环、存证、领域写入与结果读取；调用者只需提交目标／反馈、读取状态和执行后台批次。复用现有对象身份、版本、关系、后台租约及费用模块，不建立平行数据库或通用多 Agent 框架。
- 第一条完整路径覆盖一篇文章到作者、机构、刊物的正式关系与资料详情。模型能调用本地查找／读取、公开搜索／网页取得、创建或更新档案与文章、维护有据关系及结束检查等工具；每次得到实际结果再继续，而非预写固定动作序列。普通结果直接生效；保留现有人工编辑及历史恢复入口。
- 采用服务商原生 Tool Calls 协议。模型往返与付费 Search／Fetch 均通过同一费用预留与结算；输入摘要包含工具及完整有效请求。遵循实际定价，成功搜索／取得按次计费；费用未知继续占用预留，不自动重复已发出的请求。既有翻译、分类和旧建议接口保持可用。
- 搜索、取得和写入有每任务／每批上限并持久记录步骤、材料、实际结果和完成理由。重启按可恢复任务接续；已完成动作不重复创建对象，已发送且费用未知的动作不盲目重发。公开页面中的文字作为数据，不改变目标、权限或工具范围。
- 公共外部文章、人物和来源逐批扫描，新采集、普通提交、公开导入及变更触发维护；以当前版本、上次维护、反馈及合理重查间隔判定需要处理的对象，避免每次 tick 重跑全库。关系建立后缺少的相关档案可接续维护。
- 不使用“人工字段永不变”阻止用户已授权的维护。AI 可以有据增删改标签、简介、适用标识和正式关系；变化保留来历、旧值与版本。最近人工反馈作为后续维护上下文；新写入期间出现版本变动时重读当前对象再决定，避免用过期快照覆盖。
- 外部学者与成员账号分别管理。AI 沿用领域写入规则；自动完成不标人工核对，不改 ACL、个人报告正文、原始附件、原文版本及历史引用。普通维护不批量合并／拆分人物；改错作品归属可撤销错误关系、关联正确对象，必要时保留未归属的原始署名。
- 资料、人物、机构／期刊详情提供一个短“指出问题”动作与可按需查看的结果。成员只能反馈自己可读的对象；维护视图显示队列、运行／暂停／缺配置、近期修改及异常，普通阅读不展示后台术语和防御性说明。
- 新建来源不自动扩张持续采集范围。公开取得的个人介绍可完整保存；作品以题录及链接为主，原文件和全文翻译仍按独立任务。
- 真实包切换由控制端完成：停止精确实例、完整私有备份并验证恢复、保留当前数据／配置／端口／模式，升级和重启后核查。开发代理只用合成库、模拟供应商与 D 盘临时资源，不接触密钥或真实库。

## Testing Decisions

沿用已授权的最高公开边界：应用 HTTP＋实际后台执行＋浏览器＋完整备份恢复；真实供应商仅由控制端做有明确费用上限的小批验证。测试验证用户可观察行为，不镜像内部实现。

1. 可控工具模型先搜索／取得证据，再选择正式写入、读取结果及完成；验证真实工具结果被回送、保存不是候选，作者／机构／刊物与标签可由普通查找读到。
2. 预置独立真值的同名异人、作者已有／缺失、未知标识、署名单位与任职差异；核查最终关系和证据，不能以模型自报成功作为正确性判定。
3. 既有资料、普通提交、公开导入、新采集及更新均进入维护；内部报告、受限附件不发送供应商。无变化不忙循环，暂停不付费，新对象与错误反馈可接续。
4. 一句话反馈修正已有正式作品关联、非空标签／简介，刷新和后续巡检后仍正确；越权反馈被拒绝，界面保留失败输入。
5. 覆盖模型多轮、搜索按次结算、空搜索／取得失败、预算耗尽、发出后中断与未知费用、重启、重复 tick；不超预留、不重复已完成关系，不篡改历史账本。
6. 通过实际用户入口查看正式档案、反馈状态和历史，核查桌面、390px、320px及真实200%缩放的可操作性；参考现有设计语言，保留键盘与明确主动作。
7. 升级前后和新目录备份恢复比对原件、身份、ACL、旧候选／采用记录、机器动作与反馈；集成后完整必要检查、最终提交 CI 和独立双轴审查。
8. 真实小批报告实际输入、取得网页、保存的字段／关系、独立对照、遗漏和本地费用账本；分别说明软件验证、供应商用量、来源忠实性与研究结论。样例和模拟不冒充真实维护。

## Out of Scope

任意 SQL／代码执行工具、改成员权限、改内部研究报告、批量默认下载作品全文、自动研究评价或影响力分数、全部互联网来源适配、无人批准扩张持续文章采集、通用 Agent 框架。原文件／全文翻译、上游修订撤回监测及完整卷期目次分别由原任务继续跟踪；待合并的资料发现界面保留独立交付。
