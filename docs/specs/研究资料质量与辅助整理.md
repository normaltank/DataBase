# 研究资料质量与辅助整理

版本：1.0。日期：2026-10-27。状态：本轮施工基线；执行、集成和最终放行以 GitHub 任务与 PR 为准。

授权：本轮用户要求按 Matt 工作流处理 GitHub 中的数项 Issue，并授权指挥 Agent 全权代理；同时提供 DeepSeek 接入凭据。既有业务规则沿用 [PRODUCT](../../PRODUCT.md)，尤其是人工身份确认、可见范围、个人报告编辑责任和研究质量分层。外援提案按本地核查后形成的本规格执行，原提案保留历史身份。

## Problem Statement

研究员已有单篇辅助录入、资料正文与附件检索、摘录和报告、专题及核对历史，但若干连接仍需手工完成：附件命中无法直接形成可追溯摘录，报告看不到原文及人物关系变化，专题缺少结构化排查与排除记录，核对详情没有说明范围及采用的历史基线。卷期页码和 ISSN 未成为正式资料字段；无变音符拼写及部分日期查询遗漏资料。外文资料尚无可保留原文和人工修订的机器翻译流程。

本轮代码核查基线为 `358973dff044cdbc6303bbbd6cb23766f5080188`。既有核对历史、原件导出校验和自动补空白字段已存在，不重复实现，也不将提案的原始现状判断当作验收事实。

## Solution

完善研究员从查找、阅读、摘录、引用、专题整理到核对与导出的已有流程。机器翻译采用单篇显式操作，保留原始输入、机器生成版本与人工采用记录。所有结果遵守当前读取和编辑权限，保留冲突、历史、备份及恢复能力。

## User Stories

1. 作为阅读者，我希望将附件命中片段带着文件及位置放入摘录编辑器，以便核对后保存。
2. 作为摘录维护者，我希望看到引用时文件的摘要、字节数、名称及可取得的前后文，以便追溯实际采用的文件。
3. 作为复核者，我希望区分“在指定位置的提取文字中找到”“未找到”和“无法检查”，避免把文本匹配当成真实性证明。
4. 作为离线复核者，我希望校验器发现引用声明与包内指定附件不一致，并保留旧包可解释的兼容行为。
5. 作为报告作者，我希望为引用登记支撑、反例、限定或背景及对应说明，以便表达推理关系。
6. 作为报告读者，我希望知道摘录、原文及已确认身份关系后来发生了哪些变化，而旧采用内容保持固定。
7. 作为旧报告读者，我希望没有记录过的引用角色、身份基线及附件锚点如实显示未知。
8. 作为专题维护者，我希望登记纳入、排除和理由，并分别查看两类资料。
9. 作为专题维护者，我希望记下排查的来源、检索词、时期、语种、日期及结果，区分无结果、访问受阻和未登记检索。
10. 作为专题读者，我希望默认资料计数和阅读只含已纳入项，复核与导出仍保留可读的排除项及排查记录。
11. 作为核对人员，我希望记录核对范围和说明，并知道这次操作是自己核对还是由另一位成员执行。
12. 作为资料读者，我希望编辑后仍能看到此前实际核对过的版本、人员、时间、范围和说明；当前待核对不冒充已核对。
13. 作为资料维护者，我希望卷、期、页码和 ISSN 从辅助录入到编辑、历史恢复和导出保持完整。
14. 作为检索者，我希望输入 Eriks Jekabsons、Riga、Petijums 可找到相应拉脱维亚语写法，并保留原始显示文字和已有组合查询语义。
15. 作为检索者，我希望日期只有年份或年月的记录按可能日期区间参与筛选，日期未知不被虚构。
16. 作为成员，我希望对一篇可读且可共同编辑的外部资料显式请求机器中文译题／摘要，清楚知道发送的内容和机器来源。
17. 作为成员，我希望翻译任务失败可以重试、缺少摘要时只翻译题名，生成内容不会冒充经过人工确认的研究发现。
18. 作为维护者，我希望原文、机器译文和人工采用分别保存；重跑和迟到结果不能覆盖人工内容，采用时检查版本冲突。
19. 作为离线使用者，我希望上述记录和关系在授权导出、完整备份及新目录恢复后仍可查验。

## Implementation Decisions

### A. 附件锚定摘录（#41）

- 从附件命中进入现有摘录编辑流程，预填原文、附件、位置和引用文字，允许成员核对调整。
- 服务端以有权读取且属于所选原文的附件为准，固定附件编号、名称、字节数与 SHA-256；不信任客户端提交的校验值。
- 基于相同文件摘要的 ready 索引检查指定位置的规范化空白文本匹配，记录结果和可取得的前后文。跨段、未索引、无文字或未匹配时允许保存并明确原因；不能仅因整份文件其他位置出现同句就宣称位置已核验。
- 摘录后来编辑、附件替换及历史恢复不得静默重写旧报告引用。
- 离线校验器交叉核对内容与复核清单中实际声明的附件锚点、manifest 路径和实际字节；新增锚点缺失或不一致返回非零。没有锚点的旧记录保持未知，不伪造核验。

### B. 引用角色和变化提示（#42）

- 支撑、反例、限定、背景为成员显式选择的角色；旧引用保持未分类，不能迁移成默认支撑。新引用可默认背景并在界面明确显示。
- 保存角色和断言说明遵守报告作者权限及版本冲突；修订、恢复和导出保留。
- 固定原文版本及所用已确认署名、文章单位、研究对象的身份基线。读取时区分摘录更新、原文更新、原文合并、身份关系变化；署名纠正未提升正文版本也须能发现。
- 权限收窄时隐藏不可读当前内容及关系细节，保持现有引用遮蔽规则。历史缺少身份基线时如实说明不可比较。
- 阅读与离线复核呈现角色和变化原因；缺反例或限定只说明“未登记”，不判定论证错误。明确刷新后才采用新快照。

### C. 专题排查与排除记录（#43）

- 专题条目保留 included／excluded 及理由；旧项和批量加入默认 included。排除需要理由，变更、移除、恢复均通过现有权限与版本接口。
- 排查日志记录来源或检索词、时间范围、语种、实际检索日期、found／zero_results／access_blocked 和说明；没有日志表示未登记检索，不推定没有检索。
- 默认资料范围和计数仅纳入 included；详情复核区和导出分别列可读的 included／excluded，隐藏条目不泄露。
- 现有专题历史已存在，扩充其快照及恢复；完整备份和旧版本升级保持默认解释。

### D. 核对说明与历史基线（#44）

- 保留当前管理员核对权限。新核对操作记录范围（题录、原文与署名、论证与译文）及非空说明；无效范围或缺说明返回可理解的 400，界面保留输入。
- 记录核对者与提交者／当时最后修改者是否为同人，这是事实标识，不新增强制双人审批，也不生成机器置信度。
- 核对仍生成版本及历史；编辑后当前状态仍 pending。详情和可读导出展示最近一次实际核对基线，不因恢复旧正文而改写后来发生的核对事实。
- 旧核对历史能取得的人员、时间和版本保留；历史未记录的范围／说明／独立性明确未知，不追溯补造。

### E. 出版题录与检索（#45）

- 卷、期、页码、ISSN 作为正式可编辑资料字段贯通单篇取得、表单、阅读引文、CSV、内容导出、修订和完整恢复；原始取得依据继续保留。
- 与 #36 分工：本项交付字段基础，标准 RIS／BibTeX／CSL 导入导出闭环仍由 #36 跟踪，不重复建第二套交换功能。
- 查询采用 Unicode 分解、组合标记处理及 casefold 的统一规范化，保留原文。覆盖已确认署名和资料已支持的文本来源，不扩大读取范围；多词组合、子串、附件与题录联合命中保持原语义。
- 消除资料过滤阶段逐记录读取署名、一般来源关系等 N+1 查询。可用批量预取或索引实现；FTS5 为原提案的实现建议，若不能保持原有子串与组合语义则不强制引入。用小／较大合成集合的 SQL 诊断证明查询次数不随记录线性增长。
- 来源初始化已有“本次整理既有登记、未重新核验”说明，本轮不改写其历史日期为原始取得日期。

### F. 部分日期筛选（#46 的独立子任务）

- YYYY、YYYY-MM、YYYY-MM-DD 各代表真实可能日期区间，按与查询区间相交判断；完整日期按其当天判断。
- 覆盖闰年、年月边界、单边筛选、无日期／非法日期、反向范围及过滤导出一致性；不以查询时刻补全年月。
- 本轮保持现有发表时间入口，双时间轴、快捷窗口及分面看板继续由 #46 后续细化。

### G. DeepSeek 单篇辅助翻译（#46 的独立子任务）

- 成员显式触发一篇外部资料的中文译题／摘要任务。界面说明仅发送该篇题名和摘要；不发送正文、附件、人物私密信息、账号或凭据。
- 服务端使用环境变量配置 API key、base URL 和 model，凭据只留运行环境，日志、数据库、备份和前端均不含密钥。默认使用官方 HTTPS 服务；自定义端点需要可信配置和相同超时／大小／错误处理边界。
- 持久化任务状态及输入版本／摘要，执行有界请求、重试和幂等保护；可提供明确的后台 worker 命令和单篇执行入口，不因网页 GET 自动调用付费接口。
- 机器版本独立于人工正式字段，保留原始输入、译文、模型、生成时间及失败原因。缺摘要时只译题，不从题名编造摘要或核心发现。
- 提供原文／机器中文对照和明确“采用”操作，采用遵循编辑权限、最新版本和人工优先规则；重新生成只新增机器版本，不覆盖已采用或后续人工编辑内容。源记录变化时提示结果过期，并拒绝静默采用。
- 导出包含当前有权读取的译文及来源说明；完整备份／恢复保留任务和版本，但不携带运行凭据，也不自动重放付费任务。
- 不自动创建或确认人物身份、任职、文章单位、研究对象国或专题关系。

## Testing Decisions

- 沿用公开 HTTP 边界做逐个 red→green 验证，覆盖身份、权限、冲突、历史、导出与失败原子性；不以私有函数返回值或同一算法重算预期自证。
- 用独立 ZIP 校验 CLI 及固定篡改样本检查附件交叉引用。用完整备份／新目录恢复及旧版本夹具验证升级，升级前保留备份。
- 真实浏览器分别在 1366px 和 390px 验证新增入口、表单、冲突、晚到响应及阅读；使用合成研究材料。
- DeepSeek／来源站点只在外部 HTTP seam 模拟超时、失败及固定响应；真实 API 冒烟仅发送合成标题／摘要，不能据此宣称真实研究译文质量已验收。
- 完成后运行仓库完整检查，并由独立 Standards／Spec 只读子代理对同一固定基线与提交审查；发现集中交给一位修复代理，再由 merger 集成和原审查者复核。

## Out of Scope

- #46 的全来源自动巡检、持续更新、全文下载、自动身份确认、研究对象自动归类、导航改版和情报首页。
- #36 的标准格式文件交换闭环；#40 的 Windows 耗时优化（如实际阻塞本轮检查，再独立核查）。
- 真实数据库批量改写、内部资料外传、正式部署、多人研究质量验收或自动生成论证结论。
