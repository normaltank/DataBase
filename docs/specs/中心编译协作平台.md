## Problem Statement

中心的主要积累是自己形成的选题材料、编译稿、审稿意见和成品。研究员按负责国家优先寻找本地期刊、智库等信源，围绕当期主题在个人设备上按固定格式编写候选选题报告。选题会上决定采用文章，研究员继续本机编译，负责人审稿，最终一般还会形成整期汇总。期刊编译则是独立业务，按期刊、原刊卷期或覆盖范围形成概览成果。

现有资料库可以保存独立报告及附件，但没有串起负责人开期、参与者交接、会议决定、审稿返修和采用版本。仅提供新文章列表或成果上传，会丢失过程及交接关系；把外部资料逐篇入库作为提交前提、要求把Word模板重填成网页表单，又会增加研究员负担。改版需要先准确承接这两条日常工作线，再让外部资料基础设施为其提供检索和出处支持。

## Solution

提供一个编译协作入口，明确区分主题编译与期刊编译；研究员优先看到自己参加的工作，负责人看到自己负责的工作及已有提交状态。中心成果入口继续提供独立成果和历期定稿的查阅，资料检索、来源档案及自动采集保持可达。

主题编译：负责人开启一期并确定参与者 → 研究员本机写好候选选题报告后上传 → 同期参与者查阅 → 负责人记录选题会决定及编译分工 → 提交编译稿 → 负责人退回或确认定稿 → 保存各国定稿及实际存在的整期汇总。每次交接从发生时留档，汇总对应实际采用的各篇稿件版本。

期刊编译：围绕期刊及原刊卷期或覆盖范围单独保存工作材料、修订和成果，可复用文件及版本留档能力；不挂靠主题选题，不强制走主题候选和会议阶段。沿用其适用的既有内容责任及可见范围，不从主题参与者规则推导新的期刊权限。

正文、选题报告和汇总均在成员自己的设备上编写。平台保存提交原件、交接和决定；文章来自平台外、题录缺项或原文尚未入库，不妨碍交稿。新功能不依赖付费AI、采集已经收全或逐篇自动识别报告内容。

## User Stories

1. 作为管理员，我希望登记成员的负责人资格，使实际负责人能够发起主题编译，而普通成员不因看见按钮就取得组织权限。
2. 作为管理员，我希望因维护需要查阅各期工作材料，同时不因此获得审稿、确认定稿或改写作者正文的权限。
3. 作为负责人，我希望建立本期主题、参与研究员及可选提交时间，让成员找到自己参加的工作。
4. 作为研究员，我希望进入平台即可找到自己参加的主题编译和有权访问的期刊编译，看到当前材料及交接状态。
5. 作为负责人，我希望看到各参与研究员已经提交什么、哪些稿件在待审或返修，不另维护一张平行进度表。
6. 作为研究员，我希望在自己电脑按原模板完成选题报告后直接上传，不在平台重填摘要、关键词及作者介绍。
7. 作为研究员，我希望平台自动记录所属工作、提交人、时间和文件版本，只补实际缺少的必要说明。
8. 作为研究员，我希望可使用平台内文章或自行找到的站外文章，交稿不以前置逐篇入库为条件。
9. 作为研究员，我希望在来源尚未完整登记时先保留题名、链接、报告中的项目位置或其他出处线索，之后补齐资料关联。
10. 作为参与者，我希望在选题会前查阅本期其他研究员已提交的选题报告，便于提前比较候选。
11. 作为提交者，我希望重新提交形成新版本，之前的原件、提交时间和说明继续可查。
12. 作为提交者，我希望超时或重复点击不会产生重复交接；保存失败不留下半份文件或错误完成状态。
13. 作为负责人，我希望把实际会议决定、采用文章及编译分工保存在本期档案中，不要求把会议重新走成一套在线审批。
14. 作为负责人，我希望采用文章可以引用选题报告中的某项及已有出处，不因资料尚未入库而无法记录决定。
15. 作为研究员，我希望会议决定后找到自己的编译工作，继续在个人设备编写并提交稿件。
16. 作为参与者，我希望查阅本期已提交的编译稿、退回意见和修改版本，同时不取得修改他人原件的权限。
17. 作为负责人，我希望针对具体提交版本退回修改，保留审稿文字或批注文件。
18. 作为研究员，我希望看清哪一版被退回、需要修改什么，再提交新版本；之前的决定和意见继续保留。
19. 作为负责人，我希望确认具体一版为定稿，并能追溯确认人、时间与所据文件。
20. 作为使用者，我希望新上传不会自动继承旧版的定稿结论，过期页面的审稿请求也不会认错稿。
21. 作为作者，我希望负责人审稿和管理员维护查阅均不改变个人报告的作者授权。
22. 作为负责人，我希望保存整期汇总文件，并明确它采用了各国文章的哪些定稿版本。
23. 作为复用者，我希望某篇后来更新后，已归档汇总的采用记录仍对应原版，能够核对实际使用的文件。
24. 作为研究员，我希望没有整期汇总时，各篇已形成的定稿也能独立保存和复用。
25. 作为读者，我希望一期档案可以追溯过程，成果入口优先呈现已确认的成果，详细历史按需展开。
26. 作为期刊编译者，我希望按期刊及卷期或覆盖范围保存独立工作，不被要求选择中心主题或经过主题选题会。
27. 作为期刊编译者，我希望期刊原刊日期、中心编译时间和主题编译的期次分别表达。
28. 作为期刊编译者，我希望可先提交整体Word或PDF及必要出处，不强制完成年度指标、独立目次或逐篇资料登记。
29. 作为期刊编译者，我希望已有期刊身份及成果可以继续复用，未明确的期刊信息允许留为线索后补。
30. 作为期刊读者或贡献者，我希望目录译稿的既有共编和个人报告作者授权继续适用，不因新增工作入口而改变权限类别。
31. 作为成员，我希望有权访问的成果能往返其所属工作；过程文件的可见范围不因成果关联而扩大。
32. 作为老用户，我希望独立报告、跨期目录译稿、笔记、附件、原文关联与历史仍可查，不必重新上传或强行挂靠新一期。
33. 作为成员，我希望按业务类型、主题或期刊、国家分工、参与人及时间查找中心工作和成果，不被外部资料列表淹没。
34. 作为使用者，我希望保存冲突时保留已选文件和说明，读到最新状态后能够继续提交。
35. 作为维护者，我希望资格撤销、账号停用和名单变化后，各入口、下载、搜索及导出重新检查权限，历史材料仍保存。
36. 作为复用者，我希望可以下载有权访问的一期材料包，包含原件和清单，并看出包含哪些过程、成果及采用版本。
37. 作为管理员，我希望完整备份恢复到新目录后，负责人资格、参与者、原件、审稿决定和采用版本关系仍然一致。
38. 作为研究员或负责人，我希望桌面、手机窄屏和放大显示均能完成找工作、交文件、审稿和返回，不靠缩小文字取得密度。
39. 作为复核者，我希望软件检查、模板结构核对和真实跨人接续分别报告，不将模拟任务通过写成中心已正式使用。

## Implementation Decisions

### 两条业务与共同保存能力

- 主题编译和期刊编译各有稳定工作身份及适用的归属信息。共用文件保存、提交版本、审稿材料和成果关联，不共用一套强制业务阶段。资料夹保持轻量收集用途，不被改造成业务工作流。
- 一期主题编译保存主题、负责人、参与者和可选提交时间；国家表示研究分工，不能替代文章实际研究对象，也不能据此禁止使用其他来源的文章。不固定一国一篇或一人一国。
- 期刊编译保存适用期刊、原刊卷期标识或覆盖范围；已有期刊用原身份，未建档时保留已知名称和出处线索。原刊卷期与中心工作编号分开，不从文件名、旧封面或日期猜测来源身份。
- 每份提交记录所属工作、材料类型、提交者、时间、说明和不可变文件身份；阶段由实际提交及决定形成，不要求成员重复填写一套进度。提交原件与最终成果分别有明确关联。
- 新建的业务规则与已有内容编辑、可见范围、身份及原文引用规则衔接，不能用当前程序的默认权限补作新的业务决定。

### 业务角色与读取边界

- 管理员登记负责人资格，资格与系统管理员角色独立。具有有效资格的成员发起主题编译并担任当期负责人，确定参与研究员；普通参与者不能发起或代行负责人审稿。管理员若需要履行业务职责，也须具备相应资格并是该期负责人。
- 管理员可因维护查阅各期工作文件。此权限不允许其代替负责人审稿、退回、确认定稿，也不允许改写受作者授权保护的正文。
- 主题参与者可读本期已经提交的选题报告、编译稿、退回意见及修改版本；查阅权限独立于编辑授权，不能用编辑者名单代替参与者名单。个人设备上尚未提交的内容不由平台自动同步。
- 原件历史提供按工作及提交版本核权的只读入口，不以恢复旧版本或取得编辑权作为下载历史稿件的前提；不直接放开全库历史或沿用当前附件列表冒充全部历史。
- 操作时重核账号有效状态、资格、当期职责、参与关系、文件归属和最新版本。名单或资格变化保留历史贡献和审计，不删材料；作者对个人报告已有的权限继续适用。
- 期刊编译按既有目录译稿共编、个人报告作者授权和当前可见范围保存，不自动取得主题参与者互查规则，也不要求先建立主题负责人审批流程。实际审稿文件可以保存，不凭一份文件冒充已执行主题审核。
- 关联原文、旧成果及其他期次分别核权。工作材料可读，不等于其关联的受限原文可读；检索、计数、下载和导出均保持同一边界。

### 会议、审稿与版本采用

- 会议决定可以保存已有会议材料及简短决定，采用文章和分工可通过报告某项、题名或出处线索表示；库内关联可选，不重填整份报告，也不自动把报告中的全部候选当作入选。
- 编译稿提交、负责人审稿和正式采用分别记录。审稿的退回、意见及定稿都绑定实际提交版本，要求当前工作状态与版本相符；冲突返回可理解信息，并保留用户输入及已选文件。
- 审稿结论不复用外部资料的“已核对”标记。新上传保留旧版决定，但不自动获得旧版定稿结论；同一请求幂等，重复或过期的定稿请求不能覆盖另一版。
- 整期汇总保存实际文件，并列明采用的各国定稿及其具体版本；关系有审计、可导出和恢复。原文、单篇稿件或汇总后来更新，不静默改写旧汇总的采用记录。
- 汇总通常存在，按实际提交保存；没有汇总不阻止已形成的单篇成果留档。文件编排和合稿仍由成员在本机完成。
- 定稿进入或关联现有成果身份，沿用负责作者确认、可见范围与编辑授权；确认定稿不自动扩大共享范围或冒充负责作者。已有独立成果可继续独立存在。

### 文件、界面与技术接缝

- 保留当前服务与数据存储，新增清楚的协作业务接口及前端模块。复用已验证的文件格式、大小限制、原件校验、事务、乐观锁及失败文件清理机制；网络或文件保存失败时，不出现有决定无原件的半份交接。
- 附件存储名与用户文件名分开，历史原件不可覆盖；同一交接请求重复提交不新增逻辑版本。文件内容相同也不能因此吞掉用户明确提交的新说明或决定。
- 编译协作入口区分主题与期刊工作，提供“我参与／我负责”的工作范围。主题详情集中呈现本期信息、选题材料与会议决定、稿件审阅与成果，版本历史就地展开。资料检索和档案继续可达，不把原有资料能力判成无用功能。
- 文件提交自动带入当前工作、提交人及时间，必要说明简短填写；题名、摘要、关键词和作者介绍不重复录入。模板读取、正文识别或自动关联均非交接前置。
- 成果查阅能按业务类型、工作主题或期刊、研究分工和时间定位；过程档案与定稿展示分层，使用同一稳定身份及授权。旧报告、目录译稿、笔记和文件保留原访问及导出路径。
- 提供按权限生成的可读材料包，含文件清单、原名、版本、决定和采用关系，必要时可明确选择成果或过程材料范围。导出缺项及覆盖范围如实说明，不能把未导出的内容宣称为完整档案。
- 新数据结构以增量迁移加入既有链条；完整备份包括协作原件及历史引用文件，恢复校验包含负责人资格、参与者、文件归属、审稿与采用版本关系。旧库、附件、身份和历史保留，不要求重建资料库。

## Testing Decisions

沿用已授权的公开HTTP、实际浏览器、隔离合成来源或文件及新目录备份恢复边界。测试用户能观察的交接、读取、决定和恢复结果，不镜像内部表结构或仅证明按钮存在。建设不使用真实研究库、内部稿件、真实付费AI或8848端口，不重新遍历ThinkTank。

1. 以至少两期主题、多位研究员、当期负责人、非参与者和仅有系统管理角色的账号验证资格登记、开期、参与者互查、维护查阅及越权审稿被拒绝。覆盖直接访问文件和历史地址、串期、资格撤销及账号停用。
2. 通过公开接口完成Word候选报告上传、多版本原件下载、重复请求、超时重试、格式或大小失败及事务末段失败；比对独立合成文件字节，失败不留半份事件或破坏旧原件。
3. 从尚未入库的站外文章记录选题会采用及分工，完成编译稿提交、退回、再交、定稿；验证过期版本冲突和相同请求幂等，负责人或管理员没有作者授权时不能改写正文。
4. 保存各国定稿及整期汇总，更新某篇后独立核对旧汇总仍采用原版；导出清单及恢复后的文件哈希、审稿决定和版本关系一致。
5. 独立完成期刊编译文件保存、修订和成品查阅，无主题或选题会前置；覆盖已登记期刊、只知道名称出处、跨期范围、目录译稿共编及个人报告未授权者，沿既有权限验证。
6. 实际浏览器在1366px、390px及200%放大下完成负责人开期、研究员交稿、同伴只读历史、审稿返修、定稿汇总、期刊留档及成果往返；核对键盘操作、长文件名、冲突保稿、空态和全页横溢。
7. 以当前合成结构19及适用旧版本库执行增量迁移前备份；生成完整备份恢复到不存在的新目录，再通过HTTP查阅历史原件、角色和采用关系。缺文件、错误哈希、无效归属或悬空采用版本应拒绝恢复，并保持原目录不变。
8. 导出及独立读取核对文件清单和采用关系；无权限材料不进入结果。旧独立报告、跨期译稿、笔记、引用和附件继续可读可导出，不依赖补挂新工作。
9. 复用既有报告授权、记录修订、附件、内容包及恢复测试作为回归入口；每个纵切交付受影响验证及页面证据，全部集成后执行完整合成检查、双系统CI和固定基线独立Standards／Spec审查，统一返修再复核。
10. 用户模板只在已授权单文件范围内核对材料结构，不复制正文、人员样例或附件到公开仓库。合成流程通过不证明真实中心已接续使用，正式试用应另由研究员和负责人实际完成一次交接并留证。

## Out of Scope

站内Word／PDF写作或编辑器、在线合稿、报告生成器、强制逐篇拆解Word、默认将内部稿件送第三方AI、OCR全覆盖、聊天会议系统、邮件或日历自动催稿、人员排名、自动替代选题会决定。

不把期刊编译归为主题编译；不将期刊年度指标、完整卷期目次、全来源采集、身份研究、付费全文取得或综合影响力评价并入本版。原有自采集及期刊设计中的未交付任务保留真实状态，按业务优先级另行调度，不静默关闭。

不以本地开发通过作为正式部署。真实库升级仍须最终备份、新目录升级恢复演练和实际运行核查；历史备份恢复成功不替代新版本预演。
