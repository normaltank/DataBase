## Problem Statement

研究员已经找到文章，却仍需逐项抄写题名、作者和出处，再寻找对应档案。用户希望提交一个文章链接或 DOI 就能减少登记工作，也担心这与通用爬虫一样难以维护。基础资料管理第一批已经交付，本轮补齐单篇收集环节，不把整个 Zotero 功能集当作既定交付范围。

## Solution

在提交外部资料时提供“粘贴 DOI 或文章链接 → 识别并填写 → 核对保存”的入口。取得成功即补入空白基本字段，研究员可直接修改；身份与来源候选作为可选步骤核对，未确认也可保存原始署名。题名等基本信息优先展示，低频信息放入“更多信息（选填）”；缺失或取得失败时保留输入、继续手填。第一版以 DOI 的公开元数据服务、标准文章网页标签及有限试点网页为基础；发布时列明实际验证的范围。

## User Stories

1. 作为研究员，我希望输入裸 DOI、DOI 链接或文章网址，以便从已找到的文章开始登记。
2. 作为研究员，我希望提取期间看到状态并能继续人工处理，以免网络等待阻断录入。
3. 作为研究员，我希望题名、原始署名、发表日期、刊名、DOI、网址和摘要按实际取得情况预填，以便减少抄写。
4. 作为研究员，我希望缺失字段保持缺失，清楚知道哪些信息来自页面、注册元数据或我的修改，以免把推测当事实。
5. 作为研究员，我希望不同依据冲突或只有低可信页面标题时得到说明，并可在保存前修正。
6. 作为研究员，我希望原始署名、作者顺序及取得的 ORCID、ISSN 等标识保留，以便以后核对身份和出处。
7. 作为研究员，我希望 DOI 网址前缀、大小写等常见写法被识别为同一编号，看到自己有权查看的重复条目并能直接打开。
8. 作为研究员，我希望没有 DOI 时也能按文章网址提示已收录资料，普通姓名或相似题名只能作为线索。
9. 作为贡献者，我希望系统优先通过已有标识或明确来源线索提示期刊、发布机构及作者候选，候选说明匹配依据。
10. 作为贡献者，我希望明确核对并选择关联后再保存；拿不准的署名仍可作为待确认署名保存，不自动计入人物已确认作品。
11. 作为贡献者，我希望未匹配到档案时仍能保存题录，保留刊名和署名，后续使用已有维护流程补建档案。
12. 作为维护者，我希望出版商、期刊主办方、文章发布机构及文章署名单位分别理解，提取不会推定任职、机构隶属、来源国别或国际定位。
13. 作为编辑者，我希望取得成功即补齐空白基本字段，已有手填内容在重复提取、失败、请求晚到或保存校验失败时仍保留；需要替换已有值时由我明确选择。
14. 作为成员，我希望关闭或切换账号后旧请求不会把结果写入新表单，草稿恢复后仍能理解和处理已提取内容。
15. 作为贡献者，我希望预览不创建正式资料或档案，确认保存把资料、署名关联及取得依据一起保存，失败不会留下半份记录。
16. 作为共同维护者，我希望保存后能查看取得来源、时间和原始题录依据，后续修订、历史、导出与完整恢复保留这些依据。
17. 作为成员，我希望提取失败、站点限制访问、超时和不支持的输入得到可操作反馈，可以继续手填原链接。
18. 作为键盘或窄屏使用者，我希望提取、核对、选择关联、返回和保存都可操作，长标题和多位作者不遮挡主要按钮。
19. 作为成员，我希望网络提取不暴露本机文件、内部网络、账号凭据或我无权查看的资料；网页内容作为数据处理。
20. 作为使用者，我希望知道本次只取得题录，全文、附件及人工核对状态不能由“提取成功”推定。
21. 作为贡献者，我希望未选身份、未核对身份或未找到档案不会阻止基本信息填写，身份问题在相应操作附近提示并可定位。
22. 作为首次提交者，我希望先看到题名、作者、日期和出处，按需展开正文、附件及更多信息；已知题名即可开始保存，不需为了填满表格猜测缺项。

## Implementation Decisions

- 复用现有单篇资料、来源与人物身份、原始署名、人工确认及资料修订边界。一个完整流程交由一个实施任务完成；不拆出先交付但无法保存的独立爬取服务。
- 提取与正式写入分开。服务器返回可核验的取得依据和草稿；保存时校验归属、当前对象及权限，将题录和显式确认的署名关联原子写入。未经确认的作者不成为已确认作品；不自动创建或合并档案。
- DOI 优先使用 Crossref，适用时回退 DataCite；文章页优先读取 citation 元标签和 Article／ScholarlyArticle 的 JSON-LD，只有页面标题等信息时明确降级。有限试点按原站抽样选择必要适配，不对任意网站作成功保证。
- 统一 DOI 常见表示用于预览防重与最终保存防重，兼容已有记录而不批量改写真实库。网址规范化保持文章身份，不能随意删除具有意义的查询参数。重复检查遵守可见权限；不能借候选或错误信息泄露私人题录。
- 取得的外部标识和原始题录按来源持久保留，候选匹配可使用明确存在的对应关系。首版不要求建设覆盖所有人物和机构的外部身份注册表；任何姓名或机构名称匹配都需要用户核对，标识也不替代人工确认规则。
- 网页发布商、网站名称和作者单位作为有出处的线索保存，不能自动填成期刊主办机构或人物任职。若已有来源官网对应可提出发布机构候选；同一出版社下的期刊须有更具体依据。
- 提取结果直接补入空白基本字段并保留原始署名、取得依据；已有人工输入保留。候选关联明确选择并核对后才成立，相关错误不撤销已补入的基本信息。重复请求、输入切换、旧响应、关闭、草稿恢复和表单失败均保留已有工作；主要反馈紧邻当前操作且可由键盘定位。
- 表单按基本信息、正文与附件、更多信息逐步展开。保留全部原有录入能力，以用户理解的字段名和必要说明呈现；沿用蓝白柔黄主题，不增加填写门槛。
- 外部请求限公开 HTTP(S)，限制时间、大小、重定向和内容类型；每次连接和跳转检查网络目标，防止绕过本机／内网限制。提取不携带浏览器账号凭据，不执行网页脚本，不自动下载附件。
- 优先复用现有持久化和备份结构。新增结构如确有必要须有兼容迁移与恢复验证；既有资料编号、历史、引用和权限保持可用。未来批量采集可复用提取结果边界，本次不建立空的调度或插件框架。

## Testing Decisions

- 沿用已授权的应用公开 HTTP、导出／恢复和实际浏览器边界；先失败再实现。网络供应方采用可控的合成响应验证成功、缺失、冲突、限流、失败及恶意页面；网络适配的公开边界另验证实际目标限制，不能以全量替换安全函数的模拟测试证明安全。
- 通过 HTTP 验证提取不写正式数据、规范化防重、可见权限、来源类型、人工署名确认、无依据保留待确认、保存失败回滚和重复提交。通过公开详情／历史／导出及新目录恢复确认依据可继续使用。
- 浏览器验证输入、取得后实际字段、查看依据、核对候选、修改、保存及打开新资料；覆盖未确认身份仍能保存、错误就近提示、手填值保护、输入切换、无 DOI 网页、失败手填、重复处理、旧响应、草稿、键盘及 1366／390 像素宽度。额外用用户提供 DOI 对照实际服务返回，不将单样本成功推广为站点覆盖率。使用隔离的合成资料和测试端口，不将测试记录写进真实库。
- 额外抽查少量官方公开页面与 DOI 响应，逐字段比较原始输入、提取结果和缺失；注明抽样日期和失败，不从少量成功样本推导覆盖率。软件验证、原站抽查与真人研究复用分别报告。
- 完成针对性验证后运行一次完整检查；再分别进行 Standards 与 Spec 独立审查。主服务切换前备份、核对真实表与附件，禁导入启动并验证版本和数据保全。

## Out of Scope

全站持续爬取、RSS 调度、历史回填、付费或登录页面绕过、全文及附件自动下载、OCR、机器翻译、影响力评价、自动确认身份、新权限模型、所有编号类型和完整复制 Zotero。既有体验问题另由其 Issue 跟踪，不因本轮辅助录入而宣称全部基础数据库建设完成。

## Further Notes

本轮没有需要重复 Grill 的业务分歧。取得信息的真实性仍需研究员核对，平台保留依据供纠错；实际站点支持及验证限制随交付记录。前期官方资料与已知局限见[可行性调研](../../work/链接与编号辅助录入可行性.md)。公开测试使用合成题录，不上传真实库、附件或内部材料。
