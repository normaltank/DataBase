# 便携试用入场与多选操作维护

版本：1.0；日期：2026-11-03。状态：依据用户本轮明确要求冻结，待施工与验证；任务状态以 GitHub Issues 为准。

## Problem Statement

用户实际校园网试用时，需要记忆账号和自行设口令；配置又停用了默认研究员，开启主题的参与人列表因此空白，页面没有解释。采集只支持逐项保存，保存一项会丢失其他未保存配置。其他现有多选还存在隐藏选择、刷新覆盖、重复排队和不可分工成员仍可选等真实问题。上一轮视觉及软件验收没有覆盖完整入场与选择流程，不能作为这些流程可用的证据。

## Solution

便携试用默认让新浏览器自动获得可识别的临时体验身份，直接进入平台；同一浏览器刷新、返回和正常重启复用身份。访客可以开自己的练习主题、选人、交材料，并查看保留原负责人和作者的既有演示样例。正式部署继续使用原账号规则。

采集与既有多选流程提供明确范围的选择、全选、清空、已选数和批量执行；保存、刷新、失败及重试都保留正确的用户意图。既有蓝白 Operate 工作台风格保留，界面以真实任务完成情况验收。

## User Stories

1. 作为校园网试用者，我首次进入即可取得独立临时昵称，不必注册或输入演示口令。
2. 作为回访试用者，我刷新页面、切换功能或主机正常重启后继续使用同一浏览器身份。
3. 作为共同试用者，不同浏览器分别获得身份，提交者、负责人和各自操作能区分。
4. 作为体验者，我可辨认自己的临时身份，并以简单入口调整显示称呼。
5. 作为体验者，我有开启练习主题所需的试用业务资格，创建后能选择参与人、提交材料和接续工作。
6. 作为当期负责人，我看到有效成员、已选数量和自己的自动参与；可搜索、全选当前可选范围、清空并刷新新入场成员，刷新保留已选。
7. 作为唯一入场者，我得到明确的空态解释，仍能单人开期；不会把空列表误解为坏掉的选择控件。
8. 作为新访客，我能查阅明确标记的旧演示样例，并知道如何创建自己的实践；旧作者、负责人和历史决定不会被替换为我。
9. 作为资料管理员，我能批量选择支持采集的来源并启用、停用、保存配置或安排巡检，清楚看到操作范围和逐项结果。
10. 作为资料管理员，我保存某一来源后，其他来源未保存的设置仍保留；失败项可保留后重试。
11. 作为批次操作人员，我在搜索、筛选或翻页后仍能看清全部已选，包括当前不显示的条目；全选范围和后端数量上限明确。
12. 作为排队人员，我双击提交或在响应丢失后重试同一内容，不会创建重复任务；成功和失败反馈能对应到实际条目。
13. 作为候选核对人员，我刷新过程中做的新勾选不被旧响应覆盖；未选择时采用／拒绝按钮不可误提交。
14. 作为负责人，不可分工的成员不可被选中或默认提交，原因在填写前可见。
15. 作为键盘或触屏使用者，我不用 Ctrl 才能多选，能操作复选框、读到数量变化，并在窄屏和缩放下完成任务。
16. 作为主机使用者，我保留当前资料、账号、资格、交接历史、文件、AI账本和端口；新试用入口不重播种或重置已有库。
17. 作为主机使用者，我可在本机管理演示及AI配置；远端临时访客不会自动取得系统管理、密钥或费用配置权限。

## Implementation Decisions

- 试用入场仅由便携运行明确开启。普通生产应用默认关闭，正常账号及数据授权边界继续生效。
- 临时体验身份以浏览器会话／持久Cookie识别，不用校园网IP冒充个人；自动取得试用研究员能力及开期资格。页面展示其临时性质，保留独立审计归属。
- 普通试用与新包LAN启动不再要求访客口令。主机维护入口单独处理；保留既有自设账号、密码和停用状态，不统一改写旧身份。付费AI保持明确启用及统一预算边界，本轮不新增真实付费请求。
- 旧演示样例供新访客明确查阅，新实践由访客自行开期；不接管旧负责人／作者、不伪造旧参与或决定。正常成果及私人内容权限不因普通生产请求变化。
- 选择范围、隐藏选择、可用性和数量上限在操作前可见。全选只覆盖标明的可选范围，不能悄悄截断或带上不可操作项。
- 所有批量操作真实调用已有业务边界；能复用现有接口时不另造通用批处理平台。成功项与失败项分别反馈，保留草稿与待重试输入。
- 排队提交在请求期间防重；同一请求的未知结果重试复用幂等标识。刷新按返回时最新用户选择处理，不恢复旧快照。
- 两份包基于同一最终提交重建。对当前桌面试用副本的最终更新需先核实版本和备份，保留数据、控制状态、主机凭据路径及端口；不更新运行库路径来反复触发防火墙提示。

## Testing Decisions

- 优先现有认证HTTP、持久业务状态、原生启动及真实浏览器公开入口；测试完整行为，不以函数返回HTML或截图替代可提交的流程。
- 使用隔离合成库，复现LAN停用默认成员后的空选择、新访客、两种独立浏览器身份与主机维护边界；普通生产匿名请求仍被拒绝。
- 真实浏览器验证：自动入场→开期→单人空态→第二身份入场→刷新选择→多选提交→参与者上传与负责人接续，并核对实际保存成员和作者。
- 采集测试多项未保存配置、批量启停／巡检、部分失败后重试、保留其他草稿；网络与供应商用受控响应。
- 来源／作者批次及候选核对测试搜索和隐藏选择、全选／清空／上限、连击、响应丢失、刷新等待中新选择；核对HTTP请求和持久任务数。
- 桌面、900、390宽度、键盘和200%缩放检查交互、可读性、焦点、溢出、错误后输入保留。所有新增发现由同一统一返修流程闭环。
- 集成后必要完整CI、独立两轴审查、同提交发布包和单一稳定路径原生便携验收。旧通过只保留历史范围，不升级为本轮通过。

## Out of Scope

- 正式部署的免登录、统一身份平台、访客注册审批、硬件指纹或自动清理研究资料。
- 新研究功能、扩展采集源、全文/PDF能力、真实收费实验，以及关闭防火墙或校园网策略修改。
- 改写真实研究库、ThinkTank、既有凭据；以刷新全部页面或删除旧历史替代正确维护。

## Further Notes

用户已明确要求免登录临时身份及深度交互维护；本轮沿用公开接口、真实浏览器和恢复验证边界，不重复索取已授权实施步骤的批准。独立初查排除了“参与框强制单选”和“来源API只返回第一页”的猜测；以合成复现和实际浏览器为准。角色标签、主机入口及可读样例必须与实际权限一致。
