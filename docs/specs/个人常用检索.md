# 个人常用检索

版本：1.0。日期：2026-10-26。状态：在用户“继续按计划，完善基础的数据库功能”及继续内化 Zotero 的授权下，已集成并完成本地验证；[验收记录](../../work/常用检索与资料工作流验收.md)区分开发和独立检查，最终交付状态见 [#34](https://github.com/normaltank/DataBase/issues/34)／[PR #35](https://github.com/normaltank/DataBase/pull/35)。固定施工基线：`7203d87c72bb9cd50b9e9c0a6c31b9d126e2e803`。需求出处见 [R018](../需求讨论记录.md#r018继续内化-zotero-的基础资料管理)，业务权限沿用 [PRODUCT](../../PRODUCT.md)。

## Problem Statement

研究员反复围绕相同主题、国家、来源和资料类型查找资料，目前只有当前地址保留查询条件。离开后需要重新组合条件，收藏或专题又不能表达“今后新增且符合这些条件的资料”。用户要求继续内化 Zotero 的基础管理能力，不能只把前两项体验修复称作新功能建设。

## Solution

资料库提供“保存检索”及“我的检索”。成员为当前查询命名，之后可重新打开、改名、用当前条件更新或删除。保存的是条件，每次打开使用现有资料查询和当前账号权限计算结果。专题继续表示成员整理的资料集合，保存检索作为个人设置，与专题并存。

## User Stories

1. 作为研究员，我希望给当前检索命名，以便下次继续使用同一组条件。
2. 作为研究员，我希望关键词、类型、来源范围、来源、语种、研究对象、核对状态、日期、专题及排序中实际生效的条件都能保留，以免再次打开得到含义不同的查询。
3. 作为研究员，我希望在收藏、编译成果或待核对列表保存时保留其隐含条件，以免保存后扩大查询范围。
4. 作为研究员，我希望重新打开从第一页显示当前结果，新收录及不再符合条件的资料如实增减。
5. 作为研究员，我希望在检索较多时按名称查找，看到条件摘要，理解打开的范围。
6. 作为研究员，我希望明确操作后将当前条件更新到某份已保存检索，或另存为新的检索。
7. 作为研究员，我希望改名及删除只影响自己的工作设置，删除前能确认对象，原有资料、收藏及专题不受影响。
8. 作为成员，我希望不同账号的检索设置相互隔离，包括列表、读取、改名、更新及删除；管理员身份不增加代改此个人设置的能力。
9. 作为成员，我希望结果每次重新遵循资料及专题权限；保存检索本身不复制资料或授予权限。
10. 作为研究员，我希望关联专题或来源失效、无权访问时得到明确说明，保留原条件供我调整，不静默清除该条件再搜索整个资料库。
11. 作为研究员，我希望多人终端、快速切换检索和慢响应不会混入另一账号或较早请求的内容。
12. 作为编辑者，我希望切换检索沿用已有草稿保护，不丢掉未保存正文；保存检索对话框失败时保留名称输入。
13. 作为研究员，我希望同名、空名、无效条件和过量输入得到明确反馈，不默默覆盖另一份检索。
14. 作为成员，我希望多窗口同时修改同一份检索时能发现冲突，保留输入而不覆盖较新的设置。
15. 作为维护者，我希望升级保留现有资料，完整备份恢复后个人检索及其归属仍可用；旧备份恢复后可继续创建检索。
16. 作为键盘和窄屏使用者，我希望保存、查找、打开和管理检索都可操作，名称和条件较长时仍能看到主要按钮。

## Implementation Decisions

- 复用现有资料查询边界，服务端保存账号归属、名称、白名单条件及并发修改版本。条件以有效查询含义保存，不存页码、当前勾选项、结果快照或任意 URL。
- 复用资料查询实际支持的条件；列表隐含范围先转成明确条件。重新打开进入资料库第一页，并显示实际过滤范围。任意未知参数不能成为执行指令或使结果扩大。
- 当前账号专有的检索管理接口负责校验、归属及冲突；结果仍通过现有权限查询读取。保存设置不产生资料修订或研究证据。
- 以有界、可搜索的管理列表应对长名单。更新条件、另存、改名和删除为清楚的不同动作；输入失败及冲突保留当前输入。
- 关联对象合并时沿用已有旧编号解析；不存在或无权访问时保留检索并提示调整。首次加载或刷新以持久化条件为准，响应迟到和切换账号不能污染当前页面。
- 必要的数据库升级必须幂等；完整备份保留个人检索，旧备份按支持的版本升级。研究内容导出仍以研究资料为边界，不附带个人检索设置。

## Testing Decisions

- 沿用已获授权的验证边界：公开 HTTP 接口验证保存、查询、权限、冲突；完整备份恢复后通过公开接口继续使用；实际浏览器验证用户操作、草稿保护、窄屏和键盘。无需新增内部测试边界。
- TDD 按完整行为逐项红绿推进，使用独立的合成账号、资料、来源与专题。动态结果测试在保存检索后新增或修改资料，不能只比较保存前后的 JSON。
- 验证账户隔离、CSRF、无效参数、同名、同时修改、失效范围、收藏及其他隐含条件、慢响应与账号切换。备份测试包含当前版本及升级前版本；既有记录和附件不因升级改变。
- 集成后固定基线执行独立 Standards／Spec 审查及全套已有检查。本轮软件验证不代表真实研究员复用或研究结论已得到验证。

## Out of Scope

共享检索、通知或自动定时执行、布尔查询语言、相对日期、结构化主题标签、标准题录导入导出、全站采集、OCR、正式引文排版均不在本任务内。已有的专题、关键词、收藏、重复整理和证据引用继续使用，不以新概念替换。
