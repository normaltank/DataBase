## 初始 MVP 交付

在本项目中建设一个可启动、可保存数据的中文网页应用。用 ThinkTank 主资料库的真实来源和文献验证基础流程：登录 → 检索 → 看详情与出处 → 收藏/专题 → 提交资料或编译成果 → 关联原文 → 核对 → 修改历史 → 导出。

## 技术决定

- Python 3.12 + Flask 提供页面、登录和接口；SQLite 保存来源、文献、成果、关系、用户、收藏、专题及修订历史。浏览器使用原生 JavaScript/CSS，无前端编译和外部 CDN。
- 应用默认仅监听 127.0.0.1:8848；演示账号用于本机试用。本轮增补本机成员开户及凭据管理；正式联网部署、HTTPS 和运维另行实施。
- 来源、连续出版物、资料和成果保留稳定编号。机构所在地、来源研究覆盖范围、资料研究对象独立存储；没有依据的字段留空。
- 公共来源及目录译稿由有效成员共同修订。原始资料沿用提交者、授权同事及管理员维护；个人编译成果、研究笔记、研究报告采用负责作者确认及授权，不赋予管理员默认正文编辑权。核对由管理员执行。编辑后回到待核对状态，保留历史。
- 个人收藏和个人专题只对本人可见；中心专题及普通提交对登录成员可见。受限资料仅提交者、授权同事和管理员可见，接口、附件和导出执行相同权限。

提交者是上传记录的账号，未必是成果作者。2026-10-22 用户确认 R004 后，本轮将负责作者账号与提交者分开：本人提交直接确认，代交待作者本人确认；个人正文及恢复只允许作者与授权同事，调整授权和范围仅作者。旧个人成果需要显式确认／认领，不从提交者或管理员身份推定。署名 authors 独立于账号、上传者和最后修改人。

## 初始资料规则

只读使用 `D:\Agent Workspace\ThinkTank\PaperDatabase\LatviaResearchDatabase` 的四张主表。保留原始字段和校验摘要，不读取个人稿件及 Compile 编译目录。

- 64 条来源登记与 79 条连续出版物分别识别；目录入口、历史、候选及范围外条目保留标签，不称为全部已核实智库或期刊。
- 导入 `core_local_publication` 与 `extended_external_output` 的单篇资料；容器和范围外保留记录不进入默认资料库。
- 上游核验信息保留，但中心核对状态从“待核对”开始；不把上游校验直接当成中心审核。
- 已有附件仅记录官方链接及本地可用性，不批量复制和开放历史附件。上传者明确确认可在所选范围共享后，新上传文件保存在本项目。原始附件授权与批量迁移留到后续。
- 重复导入按原稳定编号跳过，不覆盖在平台内的人工修订。记录导入报告及原文件 SHA-256。

## 初始 MVP 完成范围

1. 中文工作台、资料列表和来源目录，关键词及组合筛选。
2. 原文与编译成果详情、来源关系、提交与编辑、附件上传下载。
3. 多篇原文关联、未入库出处说明、反向引用查询。
4. 待核对队列、角色校验、授权同事、修订历史与恢复。
5. 收藏、个人/中心专题、专题收集与 CSV 导出。
6. SQLite 持久化、管理员数据备份、恢复脚本和使用说明。
7. 关键权限、持久化、导出、导入与恢复自动验证，浏览器试用。

## 来源目录改进（2026-10-21—22）

按 [功能规格](specs/来源目录改进.md) 增加三类主要入口、机构类型筛选、期刊主办国别与国际定位、对象适用字段及有方向的机构关系。门户移到维护区，其他出版物和旧来源编号保留；没有全库重导、合并来源或改动权限。既有来源也可更正对象类型，服务端阻止破坏机构引用的转换。

数据库从结构版本 1 增量升级到 2，迁移前完整备份。新增类型、关系和依据与来源一起进入版本快照；反向关系及期刊国别动态计算，写入和历史恢复均在事务中验证关系约束。旧快照缺少新增字段时保留当前新增字段，避免历史结构缺项清空信息。修改国家或主办方而沿用旧依据时，该依据失效，旧值仍可查历史。

真实关系样本为 LV PEAK→FESS→LU 和 BICEPS↔SSE Riga 合作；多方共同设立只在隔离样本验证。已有机构所在地及主办登记以其原核查层级生成依据，明确存疑的登记保持待确认；少量官网复核不代替全库事实核查。国际定位采纳三项有出处的办刊定位。

独立验收指出的“大学内部单位继承大学类型”已在默认分类逻辑修正，并通过带备份和版本记录的专用修正程序处理本轮自动标签；人工修改的记录不覆盖。具体修改、运行结果、数据保全比较和浏览器截图见 [执行及验收记录](../work/来源目录改进执行记录.md)。

## 研究资料工作流程（2026-10-23，本轮验收通过）

按 [本轮规格](specs/研究资料工作流程.md) 建设 A/B/C。records 继续保存同一份内容，目录译稿新增独立类型及全员共编规则；来源介绍与正文存储经允许列表净化的 HTML，搜索使用派生文本。record_sources 表达一般来源关联，不替代发布机构、所属期刊或原文引用。新增元数据与正文进入版本快照。

研究摘录复用作者维护的 research_note，保存原文摘录、译文、解释、定位及引用时的原文版本。evidence_links 指向同一笔记并保存采用快照，显式刷新才采用新版本；读取检查当前笔记和原文权限。疑似重复只提示，人工比较后合并；保留旧对象与编号、版本、审计，转接附件、收藏、专题及引用，冲突在同一事务中拒绝。

专题新增研究问题、比较正文、阶段判断及历史。成员管理支持本机创建、停用、密码重置和本人改密，旧会话失效、最后有效管理员受保护。可读内容 ZIP 包括 HTML、JSON、允许读取的附件及证据快照；完整系统备份额外保留所有历史、账号及归档内容。

离线导出内嵌前端共用的 static/reading.css，导出时添加表格阅读容器，不回写正文或快照。正文、来源介绍、专题比较、旧原文快照及报告采用的笔记正文均显示统一表格；新原文快照显示引用时登记信息。390 px／1365 px 共 12 个离线页面检查通过，长链接换行、多列局部滚动、跨行跨列和 23 个本地链接保留；导出前后数据库逻辑散列一致。导出权限与原文改挂后的旧引用权限两项检查复跑通过，见 [离线导出结果](../work/research-workflow-validation/runs/backend-export-001/browser-checks.json)。

结构按 2→3→4→5 增量升级，有数据时各阶段先完整备份，旧列和编号不重写。恢复工具兼容 1—5。正文、关联、仅历史引用附件与新表均已在隔离样本做恢复验证；真实库已升级并由建设方、指挥方分别核对旧数据保全。2026-10-23 用户授权恢复后，先确认 8848 无监听，再用正式启动器启动，加载全部已验证后端修正；只监听 127.0.0.1，schema 5、健康检查与完整性检查通过。启动前后 14 张表的基线覆盖字段及编号、上传附件散列均不变，仍为 143 来源、494 资料、309 修订；未重复迁移、重新导入或写测试记录。建设方 8850 已停止，指挥方最终独立页面验收已通过。实际运行状态及检查证据见 [执行记录](../work/研究资料工作流程执行记录.md)。前端由采集 Agent 交付，建设 Agent 独占后端，协作边界见 [接口契约](../work/研究流程接口契约.md)。

## 长期研究基础核查（2026-10-23，只读核查）

用户提出对作者、期刊、机构开展定性与影响力研究，并保留未来自动翻译能力。建设 Agent 只读核查，指挥方复核关键结构后确认如下事实；本节不是这些能力已经实现的声明。

| 能力 | 当前代码事实 | 尚缺的基础 |
| --- | --- | --- |
| 外部作者 | [store.py](../platform_app/store.py) 的 records.authors 是署名文字；[workflow.py](../platform_app/workflow.py) 的 author_id 关联 users，表示个人成果负责作者 | 独立作者档案、异名与同名辨识、作品署名关系及确认依据 |
| 机构、期刊 | 已有稳定编号、主办／出版关系、机构关系、别名与修订快照；[source_catalog.py](../platform_app/source_catalog.py) 的关系保存依据和 checked_on | 作者与机构的任职／署名关联、现实关系生效起止时间。核查日期和修改时间均不能替代实际关系时段 |
| 影响力研究 | 普通笔记、专题、带定位摘录和报告固定引用可支持人工整理；workflow.py 的 evidence_links 保存报告采用的笔记快照 | 外部作品引文网络、带来源和统计口径的指标事实、按对象与时期组织的独立评价记录。报告内部引用不能当作外部学术被引数据 |
| 多语与翻译 | 已有原题、语种、人工正文／摘录译文和通用修订记录 | 原文与译文的明确版本对应、翻译任务及服务商适配、机器／人工处理状态与来源更新后的衔接 |

本次未修改应用、结构或真实数据，未运行新的应用测试，也未调用外部翻译服务。已确认产品方向见 [PRODUCT 第 6 节](../PRODUCT.md#6-长期方向)，分期建议见 [长期研究愿景与演进路线](长期研究愿景与演进路线.md)。
