# Windows 便携演示构建与恢复

本说明沿用 [#78 规格 1.0](https://github.com/normaltank/DataBase/issues/78)，由 [#88 范围 1.0](https://github.com/normaltank/DataBase/issues/88)加入公开真实题录及历史机器节选。由 [#101 范围1.0](https://github.com/normaltank/DataBase/issues/101)加入明确选择的本机AI配置及后台生命周期。由 [#106](https://github.com/normaltank/DataBase/issues/106) 加入便携免登录与只读样例。普通试用入口是包根目录“使用说明.html”；本文件用于复现构建、验收和恢复。产品规则仍以 [PRODUCT](../PRODUCT.md) 为准。不读取真实库或 ThinkTank。

## 构建

建设机需 Python 3.14、Git，以及首次下载官方构件所需的网络；接收方不用这些工具。先提交已审查源码，准备实际项目介绍 HTML（也兼容 PDF），再执行：

```powershell
python scripts/build_portable.py --intro-html 'C:\明确路径\项目介绍.html' --output 'C:\明确路径\dist'
python scripts/verify_portable.py 'C:\明确路径\dist\Zhihui-preview-提交前缀.zip'
python scripts/check_portable_preview.py --package 'C:\明确路径\dist\Zhihui-preview-提交前缀.zip'
```

`--prepare-only --allow-dirty` 只准备源码和运行库用于施工预验收，不生成可分享 ZIP。最终包要求实际项目介绍 HTML 或 PDF 存在，`--intro-html`与`--intro-pdf`二选一；`--allow-dirty` 会明确记录未发布源码，不用于最终交付。已存在的同名 ZIP 不覆盖。构建逐项复制版本控制白名单，不读取任何现有 data、备份、凭据或浏览器目录。构建缓存只保存 hash 锁定的公开官方构件。

仅通过 Git 接手前端或在 Linux/云端复用演示数据时，安装应用 requirements 后运行 `python -m portable.demo_seed --data-dir 明确的新目录`。它使用相同合成 PDF、头像、公开业务接口及受版本控制的公开白名单，不依赖 Windows 内嵌运行时；目标目录已存在即拒绝，避免重置任何旧数据。随后用 `create_app(该目录的绝对路径)` 启动所需的隔离开发服务，是否对外部署另按实际授权决定。

## 校园局域网临时试用

`start.bat` 只监听本机，`lan-start.bat` 可直接启动校园网临时试用，无需先设置账号或口令。普通浏览器自动取得独立临时研究员与开期资格，可在“我的”修改称呼；同一浏览器刷新、返回和正常重启复用身份。退出会结束当前身份会话，页面可明确创建新身份；清除Cookie或换浏览器会取得新身份，原材料与署名继续保留，不自动恢复身份或转移责任。停用身份仍拒绝访问，不悄悄换成新身份。

新访客默认可查看明确标记的只读主题／期刊样例，原负责人、作者、参与和历史保持；实际交材料请“开启我的练习主题”，可单人开期，也可选择已入场的其他有效成员。当前有 `demo-seed.json` 的便携库将明确且存在的样例ID一次保存到数据库，随新完整备份保留。历史备份若没有样例标记，会说明“未发现可确认的演示样例”，仍可新开练习；不会按题名推断或放开原私有工作。

主机通过本机地址打开页面，选择“主机本机维护”，可管理演示、成员、完整备份及AI状态。该入口需要本机回环来源和页面防伪令牌；LAN访客不能切换维护身份，维护Cookie也不能从远端使用。原自设账号仍可从退出页“使用已有账号”登录；公开演示口令在便携试用中拒绝，已有口令、停用状态及业务资格均不改写。正式应用不接受这些临时或本机维护会话。

LAN采用真实Waitress，Host只接受本机及启动时发现的实际IPv4，拒绝转发头，写入保留Origin／CSRF。窗口列出的校园网IPv4地址供分享，127.0.0.1仅供主机本机，不作为同事访问地址。无需修改端口时直接启动，优先复用上次端口；可停机执行 `lan-configure.bat --port 8851`，0为自动，省略参数保留原设置。此配置不读取口令、不改账号、不启用AI。随机令牌停止控制端点仍要求回环来源；停止只管理本副本。

同校园网不保证设备互访：校园Wi-Fi客户端隔离、访客网或不同网段规则可能阻断；主机须联网且保持开机不休眠。防火墙只由使用者按程序 `runtime\python.exe`、实际TCP端口和试用网段／具体客户端IP建立受限入站规则，配置文件与校园实际网络一致，结束后禁用／删除。完整中文逐步操作在包根目录[使用说明](../portable/quick-start.html)，软件不修改防火墙、路由器或开放公网。临时LAN HTTP只用于可信网络；正式TLS部署见[服务器发行说明](https://github.com/normaltank/DataBase/blob/main/docs/server-deployment.md)。

实际ZIP检查：`python scripts/check_lan_release.py --package <ZIP>`，验证本机非回环IPv4登录、两成员／私人资料／附件、重启、端口冲突、自身停止和备份新目录恢复；不冒称已在校园两台设备上验证。它和原便携验收都不探测8848。

## 不启用AI的三刊公开采集

主机进入“维护界面→自动采集”，按需“登记三刊公开来源”，在各来源下保存启用及频率，再在“本机公开采集”明确勾选期刊并开启。后台直接保存Crossref公开题录与实际提供的摘要，详情和“本刊资料”可查看结果；不要求密钥或付费AI。每轮最多25条，indexed日期窗口及游标持续接续，失败与覆盖如实展示；字段缺失不补造，不取得论文全文。具体来源与受控每刊5条实采入口见[根目录采集说明](../README.md#官方来源自动采集与原文快照)。

本机许可与明确的三刊来源ID名单存放在Windows当前用户本机应用数据中，按解压路径隔离，不进入业务备份或分享包。原路径正常重启保留；新解压路径／新用户或恢复到新目录默认关闭。点击“暂停本机公开采集”可停止新派发；停用单个来源也立即阻止新取得。AI关闭时后台只处理当前许可名单中的期刊，不接管其他已启用来源、中文或档案旧队列；新增文章保留公共资料，待明确启用AI后由自主维护接续，本次不执行付费处理。AI已明确启用时保持原后台行为及费用边界。

## 可选AI与后台维护

原始分享ZIP没有密钥；新目录默认AI暂停且没有采集后台。本机和LAN入口共用以下明确选择的流程，接收方不需要开发Python：

1. 用 `stop.bat` 停止本副本。主机直接在本机配置后续AI；普通试用与LAN启动均无需设置账号口令。
2. 双击 `ai-configure.bat`。隐藏输入自己的DeepSeek密钥，填写模型、模型版本或核对日期、带版本的CNY价格及UTC自然月预算；最后输入 `SAVE` 才保存。0预算只能暂停，输入校验失败或取消会保留原配置。配置过程不请求模型。默认价格是2026-11-03核查的 `deepseek-flash` 保守峰值：每百万tokens命中0.04、未命中2、输出8元；不是永久资费，使用前按窗口中的[官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)核对，其他模型须填写自己的有据价格版本。
3. 双击 `ai-enable.bat`，核对数据库当前月预算，输入 `ENABLE` 明确允许联网及付费。再用 `start.bat` 或 `lan-start.bat` 启动。配置或重新启用要求先停机；保存配置本身仍暂停。
4. 管理员在维护界面查看AI配置、后台状态、队列及实际预留／结算。后台沿用既有worker，处理已启用来源的采集和自动中文，并逐批自主维护新旧公开外部文章、人物及来源档案，无需读者刷新。维护视图显示队列、近期正式修改与暂停原因；机器有据改动直接保存，旧显式建议操作仍可用。未变化对象不每tick重跑，稳定对象约30天复查；AI新建来源仍须另行启用持续采集。
5. `ai-disable.bat` 可在服务运行时暂停新AI预留，并让后台完成当前有界任务和费用结算；若未开启本机公开采集，后台随后退出；Web阅读仍可继续。重新启用前用 `stop.bat`，再执行第3步。维护界面的AI暂停仍按原规则控制AI调用，不能代替关闭整个采集后台。`stop.bat` 等待本副本在途任务及Web请求后退出，不按端口或PID杀进程；等待时保留窗口，不强行关闭。

密钥与本机启用设置通过Windows DPAPI当前用户保护，存放在Windows当前用户的本机应用数据 `ResearchPreview/解压路径摘要/ai-settings.dpapi`，不在包内、业务数据库、日志或备份里。程序仅将本机已明确启用的设置交给统一AI网关，不继承系统环境中的密钥、模型、代理或研究库位置。机器或Windows用户改变、移动解压路径、损坏／缺失配置时AI关闭；请在新位置重新配置。原目录同一Windows用户停止再启动时保留设置和data；替换源码后复用同一路径也会保留本机设置。

本机配置只设置模型与价格、当前月预算及启用状态，不重置账本。维护界面调整后的当前预算在暂停／重新启用及重启时保留；重新运行配置向导才写入新的月预算。预算按UTC自然月累计，已结算及在途预留沿用现有统一网关；未知费用继续保留预留并阻止新调用，不因停机、重启、复制备份或再次启用而自动重试。月预算不等于供应商账户余额，也不是跨月总额承诺。

## 随包内容与历史译文

原三账号及其自设口令／停用状态保留，合成主题／期刊协作及原件作为只读样例。另从[固定公开fixture](../portable/samples/cee17-preview.json)播种38核心来源、27辅助机构、56外部资料，均待核对，不关联虚构中心成果。自动入场后从“我的→资料夹→历史17国公开资料样本”找到全部56篇，或在“资料”搜索“平台工作者”。题录、来源、日期精度及已知冲突保留；不将来源所在地推成文章研究对象。

56个机器题名来自既有DeepSeek批次，23篇保存原摘要不超过20词及机译摘要不超过120字的独立节选，33篇无原摘要只展示译题。不包含完整原摘要、完整译文、全文、真实账号或内部附件。原译节选独立截取，未必逐句或逐段对齐，不能作为完整摘要或专业人工校订结果。历史取得路径及限制见[#86记录](../work/中东欧17国来源与采集翻译演示核查.md)；本包不证明38站持续自动接通。

来源、资料和资料夹通过认证API创建。既有API不接收历史结果，因此[专用新库播种器](../portable/public_batch.py)只在刚完成合成初始化的演示库写入派生机器展示版本与`raw_json`来历，不执行服务商调用。历史完整输入hash、原任务／资料ID及原版本独立保留；本包输入hash按随包题名与节选重算，不能拿节选重新验证未随包全文。该展示版本不写人工中文、不允许人工采用为完整译文；本地attempts/calls/AI费用与自动任务均为0，默认AI保持暂停。明确启用后的新调用与这些历史节选分别记账。原题名／摘要修改后按普通输入hash判断失效，非输入字段修订不丢掉当前可用译文；正常非导入翻译行为保持。可读内容导出及完整备份恢复保留这两类hash与导入身份。

[构建器](../scripts/build_portable.py)使用 [固定构件锁](../portable/runtime-lock.json)：官方 CPython 3.14.10 embeddable x64、含 Waitress 的五项应用依赖及五项传递依赖，保留整份 wheel 中的 DLL、dist-info 与许可。Python 摘要依据 python.org 的 sigstore 摘要，wheel 摘要依据对应固定版本 PyPI JSON；构建不执行 pip。锁同时记录解压后文件清单，核验器逐字节核查官方构件，只有 `python314._pth` 被显式替换。摘要证明所据构件的一致性，不替代安全更新或研究真实性判断。本轮与正式源码发行共用受控应用依赖版本；后续安全修订须重新锁定、构建及验证。

`._pth` 仅包含包内标准库、包内 site-packages 与应用根目录，不启用 site；附件子进程沿用内嵌 sys.executable。启动器在导入应用前重建环境，只保留命名的 Windows 必需变量，另设置包内 TEMP/TMP 与 Windows System32 PATH。不会继承 Python 路径、研究库路径、AI 凭据、代理或证书定制。`diagnose` CLI 只报告环境变量名及包内模块来源，不打印凭据值。

## 生命周期和恢复

专用入口调用 `create_app(本包data绝对路径, embedded_worker=False)`，不导入开发 app.py。默认不起采集、中文处理或AI worker；按上述本机公开采集或AI的明确许可，由本包服务进程持有同一个worker锁；AI关闭时仅采本机名单，AI启用时沿用既有完整队列，随本包停止。空库在包内临时目录生成全部演示后才原子移入 data；已有数据库绝不重置。协作样例 PDF、TXT 和头像均为明确合成，其外链使用 example.invalid；真实题录保留正式来源网址。seed 清单保存在新库的 demo-seed.json，分开记录合成对象、原件摘要和真实公开批次映射。

实例生命周期按包目录加文件锁，控制端点需要随机令牌和本包路径身份；停止先完成自身 Waitress 请求调度再关闭自身监听与连接，不按 PID 或端口杀进程。操作序列锁和服务生命周期锁由 Windows 在进程退出后释放。过期控制状态不会成为杀进程依据。端口由服务器实际原子绑定，优先复用上次成功端口，冲突时使用可用动态端口；始终避开8848。各包目录拥有独立且稳定的会话 Cookie 名；浏览器草稿仍依赖实际端口。

完整备份在管理员界面下载。恢复到新解压且尚未启动的副本，在命令提示符运行：

```bat
runtime\python.exe -I -B -m platform_app.maintenance --restore "C:\备份路径\演示备份.zip" --target "C:\新解压路径\data"
```

目标 data 必须是尚不存在的新目录。成功后双击新副本 start.bat；恢复的数据库存在，因此不会重新播种。完整备份保留业务队列、月预算和费用账本，不包含本机密钥、公开采集许可或启用配置。新目录恢复后公开采集关闭并强制暂停AI，须在当前Windows用户下重新配置和明确启用；未知费用记录仍保持阻塞。先停止原副本再移动或复制其 data；正式资料迁移须另按实际授权处理，便携演示不自动迁移真实库。直接转发构建器生成的原始 ZIP，避免把试用后的账号、附件、日志、会话和备份带给别人。

## 验证边界

本轮优先用[单路径试用烟测](../scripts/check_portable_trial.py)：`python scripts/check_portable_trial.py --root 明确的合成解压目录 --evidence 明确的新证据目录`。它仅启动该副本的回环监听，不复制第二份运行库；双临时身份、称呼、单人／多人开期及上传通过实际HTTP，备份恢复到新data目录后以同一解释器的无监听合成HTTP核对主机／LAN来源与私有权限，正常重启核对身份和端口。可选 `--browser` 增加单宽浏览器入场、开期和上传；完整宽度、缩放及跨人接续由控制端另行验收。

[原发行验收入口](../scripts/check_portable_preview.py)继续支持两副本隔离检查，新trial包走双临时身份、只读样例、开期上传、主机维护及新目录恢复分支；旧包保留原三账号／深度交接与索引的历史检查路径，新trial分支通过不冒称重跑全部旧流程。可选[LAN入口](../scripts/check_lan_release.py)会显式开启非回环监听，需独立授权安排，主烟测不调用。核验器拒绝越界、重复、原始 ZIP 名被截断或规范化、符号链接及白名单外文件，并比对完整 manifest 和固定合成 PDF 摘要。

新增便携配置测试使用明确假密钥、Windows DPAPI、无监听的合成数据目录及模拟供应商响应，验证口令反馈／取消、UTF-8中文私有管道、配置隔离／损坏、显式启用、worker锁与停机、CNY结算／未知费用及备份恢复。付费试用仅由控制端执行并单独留证，施工自测不产生真实调用。

本轮实际执行结果、同步 SHA、独立审查和最终 ZIP 摘要由 Issue 的本次交接记录维护，施工预验收不等于最终分享版。受限 PATH 和包内模块来源能验证本宿主上不依赖开发 Python，不能冒充干净虚拟机或所有 Windows 10/11 系统覆盖。软件测试不证明研究观点、实际资料覆盖或真人跨人接续质量。
