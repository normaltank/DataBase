# 长期研究愿景与演进路线

更新：2026-10-23。供用户审阅，也供后续建设 Agent 接续。

本文说明平台要走向哪里、已有基础和建议建设顺序。已确认产品规则以 [PRODUCT](../PRODUCT.md) 为准，词义以 [GLOSSARY](../GLOSSARY.md) 为准，实现事实见 [施工说明](施工说明.md)，本次讨论出处见 [需求讨论记录 R007](需求讨论记录.md#r007作者期刊机构研究与多语资料的长期方向)。本文中的分期方案是建设方建议，尚未作为新一轮应用施工规格开工。

## 1. 我们要建成什么

建设一个中心成员可以共同积累资料、辨识作者与来源、比较观点、追溯证据并形成研究成果的平台。资料库提供持续使用的数据基础；作者、期刊和机构成为可以长期研究的对象；研究判断与所依据的材料保持联系。

发展过程是：**资料积累 → 作者与来源关联 → 围绕问题整理证据 → 定性研究与分维度评价 → 形成可追溯成果**。中文阅读与检索贯穿其中，同时保留原文、原名和译文版本。

拉脱维亚资料用于先跑通真实研究流程，未来可扩展到其他国家、语言和议题。

## 2. 用户已经确认的方向

- **作者、期刊、机构都要能研究。** 作者不能长期只是一行署名。应有能够持续整理信息、关联作品和形成研究积累的独立档案；期刊和机构在现有身份基础上继续发展。
- **定性研究是主要用途之一。** 能够整理研究主题、观点及其变化，比较不同作者、机构和期刊，并把判断联系到具体材料。具体研究分类和方法随后按实际课题细化。
- **影响力分两类评价。** 学术影响与政策／社会影响都需要，分别记录、分别评价，暂不合成一个总分。
- **中文为主，原文与译文并存。** 默认服务中文阅读和检索，保留原始内容、姓名、机构原名和出处，区分机器翻译与人工校订，保留译文版本。
- **未来可以接入翻译服务。** 用户提出 ds API；目前暂按 DeepSeek 候选服务理解。具体服务商、模型、首批内容和调用方式没有冻结。
- **成果有依据，修改有责任。** 沿用现有资料关联、证据定位、版本保护及作者授权规则；目录译稿全员共编不会自动扩大为所有个人研究成果全员可改。

## 3. 研究人员未来应该能怎样使用

以下是帮助理解方向的示例，具体页面和字段仍由实施规格细化。

研究员读到一篇文章，点击作者后，可以查看已经确认属于此人的作品、姓名写法、相关机构，以及中心对其研究主题和观点的积累。遇到同名者，可以保留待确认的署名，避免把不同人的作品混在一起。

同一作者早年的文章署名机构 A，后来转入机构 B，两段经历及依据可以分别保留。当前任职信息不会改写旧文章发表时的署名事实。从期刊或机构进入，也能汇集相应作品、作者与研究笔记；“任职”“主办”“发布”“合作”各自有清楚含义。

研究员围绕一个具体问题，选取若干作者、期刊或机构及一个时期，比较主题、论点、证据和变化。平台帮助整理材料与已有发现，研究员形成判断，并记录哪些证据支持判断、哪些提出相反解释、哪些地方仍不足以下结论。

评价影响力时，能够分别查看学术贡献、引用和讨论，以及政策引用、机构采用或公共传播的证据。被提及、受到批评、被赞同和实际采用需要分别解释；本库收录量只说明本库覆盖情况，不能直接当作总体影响力。

读者可以在中文与原文之间切换，查看译文依据的原文版本及是否经过人工校订。原文更新或重新调用翻译服务时，已有人工修订与旧报告的引用依据仍能查回。

| 方面 | 已有基础 | 真实缺口 |
| --- | --- | --- |

| 机构和期刊 | 稳定编号、类型、别名、主办／出版与机构关系、依据及修订 | 作者任职／署名关联，以及关系在现实中的生效时段 |

因此，现有数据和功能可以复用，但还不能说长期研究所需的基础已经全部预留。仅给姓名加一个链接，也不能算完成作者档案建设。

## 5. 建议的建设顺序

### 第一阶段：补齐作者身份与作品关联

这是我建议的下一项建设重点。为作者提供稳定内部编号、原名与别名、可核实的外部标识，并通过作品署名关系连接现有资料。保留原始署名、顺序、匹配依据及未确认状态；同名不自动合并，机构署名关联已有机构，不造成人物档案。

旧资料的署名文字继续保留，按已核实样本逐步建立对应关系。成员可以从资料进入作者档案，再返回其作品；已有来源、附件、专题和成果引用仍能使用。识别错误可以更正并查明历史。

作者与机构的关系要区分作品上的署名单位和现实任职信息；需要表达时间时，保存有依据的时段及未知状态。机构关系已有的“核查日期”不能代替任职或隶属关系的生效日期。

建议以一小组真实作者和作品验收：同名者可分开、不同写法可核实归一、换机构不改写历史、身份未知的署名不丢失。具体样本随实施规格确定。

### 第二阶段：形成可维护的研究档案与评价记录

复用现有摘录、笔记、专题和报告，让研究内容关联到作者、期刊或机构。建议每份评价说明研究问题、对象、时期、依据、研究员和版本，并区分材料登记的事实与研究员判断。

先围绕真实课题开展人工定性研究，同时分别积累学术影响和政策／社会影响证据。需要数字时，再明确指标含义、数据来源、覆盖范围、时间窗与比较对象；资料不足应显示不足，不能自动判为“影响力低”。

建议验收一条完整路径：选定对象和问题 → 整理材料 → 比较证据 → 分别形成两类影响评价 → 生成能返回依据的报告。作者、期刊和机构的评价可以使用不同指标，不能直接共用一套总分。

### 第三阶段：接入有版本对应的翻译流程

先把“哪份原文的哪个版本，译成哪种语言，经过哪些修订”表达清楚。建议将原文、机器译文和人工校订记录分别保存，记录所用服务、模型、时间及相关处理设置；专名与术语积累可人工维护。

新增翻译不覆盖人工校订；原文变化时能识别译文需要复核。中文译文与原名参与检索，搜索结果说明匹配的是哪种内容。具体哪些字段、正文和附件先进入翻译流程，按实际使用选择。

届时再实现独立的翻译服务适配、失败重试和必要的批量任务能力，服务商可以更换，资料与译文记录继续使用。实际接入前明确首批可发送的材料范围、账户和用量边界。本次未接入 API，也未发送本地材料。

### 后续阶段：按真实问题增加分析工具

在作者身份、关系与证据质量足够时，再评估引文关系、合作关系、主题变化、跨对象比较和可视化等工具。是否需要外部学术数据、批量分析或专门的图形界面，依据研究问题和资料覆盖决定。

这些是候选实现方式。没有必要在业务模型尚未确定时先搭空的分析接口或复杂任务系统；每次增加能力都应有可验证的使用场景。

## 6. 对后续建设的具体约束

已确认方向及原有可追溯原则由 PRODUCT 约束后续建设；建议技术方案遵守以下衔接方式，具体实现仍可调整：

1. 原文作者身份与登录账号分开。已有个人成果 author_id 的权限含义保持明确，不复用成外部学者编号。
2. 作者、期刊和机构身份尽量复用同一份记录。增加关系与内容，避免为研究页面复制一套互不相认的对象。
3. 保留原始署名、名称、出处和版本。新结构通过增量迁移接续旧资料，不能以完成“结构化”为由丢弃未能识别的信息。
4. 事实、原文、译文、研究解释及指标计算结果分别保存各自依据。现实有效时间、资料发表时间、核查时间和修改时间分别表达。
5. 新对象、关系和译文同步纳入既有权限、历史、导出及恢复流程。可从页面找到一份内容，不等于取得改写它的权限。
6. 以真实可用的能力判断完成。稳定编号、有效关系、证据关联和可恢复的版本，比仅增加按钮或接口占位更重要。

这些要求可以在现有应用中逐步落实。技术方案随规模和实际研究任务调整，不先设定更换整个技术栈。

## 7. 后续什么时候需要再 Grill

本次愿景所需的两项关键口径已经明确，没有悬而未答的问题。进入具体研究或翻译建设前，再围绕当次任务确认：

- 首个真实研究问题、对象和时期，以及研究人员希望得到怎样的成果。
- 两类影响力分别需要哪些证据和比较方法；可用数据能支持哪些结论。
- 第一批翻译覆盖哪些内容、哪些可以发往外部服务，以及人工校订怎样进入日常工作。

这些问题不妨碍现在明确产品方向，也不应被默认指标、模型输出或现有字段替代。

## 8. 参考及取舍

核查日期：2026-10-23。以下仅作为设计参考，不表示已接入相关服务。

- OpenAlex 将作者与作品分别建模，用作品署名关联记录原始姓名、署名位置与机构。本项目可借鉴这种区分，并保留人工核实和纠错。见 [作者模型](https://help.openalex.org/data/authors/) 与 [作品署名关系](https://help.openalex.org/data/authorships/)。
- DORA 建议不要用期刊指标代替对个人研究贡献的判断，并重视政策和实践等定性影响。我们据此建议保留评价依据和适用范围；两类影响分别评价是本项目用户确认的方向，不是从外部标准推导出的强制模板。见 [DORA 宣言](https://sfdora.org/read/)。
- DeepSeek 官方提供可通过 API 接入的服务，说明它可以作为未来翻译流程的候选提供方；能接 API 不等于已验证翻译质量或已具备版本管理。具体模型与费用在实施时再核查。见 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/)。
