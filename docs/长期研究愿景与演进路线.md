更新：2026-10-27。状态：在已有数据库基础上，用户明确以自采集、自维护与对象国新文章阅读作为重设计主线；十四项业务决定已形成整体施工规格，任务图待核对与发布。资料和研究的可复核性继续适用。

本文说明平台要走向哪里、已有基础和建议路径。已确认产品规则以 [PRODUCT](../PRODUCT.md) 为准，词义以 [GLOSSARY](../GLOSSARY.md) 为准，实现事实见 [施工说明](施工说明.md)。长期研究方向出处见 [需求讨论记录 R007](需求讨论记录.md#r007作者期刊机构研究与多语资料的长期方向)，基础优先的早期讨论见 [R011](需求讨论记录.md#r011产品脑暴与基础数据库来源采集的建设顺序)，最新自动化与阅读方向见 [R021](需求讨论记录.md#r021自采集自维护与前端重设计)。以下功能细目均须区分已交付、用户确认方向和建设方建议。

## 1. 我们要建成什么

建设一个中心成员可以共同积累资料、辨识作者与来源、比较观点、追溯证据并形成研究成果的平台。资料库提供持续使用的数据基础；作者、期刊和机构成为可以长期研究的对象；研究判断与所依据的材料保持联系。

发展过程是：**持续积累资料 → 自动整理与中文阅读 → 作者与来源关联 → 有依据的定性研究及分维度评价 → 保存可追溯成品成果**。中文阅读与检索贯穿其中，同时保留原文、原名和译文版本；研究写作可以在站外完成。

拉脱维亚资料用于先跑通真实研究流程，未来可扩展到其他国家、语言和议题。

后续取舍以 [研究质量与复核](../PRODUCT.md#研究质量与复核) 为条件：先用原件、真实问题和独立复核识别已有流程的困难，再据此决定需要的结构和自动化。2026-10-26 的只读盘点尚未发现真实库中的带出处摘录及报告引用；功能存在与真实研究使用分别评价，详见 [本轮核查记录](../work/研究复核深化验收.md)。

## 2. 用户已经确认的方向

- **作者、期刊、机构都要能研究。** 作者不能长期只是一行署名。应有能够持续整理信息、关联作品和形成研究积累的独立档案；期刊和机构在现有身份基础上继续发展。
- **定性研究是主要用途之一。** 能够整理研究主题、观点及其变化，比较不同作者、机构和期刊，并把判断联系到具体材料。具体研究分类和方法随后按实际课题细化。
- **影响力分两类评价。** 学术影响与政策／社会影响都需要，分别记录、分别评价，暂不合成一个总分。
- **中文为主，原文与译文并存。** 默认服务中文阅读和检索，保留原始内容、姓名、机构原名和出处，区分机器翻译与人工校订，保留译文版本。
- **自动积累，面向读者。** 最终系统应持续取得并整理来源文章，普通研究员以查看对象国新文章为主要体验，人工维护集中于异常；本轮已确认的收录、展示、身份及新增口径见 [PRODUCT](../PRODUCT.md#自采集自维护与对象国新文章2026-10-27-确认方向)。
- **数据库与写作分工。** 平台保存源数据和已经写好的报告，保留编辑、导入与导出，去掉专门的站内个人编译写作流程；资料夹用于收集内容和简短备注，研究资料与成品成果仍可供后续分析使用。早期研究写作示例保留其历史身份，新的使用与建设按 [R021](需求讨论记录.md#r021自采集自维护与前端重设计)及整体规格确认结果执行。
- **分批接入翻译服务。** 已有显式单篇 DeepSeek 题名／摘要翻译；新方向明确首批自动翻译题名与原文摘要、全文按需。生效规则与实现边界分别见 [PRODUCT](../PRODUCT.md#多语资料与中文使用2026-10-23-确认)和施工说明，不把方向当成已交付能力。
- **成果有依据，修改有责任。** 沿用资料关联、证据定位与版本保护；共同编辑和个人报告的作者授权例外按 [PRODUCT 第 3 节](../PRODUCT.md#3-已确认的共建规则)执行。

## 3. 研究人员未来应该能怎样使用

以下是帮助理解方向的示例，具体页面和字段仍由实施规格细化。

研究员读到一篇文章，点击作者后，可以查看已经确认属于此人的作品、姓名写法、相关机构，以及中心对其研究主题和观点的积累。遇到同名者，可以保留待确认的署名，避免把不同人的作品混在一起。

同一作者早年的文章署名机构 A，后来转入机构 B，两段经历及依据可以分别保留。当前任职信息不会改写旧文章发表时的署名事实。从期刊或机构进入，也能汇集相应作品、作者与研究笔记；“任职”“主办”“发布”“合作”各自有清楚含义。

研究员围绕一个具体问题，选取若干作者、期刊或机构及一个时期，比较主题、论点、证据和变化。平台帮助整理材料与已有发现，研究员形成判断，并记录哪些证据支持判断、哪些提出相反解释、哪些地方仍不足以下结论。

评价影响力时，能够分别查看学术贡献、引用和讨论，以及政策引用、机构采用或公共传播的证据。被提及、受到批评、被赞同和实际采用需要分别解释；本库收录量只说明本库覆盖情况，不能直接当作总体影响力。

读者可以在中文与原文之间切换，查看译文依据的原文版本及是否经过人工校订。原文更新或重新调用翻译服务时，已有人工修订与旧报告的引用依据仍能查回。

## 5. 当前建设顺序与后续建议

当前主线是：**已有数据基础 → 简洁阅读与成果保存 → 持续采集和自动整理 → 期刊与来源结构深化 → 有依据的研究与影响评价**。前端与自动化已形成规格；后续研究能力是已确认方向，具体批次、方法和指标尚未冻结。以下不另建任务台账。

### 短期第一批：先改最急的前端和资料使用流程

按 R021 将普通用户的体验集中在资料、档案和成品成果：默认对象国新文章与紧凑题名列表，中文内容真正参与检索；发表时间、首次收录、旧文更新及回访新增分别表达。筛选不限于日期，还覆盖对象国、来源、类型、主题、语言和内容可用性，条件与结果范围清楚。

成果保存已经写好的报告与编译内容，保留原文件、必要信息编辑、导入和导出。收藏、简单资料夹及备注集中到个人入口，移除研究问题、比较判断、组织摘录和个人编译写作等专门工作流。已有笔记、摘录、报告、原文关联、权限与历史仍可读并可复用。

完成判断是研究员能够从查找、阅读、返回到收集、成果入库与导出顺畅完成工作，页面明显减少无关入口、空模块和维护解释；不能只换配色或把旧按钮藏起来。

### 短期第二批：从少量来源跑通持续自采集与自维护

管理员确定来源及栏目，系统持续完成发现、取得依据、去重保存、中文处理、分类和有据关联；普通读者无需逐篇批准入库。已确认的完整边界、原文件／全文按需能力和异常规则见规格 1.0，不在本路线中另改一版。

首批沿用拉脱维亚试点：LIIA 机构栏目，以及既有 Baltic Journal of Economics 的 Crossref 题录入口。默认每日巡检、近期起点与历史回填按规格配置。两类来源都要分别核实实际覆盖，题录成功不等于正文取得；期刊在线、卷期、登记和索引日期不能混用。

自动翻译题名与实际摘要；没有摘要而取得正文时，另生成清楚标识的机器概述。公开网页正文保存快照，PDF 等文件及全文翻译按需执行。所有 AI 处理共用月度额度，超限或失败后先保留原始信息，条件恢复后自动续作。

自维护同时包括原文变动、失效、更正／撤回、迟登记补漏、重复、身份歧义和人工校订保护。维护者集中处理异常；正常文章不要求逐条填表。持续服务的主机、凭据、月额度及备份责任仍需上线配置，不能靠某位研究员一直打开网页维持运行。

### 接续深化：期刊模板数据与更多可靠来源

期刊设计 #54 继续保留，建议接在当前阅读／自动化基础之后落实：长期档案含封面、创刊时间、发行周期、ISSN／eISSN、主办／出版机构和官网；影响因子、中科院大类／小类分区按年度、版本及出处保存；卷期、完整或部分目次、单篇文章与中文编译内容建立对应。

同一期可有完整目次和部分选编，目录译稿仍可跨期；已有整份内容可以先保存，关系逐步补齐。它服务资料组织及成品复用，不重新扩张成已取消的个人报告写作平台。具体规格需与 R021 协调后安排施工。

扩展来源以覆盖、取得稳定性和维护成本决定，一批批验证机构、期刊及不同语言，而不是承诺全部官网立即可抓。新的国家、来源类型和历史材料可在试点跑通后扩展；拉脱维亚是试点，平台并非永久限定于拉脱维亚。

### 长期：持续研究作者、机构和期刊

作者、机构和期刊作为可长期积累的研究对象，继续保留稳定身份、作品与关系、时间及证据。自动整理降低填表负担，但身份歧义和资料不足必须可见，便于后续纠正和复核。

先从真实研究问题出发，比较对象的主题、观点、贡献及随时间的变化。成果可以在站外写作，由平台保存成品与所据资料；研究能力建设不等于重新增加站内写作流程。具体第一道研究问题、对象、时期与交付形式尚待细化。

影响评价始终分开两条线：**学术影响**，以及**政策／社会影响**。分别积累学术引用与讨论、政策引用与实际采用、公共传播等证据，不直接合成一个总分。期刊分区不能替代个人研究贡献，本库收录数量也不能代表总体影响力；未知应显示不足，不能自动判低。

### 长期候选：更深入的分析与多语复用

在对象身份、来源覆盖和证据足够时，再评估引文关系、合作关系、主题演变、跨对象比较、可视化以及辅助研究查询。外部学术数据与具体指标是否接入，由研究问题与可核验材料决定，目前不是已经冻结的施工任务。

中文优先与原文并存贯穿全部阶段。后续可以深化术语一致性、长文及多语版本复用、译文质量复核；本轮已确认的题名／摘要自动翻译、机器概述和按需全文翻译不能再列成未决定事项。OCR、更多交换格式及其他工具按真实需要另外评估，不要求先堆齐功能。

## 6. 对后续建设的具体约束

已确认方向及原有可追溯原则由 PRODUCT 约束后续建设；建议技术方案遵守以下衔接方式，具体实现仍可调整：

1. 原文作者身份与登录账号分开。已有个人成果 author_id 的权限含义保持明确，不复用成外部学者编号。
2. 作者、期刊和机构身份尽量复用同一份记录。增加关系与内容，避免为研究页面复制一套互不相认的对象。
3. 保留原始署名、名称、出处和版本。新结构通过增量迁移接续旧资料，不能以完成“结构化”为由丢弃未能识别的信息。
4. 事实、原文、译文、研究解释及指标计算结果分别保存各自依据。现实有效时间、资料发表时间、核查时间和修改时间分别表达。
5. 新对象、关系和译文同步纳入既有权限、历史、导出及恢复流程。可从页面找到一份内容，不等于取得改写它的权限。
6. 以真实可用的能力判断完成。稳定编号、有效关系、证据关联和可恢复的版本，比仅增加按钮或接口占位更重要。

这些要求可以在现有应用中逐步落实。技术方案随规模和实际研究任务调整，不先设定更换整个技术栈。

## 7. 后续什么时候需要再 Grill

R021 的十四项业务决定和规格 1.0 沿用，不再重复确认。施工粒度与依赖按 Matt 工作流核对；已有授权内的技术选型及来源配置由建设方落实。后续只围绕真正改变范围或核心含义的问题继续讨论：

- 第一项具体研究问题、对象、时期及需要交付的成果。
- 学术影响与政策／社会影响各自采用哪些证据、指标和比较方法，现有数据能支持到什么程度。
- 超出已确认边界的材料取得、外部服务或数据使用扩展。
- 正式运行位置、试点使用者及维护与备份责任；具体月额度按小批运行消耗配置。

这些未决项不妨碍当前前端与自采集建设，也不能以默认指标、模型输出或旧界面补作业务决定。

## 8. 参考及取舍

核查日期：2026-10-23。以下仅作为设计参考，不表示已接入相关服务。

- OpenAlex 将作者与作品分别建模，用作品署名关联记录原始姓名、署名位置与机构。本项目可借鉴这种区分，并保留人工核实和纠错。见 [作者模型](https://help.openalex.org/data/authors/) 与 [作品署名关系](https://help.openalex.org/data/authorships/)。
- DORA 建议不要用期刊指标代替对个人研究贡献的判断，并重视政策和实践等定性影响。我们据此建议保留评价依据和适用范围；两类影响分别评价是本项目用户确认的方向，不是从外部标准推导出的强制模板。见 [DORA 宣言](https://sfdora.org/read/)。
- DeepSeek 官方提供可通过 API 接入的服务，说明它可以作为未来翻译流程的候选提供方；能接 API 不等于已验证翻译质量或已具备版本管理。具体模型与费用在实施时再核查。见 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/)。
