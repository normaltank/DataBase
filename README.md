# 知汇 · 研究中心共建共享资料平台

一个可以在本机使用、数据可以持续保存的中文研究资料平台，以拉脱维亚资料试点，支持来源与资料管理、目录译稿共编、摘录、专题研究及成果复用。实现范围和已知缺口见 [施工说明](docs/施工说明.md)，各轮交付与验收见 [文档目录](docs/README.md)。

## GitHub 版本与本地数据

公开仓库 [normaltank/DataBase](https://github.com/normaltank/DataBase) 保存应用源码、自动测试、产品规格和建设交接文档。研究数据库、成员凭据、上传附件、备份包、运行日志、验收原始数据和本机截图均留在本地，不随 Git 上传；源码仓库不能代替完整数据备份。

本文的 143 条来源、494 条资料等数量及验收记录描述原本机试点状态，克隆仓库不会附带这些资料。新环境按下文安装依赖后，可用 `python app.py --no-import` 启动空白资料库，通过本地演示账号体验并自行录入；需要迁移实际研究资料时，另按备份恢复流程交接。历史记录中指向忽略目录、截图或本机绝对路径的证据，只能在保留这些文件的原环境查阅。

## 打开和关闭

**双击本目录的 `start.bat`。** 程序会在后台运行并打开浏览器，入口为：

<http://127.0.0.1:8848>

登录页可以直接选择“研究员”“资料管理员”或“协作同事”体验。也可以填写以下本地演示账号，密码均为 `LocalDemo2026!`：

| 账号 | 身份 | 可以做什么 |
| --- | --- | --- |
| `researcher` | 研究员 · 林 | 提交资料和成果、共同编辑来源、维护本人或获授权的资料、收藏和整理专题 |
| `colleague` | 研究员 · 周 | 同样的成员功能，可用于检查不同账号的查看和编辑范围 |
| `admin` | 资料管理员 | 成员功能、核对、公共资料维护、来源历史恢复、成员和备份管理；个人正文仍需作者授权 |

结束使用时双击 `stop.bat`。只关闭浏览器不会关闭后台程序，停止程序不会清空数据。再次启动会使用原有资料。

当前仍为本机运行：演示入口和固定密码用于试用。本轮增加本机成员创建、停用和密码管理；正式名单、联网部署、HTTPS 与运行安排仍须另行确定。

## 建议先试这条流程

1. 选择“研究员”，在工作台搜索 `language`、`PROVIDUS` 或作者名字。
2. 打开资料详情，查看作者、日期、来源、原文入口、核对状态和已有附件线索。
3. 收藏一篇资料，或加入“拉脱维亚 · 语言与社会”专题。
4. 打开“编译成果”，查看“操作示例｜拉脱维亚语言与社会资料整理”。这份演示记录关联了两篇真实资料，并有可下载的操作说明。它不是正式研究成果。
5. 上传自己的成果：填写题名和编译者，查找并添加多篇原文；原文未入库时，填写待补关联的出处。
6. 新上传附件需确认可在所选范围共享。支持 PDF、DOCX、UTF-8 TXT/Markdown，单文件最大 20 MB。
7. 切换“协作同事”，检查同事可查阅共享成果，但不能编辑未获授权的成果。
8. 切换“资料管理员”，打开待核对资料并标记已核对。之后编辑会重新变为待核对。
9. 通过“历史”恢复旧版本；恢复形成新版本，保留当前授权及共享范围。

清单导出沿用当前检索条件、专题和查看权限。个人收藏和个人专题只对本人显示；中心专题允许成员共同添加和移出资料。受限资料按提交者、负责作者、有效授权及管理员的读取范围控制，加入共享专题不会扩大资料本身的权限。

## 资料库选择与批量整理

窄屏点击“打开导航”展开完整文字菜单；选中页面后菜单收起，也可用 Escape 关闭。资料查找页点击“筛选条件”展开高级条件，已经应用的条件继续显示在结果上方；清除条件保留编译成果、收藏和待核对各自的页面范围。“整理与导出”提供清单导出等低频操作。

来源条件可按“来源类型 → 来源国别 → 国际办刊定位”缩小范围，无需选定某一家来源即可查询；要指定机构或刊物时，再展开“具体来源”，按名称、原名或别名搜索。期刊及其他出版物采用已有主办国别依据，机构采用登记国家；国际办刊定位只适用于期刊。资料的“研究对象”仍按内容登记，可以与来源国别组合筛选。来源条件匹配发布机构、所属刊物或一般关联中的同一个来源，一般关联不自动表示发布关系。

提交资料和维护来源时，发布机构、刊物、关联来源、主办／出版方及机构关系使用可搜索的选择区。已选值单独显示，缩小候选不会删除已选项；需要取消时直接移除对应已选值，多选不再要求按住 Ctrl。专题内的“清除筛选”保留专题范围，单独移除专题条件或从导航进入资料库才回到全库。

资料库默认使用紧凑列表，也可切回卡片视图；切换保留当前查找、排序、页码及选择。打开题名后，足够宽的屏幕可同时查看列表与正文，使用“上一条／下一条”阅读同页资料；“返回列表”恢复原来的浏览位置。中等及窄屏使用独立阅读区域，加载期间也可返回。

从阅读中的资料进入人物或来源档案，点击“返回资料”可恢复原检索、页码、视图及正在阅读的资料；同一账号的浏览器前进、后退和刷新也保留有效工作位置。专题打开资料再关闭时，返回原专题的查询与页码。原资料已不再可见或不在结果中时，返回当前可用列表并说明原因。

在资料库逐条勾选，或用“选择当前页”选择本页资料；最多 100 条。选中后显示批量操作与选中数量。同一查询翻页保留选择，改变查询、筛选、排序或离开资料库会清空并提示。选择按账号隔离，刷新后不恢复旧选择。

“收藏选中”只添加收藏；“加入专题”选择一个自己可维护的专题，已有条目保留一份。结果显示处理、新增及原有数量，保留当前选择便于继续整理。服务端会重新检查每条资料和专题权限；编号失效、权限不足或专题版本冲突时整批不写入。失败保留选择；专题冲突时点“重新读取专题”，核对后再次确认。

“导出选中 CSV”仅下载明确勾选且当前可读的题录，支持中文、引号和多行，并处理电子表格公式起始内容。工具栏原“导出清单”继续按筛选条件导出。批量整理不改正文、作者身份、共享范围或编辑授权。

## 个人常用检索

设置好关键词、筛选和排序后，点击资料库上方的“保存检索”，输入名称保存。下次从“我的检索”按名称查找并打开；保存的是查询条件，每次重新查询当前可见资料，因此新收录的符合条件资料也会出现。收藏、编译成果和待核对页面保存时保留其范围，重新打开从第一页开始。

“我的检索”可改名、用当前条件更新、另存一份或删除。修改当前页面的条件不会自动覆盖已保存检索；同名、保存冲突和请求失败会提示并保留输入。检索属于当前账号，删除检索只移除这份个人设置。

来源或专题已失效、无权访问时，页面保留原条件并提示调整；明确移除失效条件或选择其他条件后再保存。系统不会悄悄扩大搜索范围。完整数据备份包含个人检索；它与手动收集资料的专题资料夹分别使用。实现及验证见[本轮验收](work/常用检索与资料工作流验收.md)。

## 用 DOI 或文章链接提交资料

在资料库点击“提交资料”，将 DOI、DOI 链接或公开文章网址粘贴到顶部，点击“取得题录”。结果先进入预览，不会直接入库。核对题名、署名、日期和出处后，点击“应用预览及已核对选择”，继续修改并保存。

默认只填空白字段；要替换已经填写的内容，须勾选对应字段。重复取得相同题录会保留预览中的人工修改；取得不同结果时，先选择保留当前预览或改用新结果，主表单已有内容继续保留。草稿包含已取得题录及核对选择，可从“我的草稿”恢复。

姓名、ISSN、已有外部标识和官网地址只用于提出已有档案候选。选择作者／机构身份后，须明确确认并填写依据；未确认署名保留原文，之后再补档或纠错。发布机构和所属刊物需要明确选择，不会由出版社推断主办国别，也不会由文章单位推断任职。已收录候选可直接查看，保存时再次检查重复。

DOI 使用 Crossref／DataCite 的公开题录，网页优先读取文章标签和结构化信息。部分智库网页只能取得题名或说明，缺项继续手填；失败不会清空已填内容，可把输入网址放入空白原文链接。保存后的详情与可读导出保留取得来源、时间及当时题录。本功能不自动下载全文或附件，也不代表资料已经核对。

## 新增研究流程

从机构、期刊或其他来源详情维护介绍、创建目录译稿；每份译稿独立保存题名、编译者、年份／卷期或跨期范围、网页正文、原目录出处和附件。一般关联来源可以多选，表示内容与这些来源有关，不自动填写为发布机构。来源页、资料库、专题和检索访问同一份记录。正文与来源介绍、别名可以检索；本地附件文字检索见下节，OCR 尚不包含在内。

来源目录的“筛选条件”分别提供机构类型、期刊主办国别、国际定位和收录范围；已经应用的条件可以单独移除。来源、人物和专题详情的“本页内容”可以跳到相应章节，保留当前查询页面。人物的修改历史、比较合并和身份整理历史位于“历史与身份整理”，编辑与导出直接可见。

点击来源名称进入机构、期刊或其他出版物的独立研究档案，可复制地址再次打开；“快速预览”便于在目录中查看，关闭后继续原来的筛选。机构档案展示适用的信息、机构关系与任职人物；期刊显示主办方、出版方、主办国别、国际定位及 ISSN。公共介绍继续通过“编辑来源”共同维护，历史与纠错入口在“历史与维护”中。

档案把机构发布／刊物刊载资料、一般关联资料、目录译稿和中心成果分区展示。明确以该对象为研究对象的笔记另行汇集；一般关联或引用并不自动成为这类笔记。数量与分页只包含当前成员可见的内容；暂未收录不代表对象没有成果。资料、译稿及笔记仍访问同一份记录，编辑权限按原有规则执行。

目录译稿由所有有效成员共同编辑。保存发现他人已有新版本时，保留输入并对照最新内容后明确继续处理。草稿按账号保存，关闭或刷新页面后可从“我的草稿”继续；选中的完整附件也会保留。网页正文支持标题、段落、列表、表格和链接；Word／PDF 作为独立附件，不在网页中修改文件本身。

个人编译成果、研究笔记和研究报告分别记录署名、负责作者账号和上传者。本人提交直接确认；替别人提交时选择负责作者，由该作者本人确认后生效。正文仅已确认作者及其授权同事可修改或恢复；管理员身份本身不授予个人正文改写权。旧个人成果先显式认领或指定作者确认，不自动把旧提交者当作作者。授权与共享范围由负责作者调整，恢复历史不恢复旧权限。

阅读原始资料时，可保存原文摘录、自己的译文、研究员解释和页码／段落定位，并保留原文版本或所用附件。研究笔记和报告能加入专题；报告引用证据时记录采用版本，后续修改笔记不会悄悄改变旧报告的依据。明确刷新引用才采用新版本。无权查看原文时，对应摘录和自动引用片段也会隐藏。

专题可记录研究问题、比较正文和阶段判断，收集资料、摘录及报告。移出专题只解除关联。疑似重复需要先比较影响，再人工确认；合并保留旧编号转向、归档内容和历史，并转接附件、收藏、专题及引用。权限、类型、引用快照或机构关系冲突时拒绝合并。真实试点库不会自动批量合并。

专题添加资料、成果关联原文均支持搜索与翻页，显示当前账号可用候选的总数。已有专题条目或已选原文会从候选中排除；原文选择只列外部资料，不会因前页包含中心成果而漏掉后面的原文。翻页、重新搜索和重试保留已经选定的关联。

### 附件文字检索

新上传的文本型 PDF、DOCX、UTF-8 TXT／Markdown 会在资料保存后尝试建立文字索引。资料库关键词同时匹配题录、正文和当前可读取附件；多个词可以分布在题录与附件中。命中结果注明附件名称、位置与文字片段，点击文件名下载原件核对。PDF 使用文件页码，可能不同于印刷页码；DOCX 仅提取正文段落与表格行；TXT／Markdown 使用行号。自动提取文字不属于人工研究摘录，也不会改变报告已有引用。

旧附件及恢复备份后的附件：打开资料详情，在“附件文字检索”中点击“建立索引”或“重建索引”。当前有权下载该附件的成员均可执行；重建不修改正文、版本或授权。页面分别显示未建立、已建立、无可提取文字、格式不支持、超过限制或提取失败。扫描图片不执行 OCR，加密 PDF、损坏文件或提取失败仍可按原方式下载。

每份索引最多处理 10 MB 文件、300 页 PDF、20 MB 解压内容、100 万字符、2 万个位置片段，限时 12 秒；上传仍保留原有 20 MB 上限。PDF 的排版顺序及混合图片可能导致提取不完整；DOCX 的图片、脚注及文本框不在本轮提取范围。普通搜索只读已有索引，不触发解析。仅当前附件参与检索，历史恢复、合并及权限变更会即时改变可搜索范围。

文字缓存存于数据目录的 `attachment-index/`，可丢弃且不随完整备份导出。原数据库和附件仍是备份依据；恢复至新目录后逐份重新建立索引。尚未建立索引时，附件文字不会命中，原有题录及正文仍可检索。

## 作者目录与人物档案

从“作者目录”按原名、中文名或别名查找，也可先建立尚未关联作品的人物档案。同名人物分别保存；显示姓名、姓名写法、分节介绍和参考出处由有效成员共同维护，每次保存填写维护依据或说明。人物身份与成员账号分开。

在原始资料中打开“整理署名”，保留原始整段文字，再逐项填写署名片段、调整顺序，并选择人物或机构档案。目录与候选显示已登记的简介和机构线索，同名时需核实后选择；“任职登记”包含有据的历史任职，不表示当前或唯一单位。已确认署名必须填写可核查依据，拿不准时保留待确认。机构作者与发布机构分别登记。普通同事可以维护有权查看的资料署名，正文仍按原有编辑授权维护。

从署名可进入人物或机构档案的已确认作品列表，再返回原资料；待确认项不计入已确认作品，搜索和数量按当前可见范围计算。认错时重新选择身份或退回待确认，移除后历史仍保留。“署名历史”可查看前后身份、依据和修改人，并单独恢复某一项；正文历史恢复保留当前公共署名，避免覆盖后来的身份纠正。保存冲突保留当前输入，关闭后可从“我的草稿”继续。

人物档案的“维护任职经历”可分别登记已有机构、角色与可核查出处，允许同时任职多家机构或在同一机构分段任职。起止时间可填 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`，仅知道一端或完全未知时保留空白；页面明确显示时间未知，不据此推定现任。机构详情的“任职人物”可查阅、选择人物并维护其经历；同名选择器同时展示姓名写法和已登记简介。

资料阅读页的“维护文章单位”按本篇作品的具体署名登记一家或多家机构及出处。先在“整理署名”登记作者片段，再选择对应的第几项署名；各单位卡片保留署名序位并可进入人物或机构档案。文章署名单位、人物任职、机构署名作品和发布作品分别展示；修改任职不会改写旧文章单位，发布文章不会自动建立任职。任职与文章单位各有修改历史和单项恢复，移除保留来历；恢复正文历史保留当前关系。冲突时保留输入及本机草稿，对照最新关系后继续保存；公共关系维护仍不授予正文或独立笔记的编辑权。

人物档案中的“写研究笔记”会预选此人；笔记编辑页可同时选择多个人物、机构和期刊。也可从档案“关联已有笔记”，选择自己当前有编辑权的笔记，继续调整研究对象。各档案汇集同一份笔记，移除一个对象保留笔记；引用原文或一般关联来源分别登记。研究对象与正文均由负责作者及其授权同事维护，代交待作者确认、撤权和管理员边界沿用原规则。保存冲突会保留正文和对象选择，先对照最新内容再保存；“研究对象调整历史”可查看对象名称、类型、操作人和原始身份线索。

头像支持 JPEG、PNG、WebP，单张不超过 5 MiB，上传时填写来源链接或说明。替换、移除后，原头像仍随历史保留。输入无效或同时编辑发生冲突时，当前输入和待上传文件保留；对照最新版本后继续保存。关闭或刷新后从“我的草稿”继续，并明确选择恢复草稿。“修改历史”可查看修改人、依据和旧头像，恢复产生新版本。

确认两个档案属于同一人时，从人物详情打开“比较合并”，查找另一档案，核对两份介绍、出处及当前可阅读的作品和研究关联。逐项选择当前姓名、原名、中文名、介绍和头像，填写身份依据并确认；同名选项通过“保留编号的档案”和“合并到前者的档案”区分。未选内容及各条关系来历继续保留，当前和历史头像的原链接仍可用。旧编号仍可搜索、打开，并说明合并去向；编号不作为姓名写法展示。

“身份整理历史”可查看原合并、档案与可阅读的关系，并预览拆回。预览区分原有转接、后续新增、独立更正和已解除：只按本次合并来历恢复未被独立重新指定的归属，保留后续介绍、头像、任职字段、已纠正归属与解除结果。仅完善署名文字或任职角色不表示重新确认人物身份。新增任职逐条明确选择人物；新增作品可选择人物或保留待确认。若有依赖的后续合并，按页面顺序先拆后续，再从历史重新预览较早一次。

私人笔记不阻塞公共人物拆回。归属不明的受影响笔记关联保留原对象及来历，显示“研究对象待复核”，暂不计入人物已确认笔记；其他已明确的人物、机构或期刊关联继续有效。作者或当前授权同事打开笔记的“复核研究对象”，可确认原对象、改选或移除。普通正文保存继续保留待复核状态，公共身份操作不授予同事或管理员代替作者重选对象的权限。正文、原有作者授权和报告采用的引用快照保持，读者可查看身份更正依据。

介绍历史恢复不会拆回身份。预览后任何参与档案、相关关系、当前或原端点及身份记录变化，都须重新比较；页面保留分配选择和依据，重比后再次明确确认。笔记延后复核遇到版本冲突也保留选择，重新核对后再处理。

点击“导出人物档案”下载离线 ZIP，解压后从 `index.html` 进入该人物的姓名写法、介绍、出处、任职依据、当前与历史身份、作品和笔记关系。头像及可读取的附件使用包内相对链接；`content.json` 保留同一范围的结构化内容、稳定编号和版本。已确认作品／笔记、待复核笔记及已移除关系分别呈现，待复核不计为已确认。导出逐条使用当前读取权限，作者已共享的当前笔记可保留，不能读取的旧私人来历不会随历史带出。

人物 Wiki 七项任务已实现并完成开发、指挥方独立验收和整组审查，见 [首版验收记录](work/人物Wiki首版开发验收.md)。交付入口为 [PR #13](https://github.com/normaltank/DataBase/pull/13)，合并与本机数据切换结果由 [父任务 #1](https://github.com/normaltank/DataBase/issues/1) 维护。首次升级保留旧署名，不自动创建人物或按姓名匹配；需要成员依据材料建立档案和确认关联。

## 成员与内容导出

管理员可创建本机成员、停用账号、重置密码；系统保留至少一位有效管理员。停用不删除署名或修订记录。密码至少 12 个字符；成员可修改本人的密码，重置或停用使旧会话失效。正式账号名单与备份排程仍由使用方确定。

资料库内容导出使用当前资料筛选，人物详情导出限定所选人物及其可读关系、身份历史所需的资料和引用，生成 ZIP：打开 `index.html` 阅读正文、来源介绍、专题和引用证据；`content.json` 保留结构化记录和关系，`attachments/` 保存有权读取的文件，`avatars/` 保存导出中引用的头像。可访问的所引笔记与原文一同纳入。此导出不包含账户凭据；需要恢复全部账号、历史及归档内容时，使用管理员完整备份。

解压后的 HTML 无需联网加载样式。正文、来源介绍、专题比较、原文旧快照及报告采用的笔记正文使用一致的表格边框、表头和留白；长链接可以换行，多列表格可在自身区域横向滚动。引用保持采用时的版本；新原文快照记录题名、作者、日期、链接、编号和版本，实际摘录另列。已下载的旧 ZIP 需重新导出才能采用新样式。

### 核查导出的依据与文件

新导出包的 `index.html` 提供复核入口。`review.html` 和 `evidence-coverage.json` 分别以可读页面和结构化清单说明：当前正文及附件、引用采用时的题录与摘录、实际包含的指定原文附件。只有外部链接、只有题录或普通笔记未固定原文时如实提示；当前内容不补作旧引用依据。附件缺失、大小或校验值与登记不一致时，导出会失败，先恢复或核实原件再导出。

`manifest.json` 列出包内文件的字节数及 SHA-256。使用 Python 3 运行仓库里的独立校验脚本即可检查，无需启动平台、登录或联网：

```text
python scripts/verify_content_export.py "research-content.zip"
```

可从任意目录运行脚本的完整路径。如果另有可信渠道提供整个 ZIP 的 SHA-256，可追加 `--sha256 该校验值` 对照。脚本只读压缩包，不运行包内文件。旧导出包没有清单时需重新导出；完整系统备份使用另一个恢复流程。

校验通过表示包内文件与清单一致，不能证明来源真实、观点正确，也不能排除文件连同清单一起被改写。实际研究复核还须检查原件上下文、译法、反例和论证，见 [研究质量与复核](PRODUCT.md#研究质量与复核)。

## 来源目录的使用

来源目录提供机构、期刊、其他出版物及全部入口。机构可按智库、大学／高校、研究所／研究中心等类型筛选；类型描述机构自身，大学的下属研究单位不会因此成为大学。年鉴、工作论文系列和旧出版物登记在其他出版物中；采集门户在“数据与维护”管理，旧编号及关联继续保留。

期刊可组合筛选主办国别和国际定位。国别按主办关系及机构国家登记生成，出版方国家另记；缺失或冲突保持待确认。国际定位为是、否、未知，选择是或否需填写依据。切换主要类型会清除不适用的筛选。

机构详情可以沿有依据的隶属、共同设立、合作、资助关系双向浏览；编辑关系时说明方向、依据与核查日期。机构详情与编辑不显示 ISSN 等期刊字段。来源对象类型也可纠错，稳定编号不变；不适用字段保留在历史，尚有机构关系或主办／出版引用时先处理关联。原始 classification 仍保存原值。

本轮试用库有 58 个机构、44 个期刊、37 个其他出版物，另有 4 个资料发现网站。44 个期刊中，34 个可由现有登记推导主办国别、10 个待确认；国际定位为是 3 个、否 0 个、未知 41 个。这些不是中心已核对数量。具体数据依据和未决项见执行记录。

“数据与维护”中的“资料发现网站”保存门户、机构目录与检索站等发现线索，当前不执行自动采集。机构、期刊的官网和资料目录地址继续保存在各自档案，无需另建一份身份。未来采集也可以从这些官网的文章列表、刊期页或订阅地址开始，具体采集规则另行建设。

机构所在地、来源研究覆盖范围及资料研究对象分开记录。原库没有明确研究对象字段，因此初始资料的研究对象保持空白，不能因为资料由拉脱维亚机构提供就自动标为研究拉脱维亚。未提供的译题、摘要和关键词同样不编造补齐。双语条目可按任一已登记语言筛选。

原库核验信息保留在详情中，但中心核对状态从待核对开始。原库附件仅保留官方链接和登记线索，未批量迁移或默认开放；本项目新上传并确认共享的附件可以下载。未读取 `Compile` 或 `MyPaper` 中的个人研究成果。

## 数据保存在何处

- `data/platform.sqlite3`：来源、资料、成果、关系、账号、收藏、专题、历史。
- `data/uploads/`：在本平台上传的附件，包括历史版本引用的文件。
- `data/avatars/`：人物当前及历史头像，随完整备份保存。
- `data/.session-key`：本机登录会话密钥。
- `data/backups/`：管理员生成的完整备份。
- `logs/platform.stdout.log`、`logs/platform.stderr.log`：运行记录。
- `samples/演示编译说明.md`：操作示例附件原件。

不要只复制数据库而遗漏附件。程序源码和说明需另行一并交接。

## 备份与恢复

管理员登录后进入“数据与维护”，点击“下载完整备份”。备份包含所有账号的个人/共享/受限数据、密码散列、关联、历史、平台上传附件、当前与历史人物头像，以及身份事件、旧编号和拆回依据，由管理员保管。人物、署名、任职、文章单位与身份操作结构各次增量升级前自动生成完整备份；旧版备份恢复到新目录后，由新版应用继续增量升级。

也可以在本目录执行：

```powershell
python -m platform_app.maintenance --backup data
```

恢复必须使用一个**尚不存在的新目录**，不会覆盖正在使用的数据：

```powershell
python -m platform_app.maintenance --restore "D:\备份\research-backup.zip" --target "D:\Agent Workspace\DataBase\data-restored"
python app.py --data-dir "D:\Agent Workspace\DataBase\data-restored" --no-import --port 8849
```

打开 `http://127.0.0.1:8849` 验证恢复结果。恢复工具校验备份内文件散列、数据库完整性、外键、当前与历史头像及附件引用，还检查人物转向、关系历史端点与连续版本、身份事件前后关系及依赖、拆回分配和幂等结果的一致性；校验失败不会发布目标目录。会话密钥不会随备份转移，恢复后重新登录。完整数据备份不包含 ThinkTank 原目录中的未迁移附件。

## 在另一台机器启动 / 开发

恢复工具兼容结构版本 1—11。新版本启动时增量迁移旧库，有数据的每个升级阶段先生成完整备份；不会重新导入覆盖已有资料。备份包括仅由历史版本引用的上传附件及个人常用检索。恢复演练始终使用新目录，切换实际数据目录前先核查正文、附件、关系与历史。

需要 Python 3.10 或以上。当前已在 Python 3.12 上验证。前端无安装、编译和外部 CDN 依赖。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start.ps1
```

首次启动时会尝试从默认 ThinkTank 路径导入；该目录不存在时使用现有平台数据或空库，可手动提交。可指定其他资料目录或仅启动现有数据库：

```powershell
python app.py --source "D:\另一个位置\LatviaResearchDatabase"
python app.py --no-import
```

若端口被占用，使用 `start.ps1 -Port 8080`。启动器会复用已正常运行的服务。`stop.bat` 仅停止由本项目启动器记录且命令路径匹配的后台进程；手工执行 `python app.py` 时用该终端的 Ctrl+C 停止。

| `tests/test_platform.py` | 权限和关键业务流程验证 |
| `tests/test_record_revisions.py` | 合成存储故障下的回滚、版本历史及历史附件保全验证 |
| `tests/test_source_catalog.py`、`tests/test_source_types.py` | 来源筛选、关系、类型纠错、历史及数据升级验证 |
| `tests/test_workflow.py` | 共编、作者确认、证据、合并、专题、成员、导出及完整恢复验证 |
| `docs/施工说明.md` | 乙方施工范围、技术决定与后续工作 |
| `docs/试用验收记录.md` | 初始 MVP 测试结果和已知边界；来源新增验证见本轮执行记录 |

所有业务接口需要登录；修改操作需带当前会话的 `X-CSRF-Token`。`GET /api/session` 返回会话和令牌。主要读取入口为 `GET /api/records`、`GET /api/records/<id>`、`GET /api/sources`、`GET /api/sources/<id>`、`GET /api/collections`。资料列表支持 `q`、`source`、`source_group`、`source_country`、`source_international`、`kind`、`status`、`language`、`country`、`from`、`to`、`collection`、`favorite`、`sort`、`page`、`size`。`country` 仍表示资料研究对象；新增三个来源范围条件的行为见[规格](docs/specs/基础数据库查找与来源选择.md)。`GET /api/export` 与完整内容导出接受相同资料筛选条件。

`GET /api/export/content?person=<人物编号>` 是人物详情所用的可读导出入口；旧人物编号按当前身份解析，空参数返回 400，未知编号返回 404，均不会退回全库导出。身份与关系的读写及本轮稳定版本约定见 [首版验收记录](work/人物Wiki首版开发验收.md#操作契约与后续衔接)。

`POST /api/intake/preview` 接收 `{ "input": "DOI 或文章网址" }`，需要登录及当前 CSRF，返回字段、原始署名、重复与档案候选、取得依据和绑定当前成员的签名凭据，不写正式资料。确认后的创建仍使用现有资料保存接口。网络边界、支持范围和验证见[辅助录入验收](work/链接与编号辅助录入验收.md)。

修订接口需要传入当前 `version`，防止覆盖同事已保存的新版本。编辑者不得通过接口自行扩大授权；管理员核对接口与备份接口也在服务端检查角色。

`/api/saved-searches` 提供个人检索列表和创建，`/api/saved-searches/<id>` 提供读取、带版本的修改及删除。资料查询传入 `saved_search=<id>` 时以该账号保存的条件为准，只允许另行指定页码与每页数量；列表及导出继续执行当前权限检查。`GET /api/record-candidates` 按原文／专题用途先筛出合格资料，再计数和分页，避免先截断后过滤。

## 自动验证

安装依赖后，在仓库目录运行统一检查：

```powershell
python scripts/check.py
```

该入口检查应用、维护脚本和测试的 Python 语法，再发现并执行完整合成数据套件。测试使用独立临时目录；入口始终关闭外部资料测试，包括当前终端曾设置外部检查开关的情况。语法错误、测试失败、未发现测试或全部跳过均返回非零退出码。

直接运行 `python -m unittest discover -s tests -v` 时，外部资料测试同样默认跳过，连 ThinkTank 目录是否存在也不会探测。需要单项调试时，可使用 unittest 的 `-p` 或 `-k` 筛选；交付前仍运行上述完整入口。

[GitHub Actions](.github/workflows/check.yml) 在推送和 PR 时，使用 Ubuntu、Windows 与 Python 3.12 执行同一命令，令牌仅有读取仓库内容的权限。结果以对应提交的实际检查记录为准；配置存在不代表某次运行已经通过。

辅助录入的定向浏览器回归为 `python scripts/check_intake_preview_browser.py`，需另有 Playwright 和 Chromium；可用 `DATABASE_BROWSER_EXECUTABLE` 指定浏览器。脚本只在空闲的 8851 端口启动临时合成库，模拟题录服务，不访问真实资料或外部站点；它不包含在上述无浏览器的合成套件中。

### 单独检查真实资料导入

只有在已获授权、确认[四张试点主表](#初始数据及其边界)可供此次验证时，才在 PowerShell 显式开启并单独运行原外部测试：

```powershell
$env:RUN_THINKTANK_IMPORT_TEST = "1"
try {
    python -m unittest discover -s tests -p test_platform.py -k real_import -v
} finally {
    Remove-Item Env:\RUN_THINKTANK_IMPORT_TEST -ErrorAction SilentlyContinue
}
```

该测试先检查默认资料目录是否存在；缺失则跳过，存在时读取指定主表，对导入前后散列、幂等性和关联进行验证，输出使用临时数据库。普通检查与 CI 均不执行这一项。

自动采集、附件 OCR、实时协作、正式网络部署、对外发布和高级分析仍未接入，详见施工说明。
